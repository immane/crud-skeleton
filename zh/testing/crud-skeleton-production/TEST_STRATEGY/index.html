    测试策略¶

    目标和范围¶

    目标是保存身份的模块化 Symfony API 的安全迭代， 资金、订单、库存和异步状态。测试保护可观察的 契约和领域不变量，而不是实现细节或目标 测试计数。

    该策略涵盖 src/ 下的代码、Doctrine 模式行为、HTTP API、 信使处理程序，并释放烟雾检查。真实的外部提供商（短信、 微信、七牛、支付收单机构）由确定性适配器代表 自动化测试；他们的凭证和提供商方行为需要 单独的分期认证。

    测试环境¶

    环境 数据库 目的 约束
    本地 PHPUnit SQLite (var/test.db) 快速开发反馈 不要将 SQLite 锁定或 SQL 方言行为视为生产证明
    并行本地 PHPUnit 每进程 SQLite 快速隔离套件运行 并行模式设置不支持外部共享数据库
    CI PHPUnit PostgreSQL 16 合并门和数据库可移植性 每个拉取请求都需要
    暂存/发布 部署服务 配置、真实 HTTP、工作人员和操作检查 切勿使用生产凭证或客户数据

    MySQL是Docker Compose声明的部署数据库。任何迁移或 必须在 MySQL 兼容的暂存上检查使用特定于数据库的 SQL 的查询 释放前； PostgreSQL CI 不证明 MySQL 兼容性。

    测试层¶

    层 目的 示例 规则
    单位 确定性领域决策和错误案例 DSL、定价、令牌、工作流程、实体方法 没有内核或真正的数据库，除非组件本身是持久性绑定的
    整合 学说映射、事务、存储库、服务连接、事件/处理程序效果 发票调整、钱包转账、发件箱/收件箱 断言持久状态和回滚/幂等性效果
    HTTP/API 路由、身份验证、授权、序列化、验证和状态代码 应用程序/管理边界、区域设置、OpenAPI 维护公共响应信封和数据隔离
    系统烟雾 已部署的服务布线和关键旅程 授权、目录、钱包、订单/付款、商店/库存流程 针对一次性环境运行，而不是 PHPUnit 模拟
    手册提供商认证 第三方合约和回调验证 微信支付、短信、七牛 文档提供者沙箱结果并在测试中不保留任何秘密

    一种行为通常应该有一个主要层。添加更高层测试 当集成边界、许可边界或传输契约处于 风险。不要仅仅为了提高线路覆盖率而添加控制器测试。

    所需变更规则¶

    改变 所需的最低证据
    纯域规则或错误修复 重点单元测试，包括之前的失败案例
    服务、存储库、事务或学说映射 持久状态集成测试；多次写入时回滚测试
    API 路由、有效负载、授权、区域设置或序列化程序 HTTP/API 成功和拒绝/验证测试
    国家转型或货币流动 有效和无效的转换测试；不变和重复请求覆盖率
    消息、发件箱、收件箱、重试或消费者 首次交付、重复交付和无序/故障处理测试
    迁移或特定于数据库的查询 新鲜模式迁移验证和目标数据库暂存验证
    外部提供商适配器 确定性合约测试加上发布前的暂存/沙箱认证

    当更改涉及多个行、聚合或模块时，测试整个 业务结果而不仅仅是单个方法调用。

    强制命令¶

    使用存储库 PHP 8.4+ 运行时。在 php 为 7.4 的本地计算机上， 项目上下文当前记录了/opt/homebrew/opt/php@8.5/bin/php。

    /opt/homebrew/opt/php@8.5/bin/php ./vendor/bin/phpunit
composer phpstan
composer rector:types:check

    phpunit.dist.xml 将测试进程内存限制设置为 512M，因为完成 OpenAPI 生成由集成套件执行。

    对于本地覆盖检查：

    XDEBUG_MODE=coverage /opt/homebrew/opt/php@8.5/bin/php ./vendor/bin/phpunit --coverage-html var/coverage

    对于发布烟雾检查，启动一次性 Docker 环境，应用 迁移，创建所需的测试用户/数据，然后仅运行以下脚本 匹配启用的模块：

    scripts/tests/api-smoke.sh
scripts/tests/store-smoke.sh
scripts/tests/inventory-smoke.sh

    这些命令可以创建测试数据，并且不得以共享或生产为目标 环境。

    质量门¶

    合并门：

    • PHPUnit 在 CI PostgreSQL 上取得成功。新跳过的测试、警告、通知或 弃用需要明确的理由和后续行动，而不是默默地 扩大基线。
    • composer phpstan 和 composer rector:types:check 成功。
    • src/的线路覆盖率至少为90%；排除代码的增加或 降低的门槛需要明确的维护者批准。
    • 变化的风险体现在测试矩阵及其所需的证据中 存在。

    释放门：

    • 对于发布提交，合并门是绿色的。
    • 相关烟雾脚本和迁移检查在一次性设备上成功 类似部署的环境。
    • 工作线程、调度程序、回调 URL、秘密和可观察性被检查为 在PRODUCTION_VALIDATION.md中描述。
    • 关键变更有回滚或补偿操作计划。

    维护规则¶

    • 保持测试的确定性：注入时钟、UUID、网关和提供商 可变性会隐藏失败的响应。
    • 每个测试都拥有自己的数据；不依赖于执行顺序或先前的测试。
    • 将公共 API 断言用于公共合约，并将持久性断言用于 交易合同。避免对私有实现细节进行断言。
    • 更喜欢对具有许多等效输入的规则进行表驱动测试；名称测试 受保护的结果之后。
    • 每当模块获得a时更新此策略、矩阵和不变量 新的关键路径或更改现有合同。
