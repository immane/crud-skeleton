    tests/Trade/Controller/、tests/Trade/Integration/、tests/Trade/MessageHandler/的只读审核 （13个测试文件+1个支持fake，191个测试方法）。目标：识别不必要/多余的测试 这些是稍后删除的候选者。 src/ 或 tests/ 下的任何内容均未修改。

    删除候选表中未列出的所有内容，包括：

    • 所有跳过的记录已知错误的测试（请勿删除）：OrderWorkflowApiTest::testDoTransitionMustNotForwardArbitraryBodyFieldsToUpdate， App/OrderControllerTest::testSubmitActionReturnsWarningWhenTransitionFails， Manage/OrderControllerTest::testDoTransitionDoesNotForwardArbitraryFieldsToUpdate （仅保留两个篡改双胞胎之一 - 请参阅删除表）加上范围外的跳过。

    • TradeRepoFullTest — 存储库查询的幸存者（findNotDeleted/findActive， findByProduct/findActiveByProduct、findById、findByUser、findByOrder） 精确的包含/排除断言。
    • TradeStoreOrderEventTest::testDuplicateSpecificationItemsUseDistinctOrderLineIds — 唯一不变式（对于一个发件箱事件中的重复行而言是不同的 lineId）。

    • App/OrderControllerTest 和未列出的 Manage/OrderControllerTest 方法 — 覆盖控制器分支的快速单元测试（价格引擎抛出、交易关闭 抛出，跨用户所有权，支付方式转发）集成无法达到。

    合并建议（注意：合并减少运行时间）¶

    1. 将 Trade API 全流程测试整合为一个表驱动测试。 TradeApiIntegrationTest 重新运行创建→提交→确认→付款→履行→完成→退款最多5× （并取消 3×）使用每次测试内核 + DB 引导程序（~6.4 s 文件）。保持单一数据驱动 OrderWorkflowApiTest::testHappyPathDraftToRefundedViaDoTransitions 中的全流程（已经 最强）并删除 26 个标记的 TradeApiIntegrationTest 测试 - 文件保留 仅其独特的产品/规格/批次/应用程序/项目覆盖范围。预期运行时间节省：大约一半 TradeApiIntegrationTest 的约 6.4 秒，加上共享 var/test.db 上的数据库争用减少。

    2. 删除TradeRepositoryIntegrationTest.php并保留TradeRepoFullTest 存储库覆盖文件。 相同的种子样式，更强的断言。节省了一个完整的 bootTestDatabase() 每类。

    3. 折叠Manage/OrderControllerTest中9个几乎相同的未找到单元测试 （testDeleteActionReturns404WhenOrderNotFound、testPayActionReturns404WhenOrderNotFound、 testPaymentActionReturns404WhenOrderNotFound，testFulfillActionReturns404WhenOrderNotFound， testRefundActionReturns404WhenOrderNotFound，testTransitionsActionReturns404WhenOrderNotFound， testDoTransitionActionReturns404WhenOrderNotFound，testItemsActionReturns404WhenOrderNotFound， testUpdateActionReturns404WhenOrderNotFound) 进入一个数据驱动的测试，由 （操作、HTTP 方法、uri）。这些是 ~9× 样板，断言相同 get() → null → 404 'Order not found.'合同。 （运行时影响很小——单位——但它 删除约 90 条重复行。）

    4. TradePaymentIntegrationTest::testAppUserCanSubmitConfirmAndPayOwnOrder 重新断言 OrderWorkflowApiTest::testAppUserSubmitConfirmAndCancelOwnOrder 已涵盖应用程序提交/确认步骤； 仅保留基于发票的付款步骤（自动付款模拟）作为唯一增量，或将其折叠到 通过应用程序流程测试。
