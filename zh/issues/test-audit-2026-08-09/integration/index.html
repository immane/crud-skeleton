    合并建议（预计节省时间）¶

    1. BaseServiceIntegrationTest（2个测试）→合并到CommonModulesIntegrationTest（8个测试），保留1个 服务层文件。两者都实例化一个 BaseService 子类并启动内核以执行相同的操作 update/get/list/remove路径；只有实体不同（内容与六个常见实体）。幸存者： CommonModulesIntegrationTest （将内容行添加到其表驱动样式，反之亦然）。 节省：~1 个文件 × 2 次内核启动 ≈ 0.4–0.6 秒。
    2. OpenApiIntegrationTest→合并到CoreOpenApiEnricherApiTest。移动独特的 /api/doc swagger-UI HTML 断言、公共媒体端点标签/摘要以及媒体上传 requestBody + 媒体架构 断言到CoreOpenApiEnricherApiTest，然后删除OpenApiIntegrationTest。 节省：1 次内核启动 ≈ 0.3–0.5 秒。
    3. TradePaymentIntegrationTest→合并到PaymentTradeIntegrationTest（幸存者：PaymentTradeIntegrationTest， 14 次测试）。两次支付/退款重叠（见表）加上应用程序订单提交/确认/支付和转换失败 测试重复已存在的 PaymentTradeIntegrationTest 和 tests/Trade/Controller/App/OrderControllerTest 盖。 节省：2–4 次内核启动 ≈ 0.5–0.8 秒。
    4. CoreDynamicQueryApiTest::testShowDqlRejectedOutsideDev：将其消息断言折叠成 CoreExceptionInterceptorApiTest::testAccessDeniedOnShowDqlReturnsJsonEnvelope，然后删除DynamicQuery 复制。 节省：1 次内核启动 ≈ 0.2–0.3 秒。

    估计节省总计： ≈ 13s 集成组的 2.5–4 秒（大约 20–30%） 通过删除 10–12 个冗余 测试并折叠 3-4 个文件，而不会丢失任何记录为已知错误的行为。

    验证步骤¶

    1. 任何删除后，在 CI PostgreSQL 上运行完整套件以确认零失败和零新跳过的测试： /opt/homebrew/opt/php@8.5/bin/php ./vendor/bin/phpunit。
    2. 确认 composer phpstan 和 composer rector:types:check 仍然通过（没有删除测试命名空间引用 来自任何 src/ 或其他测试文件）。
    3. 确认删除后src/线路覆盖率保持≥90%（XDEBUG_MODE=coverage ... --coverage-html var/coverage）； 上述候选人声称所引用的幸存测试已经涵盖了行为。
    4. 确认每个列出的 DUPLICATE 对一起失败/通过：暂时恢复一侧，运行幸存的测试， 然后恢复——幸存的测试仍然必须捕获相同的回归。
    5. 重新检查 38 个跳过的错误文档测试是否未受影响（所有 markTestSkipped 案例保持保留）。
