    保留¶

    基本实体测试（CategoryTest、CommentTest、ContentTest、MediaTest、PageTest、 PictureTest、SettingTest、TagTest) — 普通构造函数/ Fluent-setter/touch/prePersist 断言。这些是传统的基本套件；它们是样板，但是 跨每个模块建立的模式，因此本次审核保留它们。

    跳过记录真实错误的测试（根据活动说明，这些是保留的）： - ContentEntityCoverageTest::testSetTitleTouchesUpdatedAt，testAddTagTouchesUpdatedAt （文档 Content::setTitle()/addTag() 未触及 updatedAt — 活动 Bug 1）。 - CommentParentScopeIntegrationTest::testReplyParentMustBelongToSameEntityScope （记录跨实体家长接受度 - 活动 Bug 2）。

    行为价值（套件中任何地方都不会重复）： - PictureControllerTest（完整的 HTTP CRUD、验证、所有者范围隔离、图片存储库 自定义方法）。没有其他文件触及 /api/v1/{app,manage}/pictures。 - MediaUploadIntegrationTest核心上传历程：管理上传存储+删除文件， 没有尺寸的 PDF 上传、仅限所有者的应用程序删除、公共只读范围、丢失文件/ 未知存储/未知类别 400、MediaService 验证分支和存储 故障处理。这些都是独一无二的。 - CommonRepoFullTest 自定义存储库方法（findBySlug、findRootCategories、 findEnabled、findByEntity、findPending、findImages、findPublished、findByGroup、 findByNameLike) — 仅在这些查询被断言的地方。

    HIGH-confidence reasoning (exact citations)¶

    • CategoryEntityCoverageTest / ContentEntityCoverageTest（主动测试）。 每个都强制 null通过ReflectionProperty/newInstanceWithoutConstructor集合来执行 Category::getChildren() (src/Common/Entity/Category.php:120-122) 中的防御性惰性初始化守卫 / Content::getTags() (src/Common/Entity/Content.php:102-104)。状态无法到达 通过公共构造函数，它总是初始化 ArrayCollection （Category.php:53、Content.php:46）。所断言的行为（集合成员资格， dedup、父链接）已在列出的基本测试中断言。文档块状态 彻底的目的是：“覆盖最后一个未覆盖的树枝”。这些固定实现 纯粹用于线路覆盖的细节。
    • CommentApiExtraTest::testCommentCreateAndList. POST /api/v1/app/comments → 201 和 GET /api/v1/app/comments → 200/code=0 是一个严格的子集 AppApiRegressionTest::testAppCommentCreateDefaultsToPending（201 + code=0 + 字段）和 testAppCommentListOnlyReturnsApproved / testAppCommentPendingNotVisibleInAppList（获取 列表）。它仅断言状态代码和 code=0。
    • CommentControllerTest::testCreateWithAuthenticatedUserRecordsAuthorFields. 通过断言 FakeCommentService 表示 defaultCreateValues() 记录来自当前用户的 authorName/authorEmail/status = pending — 正是 AppApiRegressionTest::testAppCommentCreateDefaultsToPending 在真实的 HTTP 堆栈上断言（authorName = 'testauth'、authorEmail = 'testauth@example.com'、 status = 'pending'）。
    • MediaControllerUploadTest::testAppUploadReturns500ForUnexpectedError. 等同于 MediaUploadIntegrationTest::testUploadHandlesUnexpectedStorageFailure：同样继承 App\Common\Controller\App\MediaController::uploadAction() catch (\Throwable) → 500 + message，同样的假MediaServiceInterface投掷，同样的uploadOwner() → null。的 集成变体严格来说更强（真正的容器序列化器/翻译器/请求 堆栈）。
    • MediaControllerUploadTest::testManageUploadReturns500ForUnexpectedError. Manage\MediaController 扩展App\MediaController并继承uploadAction()；与 uploadOwner() → null 执行的catch (\Throwable) → 500路径与App测试的代码相同，仅不同 在抛出的消息中。一个代码路径的两次测试。
    • MediaUploadIntegrationTest::testMediaEntityAccessorsAndPrePersistDefaults. 复制 MediaTest::testSettersAreFluent （相同的六个 setter，相同的断言 文件名/原始文件名/mimeType/大小/路径/存储 + getUpdatedAt()) 和 MediaTest::testPrePersistWhenCreatedFromReflection（反射newInstanceWithoutConstructor
    • prePersist() + createdAt）。嵌入集成文件中的纯实体单元测试。
    • SettingApiIntegrationTest::testCreateAndReadSettingViaManageApi. POST /api/v1/manage/settings (201, 键/值断言) + GET /api/v1/manage/settings/{id} (键断言) 是严格的 CommonModulesApiRegressionTest::testSettingCrudRegression 的子集（相同的 POST 断言， 加上 GET 详细值、PUT、DELETE）。

    中等置信度推理¶

    • ContentControllerTest. App\ContentController 是 generic 的空子类 ListApiViewMixin/DetailApiViewMixin mixins（无自定义逻辑）。清单/详情/404 tests/Core/View/DetailApiViewMixinTest 涵盖了单元级别的行为，并且 批量/列表混合测试； 404-on-missing 也涵盖了每个其他实体的 HTTP 级别。 该文件唯一添加的是 /api/v1/app/contents 的路由布线 + auth Smoke （/app/contents 不存在于 AppApiRegressionTest::testAppEndpointsRequireAuthentication 中）。 边界 - 仅当团队想要一个代表性的“应用程序列表/详细信息 + 身份验证”测试时才进行标记 每个模块； mixin 级别的覆盖使该文件变得多余。
    • CommonBatchUpdateTest. 7 个测试中的每一个在结构上都是相同的（创建两行， POST batch-update，断言 HTTP 200）。仅断言 200 意味着测试通过，即使 更新是无操作（弱/无持久性验证）。 batchUpdateAction 的行为是 由UpdateApiViewMixinTest（单位）和TradeApiIntegrationTest（HTTP，带有真实的 结果断言）。合并到一个验证持久值的参数化测试中，或者 放弃支持一般覆盖范围。
    • CommonRepoTest. 所有 7 个测试都是相同的模式 persist → flush → findById → same entity → findAll non-empty，仅运用通用 Doctrine EntityRepository 方法 （没有自定义存储库逻辑）。 findById 往返行程已被证明 ContentRepositoryIntegrationTest::testFindByIdReturnsEntityOrNull 以及每个 CommonModulesIntegrationTest CRUD 流程。合并到一个参数化映射测试中。
    • CommonRepoFullTest::testContentFindLatest*。 findLatest() 已下单+限额 由 ContentRepositoryIntegrationTest::testFindLatestReturnsNewestFirstAndRespectsLimit 断言； 新测试添加了限制计数断言，无需排序和 findLatest(1) → count 1。 将默认限制变体折叠到预先存在的测试中，而不是重复。
    • CommentControllerTest::testCreateWithoutUserFallsBackToPendingStatus. 应用程序评论创建 受身份验证保护 (AppApiRegressionTest::testAppCommentCreateUnauthenticated)，因此 defaultCreateValues() 的空用户分支在生产环境中无法访问；测试模拟 getUser() → null 纯粹是为了覆盖该防御分支（文档块：“覆盖剩余的 未覆盖的线 (50)")。无法到达的分支的覆盖范围追踪。

    合并建议¶

    1. CommonBatchUpdateTest（7 个测试）→ 一个断言持久字段值的表驱动测试， 不仅仅是 HTTP 200。
    2. CommonRepoTest（7个测试）→ 1个参数化persist → findById → findAll映射测试 （或删除以支持 CommonModulesIntegrationTest CRUD 覆盖）。
    3. CommonRepoFullTest::testContentFindLatest* → 折叠成ContentRepositoryIntegrationTest （已经断言排序/限制）。
    4. MediaUploadIntegrationTest::testMediaEntityAccessorsAndPrePersistDefaults → 折叠成 MediaTest （或删除；MediaTest 已覆盖它）。
    5. CommentControllerTest（如果保留）→ 将两个单元测试折叠到 HTTP 级别的覆盖范围中 AppApiRegressionTest 而不是维护大量模拟的第二个副本。

    注释/非阻塞观察¶

    • ContentTest::testSettersAreFluentAndTouchUpdatesTimestamp 通过只是因为 setBody() 触摸updatedAt；它没有捕获 setTitle() 缺失 - touch() 错误。这是一个 覆盖盲点，不是多余的测试 - 中跳过的测试 ContentEntityCoverageTest 而是记录该错误。不要将此测试视为证据 错误已修复。
    • 该模块中没有标记跳过的测试；所有跳过记录活动错误并保留。
