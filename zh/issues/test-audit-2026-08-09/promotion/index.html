    推广模块测试审核(2026-08-09)¶

    范围：tests/Promotion/下的每个测试（27个文件，360个测试）。此审核识别出未添加可观察行为保护且适合稍后删除的测试。它是只读 — 没有修改 src/ 或 tests/ 文件。

    分类要点： 1. 覆盖范围追逐——琐碎/同义反复的断言 2.重复——其他地方涵盖的相同行为（引用的命名测试） 3. 实现细节——断言内部结构，而不是公共/持久合约 4. 冗余回归——测试更广泛的测试已经保护的固定回归 5. 几乎空了

    依赖的上下文：TEST_STRATEGY.md（单位 = 确定性域决策；每个行为一个主要层；没有控制器测试只是为了提高覆盖率）、TEST_MATRIX.md、BUSINESS_INVARIANTS.md 和 docs/issues/coverage-2026-08-09/（添加了 *CoverageTest / ParserBugReproTest 文件的 2026 年 8 月 09 日覆盖率活动）。

    ＃＃ 保持

    • DSL 行为测试 — LexerTest、ParserTest、EvaluatorTest、ParserBugReproTest。词法分析器/解析器/评估器是模块的核心规则引擎；这些测试固定令牌/语法/评估语义。 ParserBugReproTest 固定已知缺陷（分层类型不可解析、OR 块吸收、尾随点错误、未使用的 desc、多个 when:、缺少 when: 模拟不匹配）及其 3 个跳过的测试记录了预期行为 - 根据活动规则明确保留。
    • 管道集成 — PromotionPricingPipelineIntegrationTest（商店范围、全球营销活动、最优惠价格选择、多 SKU 堆叠、到期）是 BUSINESS_INVARIANTS“促销”行的证据。
    • 计算器冲突模式 - PromotionCalculatorTest（可堆叠循环，lock_item）+ PromotionCalculatorCoverageTest（独占中断，最佳价格扫描跳过）是互补的：覆盖文件涵盖了主要测试省略的两种冲突模式。
    • PromotionService 过滤/优先级/应用 — 30 多个 PromotionServiceTest 过滤、时间窗口、DSL 条件和排序测试以及覆盖测试优先级回退。
    • PromotionTemplateService 解析/模拟/更新 + 覆盖范围（类型/阶段不匹配验证）。
    • 策略核心规则 - 每个策略的主要案例（折扣率/上限/商品、FullReduction 值、礼品添加、会员级别门、第 N 个商品、分层最佳匹配、FreeShipping 元）。
    • 存储库 + 实体测试 — 持久状态（带有模板/配置/时间字段的 findById）、实体构造函数/访问器/触摸合约的学说映射验证。
    • PromotionTemplateControllerTest 验证/空运行操作测试 — 唯一断言实际状态代码 (200/422/404) 的控制器测试。

    合并建议¶

    1. TieredStrategyTest — 根据 TEST_STRATEGY 的“对于具有许多等效输入的规则，首选表驱动测试”，将六个重叠层案例转换为一个表驱动测试（全匹配/不匹配/部分匹配/来自-与-较少优先级/钳位/默认）。这将吸收第 18-19 行的候选者。
    2. 策略回退对 — DiscountStrategyTest::testApplyWithMissingConfigRate + testApplyWithNonNumericRateDefaultsToZeroRate 和 FullReductionStrategyTest::testApplyWithMissingConfigRef + testApplyWithNonNumericString 是同一 resolveValue() 回退到 0 规则的表行；表驱动它们。
    3. PromotionServiceTest 时间窗口四重奏 — testGetAvailableFiltersByStartTime、testGetAvailableFiltersByEndTime、testGetAvailablePromotionWithinTimeRange、testGetAvailableWithoutStartAndEndTime 是一条过滤规则的四行；工作台驱动。
    4. PromotionServiceTest 应用无操作三重奏 — testApplyWithNoTemplate、testApplyWithNoAstCache、testApplyWithEmptyDoChildren/testApplyWithNoDoNode 是三个早期返回分支；将空模板对（候选）和无操作对合并到一个参数化测试中。
    5. PromotionTemplateServiceTest 模拟信封三重奏 — testSimulateReturnsStructure、testSimulatePassesSampleContext、testSimulateWithEmptyContext 断言一个无 when 模拟路径；合并为单个形状/直通测试。
    6. PromotionTemplateServiceTest parseDsl 每个类型冒烟测试 — testParseDslFullReduction、testParseDslDiscountWithPercent、testParseDslTieredType、testParseDslNthDiscountType、testParseDslMemberDiscountType 是包装器级往返表（每个类型语法已被 ParserTest 覆盖）；工作台驱动。
    7. 管理控制器白名单测试 - Manage/PromotionControllerTest 和 Manage/PromotionTemplateControllerTest 的基于反射的属性断言在结构上重复。替换为断言白名单强制执行（字段接受/拒绝）的 HTTP 创建/更新集成测试，与 TEST_STRATEGY 的 API 层规则以及已存在的验证/空运行操作测试一致。
    8. 最佳价格覆盖范围 - PromotionCalculatorCoverageTest::testBestPricePromotionSkippedDuringStandardScan / ::testBestPriceCandidateScanSkipsNonBestPricePromotions 与 PromotionPricingPipelineIntegrationTest 中的管道级最佳价格场景重叠。今天保留两者（单元隔离与 E2E 证明），但如果认为集成套件足够，则可以将这两个单元测试一起删除。

    验证步骤¶

    1. 确认模块套件大小并且在进行任何更改之前它是绿色的： /opt/homebrew/opt/php@8.5/bin/php ./vendor/bin/phpunit tests/Promotion（预计 360 次测试）。
    2. 仅对于 高置信度 候选者（8 个测试：6 个 ParserCoverageTest 死分支测试，ParserCoverageTest::testLexerRoundTripItemsNumericRate、PromotionServiceTest::testApplyWithNullTemplateDoesNothing），删除它们，然后重新运行 tests/Promotion 以及完整套件 — 必须保持绿色，零失败/跳过更改。
    3. 针对 docs/issues/coverage-2026-08-09/promotion-dsl.md Bug 7（EOL-skip 分支记录为词法分析器输出已死）和 Bug 4/5/6（其他 ParserCoverageTest 案例）交叉检查每个 ParserCoverageTest 删除，以确认保留的错误路径测试仍然固定可到达的语法错误。
    4. 删除后从 TEST_STRATEGY 重新运行质量门： composer phpstan 和 composer rector:types:check。
    5. 重新检查 90% 线路覆盖率门：删除的高置信度测试仅触及活动已记录为无法访问的防御代码的线路，因此覆盖率不应低于门限；如果确实如此，请保留测试而不是降低阈值。
    6. 将任何已接受的删除记录在TEST_MATRIX.md/本次审计中，作为模块保留的证据集（根据矩阵维护规则）。
