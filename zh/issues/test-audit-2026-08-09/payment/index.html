    支付模块测试审核(2026-08-09)¶

    对tests/Payment/（14个文件，76个测试）进行只读审核，以识别不必要的/ 多余的测试作为稍后删除的候选。参考文件： TEST_STRATEGY.md（“一个行为通常应该有一个主要层”， “不要仅仅为了提高线路覆盖率而添加控制器测试”）， TEST_MATRIX.md、BUSINESS_INVARIANTS.md（付款不变）以及 coverage-2026-08-09 活动总结（99.46% 线路覆盖率 套房）。

    偏见注释：支付网关/调整/发票生命周期行为是 资金关键（BUSINESS_INVARIANTS“付款”行）并且保留，除非有确切的 重复存在于同一层或更高层。此中不存在跳过的测试 模块，因此没有需要保护的错误记录测试。

    保留¶

    • tests/Payment/Integration/InvoiceServiceIntegrationTest.php (10) — 的 主要发票生命周期测试：创建→付款→通知→退款，findBySource， 存储库查找、编辑、幂等重复通知、取消/失败、 退款验证分支机构。金钱至上，权威。
    • tests/Payment/Integration/PaymentApiIntegrationTest.php (4) — 的 支付模块拥有的 HTTP 层，用于管理/应用程序发票路由 + 通知 网络钩子。这是控制器单元测试复制的层；保留 这些，删除那些。
    • tests/Payment/Entity/InvoiceTest.php (1) — 实体默认值/访问器 + __toString + prePersist。核心实体行为。
    • tests/Payment/Service/PaymentAdjustmentRegistryTest.php (1) — 唯一的测试 行使登记权（适用/申请/sumApplied/hasApplied/release/refund） 与受控的假冒提供商隔离。合理的基层 注册表类本身。
    • tests/Payment/Integration/PaymentAdjustmentMultiGatewayIntegrationTest.php (17 of 19) — 综合推演+网关矩阵（模拟/钱包/微信， 自动付费、通知、部分/全额退款、失败/取消释放、顺序 多张发票）。对金钱至关重要；保留，但下面提到的两个内部重复项除外。
    • tests/Payment/Integration/PaymentAdjustmentIntegrationTest.php → testDeductedInvoiceRejectsPartialRefund — 唯一的测试 “调整后的发票仅支持全额退款”守卫 (InvoiceService.php:241-243)。独特的。
    • tests/Payment/Service/InvoiceServiceTest.php → testCreateInvoiceRejectsNegativeAmount、testPayThrowsWhenDeductionExceedsInvoiceAmount、 testPayAppliesGatewayAndTradeTypeOptions，testMarkFailedThrowsWhenWorkflowCannotFail — 这些分支（负金额、扣除 > 发票、网关/tradeType 选项应用程序、不允许失败的防护）不被任何断言 集成/HTTP 测试。独特的覆盖范围。

    MERGE SUGGESTIONS¶

    • PaymentAdjustmentIntegrationTest → PaymentAdjustmentMultiGatewayIntegrationTest: the 4 flagged tests are scenario-level duplicates of the later, more comprehensive multi-gateway file. Rather than delete outright, merge any scenario nuance (the 200-vs-400 walletAmount in the gateway-failure test) into the MultiGateway file and drop the older file's duplicates. Keep testDeductedInvoiceRejectsPartialRefund (only full-refund-only guard).
    • InvoiceServiceTest → InvoiceServiceIntegrationTest: this coverage-campaign file re-asserts workflow-guard exceptions that the integration file proves with the real state machine. The 4 unique unit branches (negative amount, deduction-exceeds, gateway/tradeType options, fail-not-allowed) are better expressed as integration scenarios in InvoiceServiceIntegrationTest.php; the remaining 5 guard tests are then deleted.
    • Controller unit files (App/Manage/Webhook) → PaymentApiIntegrationTest + PaymentTradeIntegrationTest: the HTTP layer already owns these routes (strategy: "Do not add controller tests merely to raise line coverage"). Any genuinely uncovered branch (e.g. manage cancel-404, refund amount/reason missing) should be added to PaymentApiIntegrationTest instead of kept as a mocked-service unit test.

    Verification steps¶

    1. Confirm the audit made no changes under src/ or tests/ (only this report was written under docs/issues/test-audit-2026-08-09/).
    2. Before deleting any test, temporarily --filter the covering test to prove it still fails when the candidate is removed from the suite (i.e. the "covered by" test is the real safety net): 
      /opt/homebrew/opt/php@8.5/bin/php ./vendor/bin/phpunit --filter PaymentApiIntegrationTest
/opt/homebrew/opt/php@8.5/bin/php ./vendor/bin/phpunit --filter PaymentAdjustmentMultiGatewayIntegrationTest
/opt/homebrew/opt/php@8.5/bin/php ./vendor/bin/phpunit --filter PaymentTradeIntegrationTest
/opt/homebrew/opt/php@8.5/bin/php ./vendor/bin/phpunit --filter InvoiceServiceIntegrationTest
    3. Deletion batches should be atomic per file and re-run the full suite on the CI environment (PostgreSQL) plus composer phpstan and composer rector:types:check per the strategy's mandatory commands.
    4. Keep at least one of each duplicated pair until the coverage-campaign line target is consciously re-negotiated; deleting a duplicate lowers measured coverage even when behavioral protection is unchanged.
    5. Do not delete any skipped/bug-documenting test if the module gains skipped tests in the future; none exist today.
