    3. 发现错误¶

    3.1 FlatNormalizer 破坏了看起来像 JSON 的字符串属性 — HIGH¶

    • 地点： src/Core/Serializer/Normalizer/FlatNormalizer.php:124-130
    • 描述： 通过属性访问器读取的每个非数字字符串属性都通过 json_decode() 传递。如果字符串恰好是有效的 JSON，则属性值将自动替换为解码后的 PHP 值 — 无论属性是 JSON 列还是普通文本字段。
    • 影响： 规范化 API 输出中的类型损坏：纯文本注释 "true" 变为布尔值 true，"null" 变为 null，"{}" / "[]" 变为空数组，"123.0"...（数字字符串被排除，但 "1e2" → 100 不是）。 API 的使用者接收到错误的类型并失去数据保真度。无法选择退出某个列。
    • 复制： 
      $obj = new class { public string $note = 'true'; public string $empty = '{}'; };
(new FlatNormalizer(new ObjectNormalizer(), PropertyAccess::createPropertyAccessor()))
    ->normalize($obj, 'json');
// ['note' => true, 'empty' => []]   ← strings replaced by non-strings
    • 建议的修复： 仅在已知属性是 JSON 列时进行 JSON 解码（例如，由配置的列允许列表或通过上下文传递的 json 学说映射提示驱动），或者在解码值不是数组/对象时保留字符串；不要对每个字符串字段进行全面解码。

    3.2 FlatNormalizer 丢弃除 id/__toString/__metadata 之外的所有关系字段 — MEDIUM¶

    • 位置： src/Core/Serializer/Normalizer/FlatNormalizer.php:106-108 （+ reduceTransform 位于 88-103）
    • 描述：当原始属性值是具有 getId() （关系）的对象时，该属性的装饰规范化器的基线（可能包含 name、slug、price 等）被 reduceTransform($raw) 批量覆盖，它仅发出 id、__toString、__metadata。
    • 影响： 相关实体有效负载被简化为一个 id（可能还有一个标签），默默地删除装饰规范化器生成的所有其他字段。如果 API 预计返回这些字段（例如产品上的类别 name），则响应不完整。
    • 复制： 装饰规范化器返回 ['related' => ['id' => 9, 'name' => 'Pizza', 'price' => 9.99]]；相关对象具有 getId() → 输出关系变为 ['id' => 9, '__toString' => 'Pizza']（name/price 丢失）。
    • 建议的修复： 将简化表示与基线合并（array_merge、id/__toString/__metadata 键到修饰输出上，或仅填充缺失的键），以便现有关系字段保留。

    3.3 LocaleListener 无法解析带有可选空格/大小写的有效 Accept-Language q 值形式 — LOW¶

    • 地点： src/Core/EventListener/LocaleListener.php:78-82
    • 描述： parseAcceptLanguage() 在确切的标记 ;q= 上进行拆分。 RFC 7230/7231 允许在 ;/= 分隔符和不区分大小写的参数名称周围使用可选空格。像 zh-CN; q=1.0, en; q=0.5 这样的标头（; 之后的空格，由某些客户端发出）不会被分割，因此 lang 变成 "zh-CN; q=1.0"，失败 resolveLocale()，并且请求会默默地回退到默认区域设置 en。 fr;Q=1.0 相同。
    • 影响： 格式良好的浏览器/代理可能会提供错误的语言。 （已确认：zh-CN; q=1.0, en; q=0.5 产生区域设置 en 而不是 zh。）
    • 复制： 
      $request->headers->set('Accept-Language', 'zh-CN; q=1.0, en; q=0.5');
$listener->onKernelRequest(new RequestEvent($kernel, $request, HttpKernelInterface::MAIN_REQUEST));
// $request->getLocale() === 'en'  (expected 'zh')
    • 建议的修复： 首先规范化每个项目（折叠空白/小写 q），例如preg_split('/\s*;\s*q\s*=\s*/i', $item) 而不是文字 explode(';q=', ...)，并修剪语言标签。

    3.4 ExpressionDqlParser — 无法访问的防御分支（死代码） — 低¶

    无法提高到 100% 的四条线是任何公众意见都无法达到的。每个都是一个防御分支，其守卫永远不会失败：

    线路 守卫 为什么无法访问
    317 317 if (empty($matches[1])) throw 'Invalid attribute access' 312 处的守卫正则表达式 (/^entity(\.get[A-Z]\w+\(\))+$/) 已经保证 ≥1 次捕获，因此 $matches[1] 永远不会为空。
    394 394 throw 'matches pattern parameter was not compiled' compileMatchOperand() 首先在右操作数上调用 recursiveCompile()，它总是在查找循环运行之前将参数插入到 $this->parameters 中；循环总是能找到它。
    488 488 if (count($segments) === 0) throw 'Empty path' explode('.', $path) 为每个可能的字符串至少返回一个元素。
    541 541 if (strpos($token, ':') === 0) continue 537 处的 where-token 正则表达式 ([a-zA-Z_][\w]*(?:\.[a-zA-Z_][\w]*)+) 永远无法生成以 : 开头的匹配项，因此冒号前缀跳过永远不会触发。

    关于 541 的注释： 这也是一个潜在的正确性气味 - 因为正则表达式以字母开头，:filter_parameter_1 不会被此防护排除，它根本不会匹配（没有点）。更重要的是，正则表达式 确实 匹配字符串文字内的点路径（例如 JSON-ish where 子句），这将使 validateFragments() 抛出不相关的文本。值得后续正则表达式强化（例如 : / 引用处理的负向后查找）。

    3.5 ExpressionQueryBuilderAssembler 默默地吞下连接失败 — 低/中¶

    • 地点： src/Core/Parser/ExpressionQueryBuilderAssembler.php:116-126
    • 描述： leftJoin() 失败被捕获并忽略 (catch (\Exception $e) { /* ignore join errors */ })，并且重复的连接别名会被静默跳过 (117-119)。如果联接路径无效，则程序集“成功”，而 WHERE 子句仍引用缺少的联接别名。
    • 影响： 错误稍后会出现，如查询执行时出现模糊的 DQL“别名未连接”失败，或者当别名被重复用于不同的路径时，查询会默默地返回与预期不同的结果。
    • 建议的修复： 至少记录吞没的异常；考虑对无效的连接路径重新抛出 ValidatorException （与类的其他验证一致），并在别名冲突时出错（或重命名），而不是跳过。

    3.6 OpenApiEnricherListener — 轻微的稳健性问题 — 低¶

    • src/Core/EventListener/OpenApiEnricherListener.php:110-112 — $content === false 无法访问（仅当使用 getContent(true) 时才可访问，但事实并非如此）；空字符串守卫是真正的路径。
    • :115 — 正文以 {（前导模板文本）开头的 HTML /api/doc 响应将被错误分类为原始 JSON 和 json_decoded；今天无害但脆弱。
    • :196 — $t['name'] 在不检查键是否存在的情况下取消引用； tags 条目缺少 name 的规范（例如自定义工具）将引发未定义键警告/通知。
    • :134-138 — if (is_string($newJson)) 块缩进错误（功能上正确，但令人困惑）。

    没有测试被标记为跳过：我编写的所有“正确行为”测试都通过了当前源。 §3.4 中的 4 个枯枝是故意不被覆盖的（它们是无法到达的）；尝试强制它们需要反射注入的假 AST 节点，而这在实践中是不可能发生的。
