    合并的错误列表（按严重性删除重复项）¶

    关键¶

    1. RsaClient 使用 MD5 签名 — src/Core/Utils/RsaClient.php:51,99。 MD5 是可伪造的，并且在 FIPS 下被禁用。修复：OPENSSL_ALGO_SHA256。 (核心-utils-di，R-1)
    2. Location 依赖于 php-curl-class，但未安装 — src/Core/Utils/Location.php:5,18,33,50。每次调用都会导致 Class "Curl\Curl" not found 致命（catch (\ErrorException) 不会捕获 Error）。修复：将包添加到 composer.json 或注入 HTTP 客户端。 （核心-utils-di，L-1）

The incoming request is never passed to EasyWeChat; serve() reads an empty fromGlobals() request → every real callback fails. Fix: $app->setRequestFromSymfonyRequest($request) before serve(). (wechat, Bug 1)
    2. Math::mt_rand()/Math::rand() always throw on PHP 8.5 — src/Core/Utils/Math.php:85,91. One-arg rand()/mt_rand() is an error in PHP 8.5. Fix: rand(0, $x) / mt_rand(0, $x). (core-utils-di, M-1)

    剩余未覆盖线 (46) — 为什么它们未被覆盖¶

    剩余的未覆盖线是四个类别之一，所有类别都记录在每个模块的报告中：

    1. 已弃用的 PHP 构造，如果执行，则会引发弃用（将破坏 failOnDeprecation）：RsaClient openssl_free_key 分支、Math::lcg_value()。
    2. 损坏的代码路径，如果没有致命错误就无法执行：Location::getAddress()（设计损坏）、Math::mt_rand()/rand() 单参数调用（在 PHP 8.5 上崩溃）。
    3. 可证明无法访问的防御/死代码（在给定调用图的情况下永远无法触发的守卫）：BaseServiceReadListTrait死catch，BaseServiceMutationTrait``!is_object检查，ExpressionDqlParser无法到达的错误分支，Inflect失败，Quantity填充分支，TokenManager冗余黑名单检查，RedisOtpStorage错误路径，RsaClient子模尺寸防护装置。
    4. 配置/DI 管道 仅在容器编译时运行（CoreExtension::load、Configuration），该套件执行这些操作，但 Xdebug 的 HTML 报告部分归因于编译时。

    完全消除剩余的行需要删除死代码或重构损坏的路径 - 两者都是 src/ 更改，并且超出了设计范围。

    活动如何进行¶

    • 基线：完整套件（1749 次测试，90.18% 行）通过 var/coverage2。
    • 24 个子代理 分 3 波，每个代理一份报告，每个代理被指示 (a) 永远不要触摸 src/，(b) 瞄准 var/uncovered-map.txt 中列出的未覆盖行，(c) 遵循项目测试约定，以及 (d) 使用 file:line + 建议的修复记录错误并保持套件绿色（在真实 src bug 上失败的正确行为测试标记为 markTestSkipped 并引用报告）。
    • 整合：完整串行运行 → 2686 次测试绿色；修复了一个交叉测试环境泄漏（在 StoreTradeInventoryEnabledFlowTest 的 tearDownAfterClass 中恢复了 INVENTORY_ENABLED）；将 #[AllowMockObjectsWithoutExpectations] 添加到新的模拟重测试类中。
