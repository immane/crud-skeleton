    促销操作手册¶

    此操作手册是配置、验证和故障排除的操作指南 促销捆绑包。它补充了设计文件 与混凝土， 分步程序。

    1. 一分钟概念¶

    • PromotionTemplate 是可重复使用的 DSL 配方（“做什么”）。
    • 促销是绑定到商店的模板的具体的、有时间限制的实例 （“时间和地点”）。
    • DSL 是一种小型、封闭的语言，可在节省时间的情况下解析为 AST。这不是 ExpressionLanguage 并且没有 eval。
    • 引擎将模板 type 解析为 策略 并应用每个 do: 操作 按顺序。
    • 促销活动是多商店：每个促销活动都带有 storeCode。

    2. 两级模型¶

    水平 实体 目的 示例
    食谱 PromotionTemplate 可重复使用的DSL+类型+相位 “满减：花X省Y”
    实例 Promotion 模板+商店+时间窗口+配置 "商店 A，2026-08-01 → 08-31，阈值=200，金额=30"

    始终创作模板一次，然后从中创建许多促销活动。这保持了 DSL 位于一处，让运营商仅调整每个实例的 config。

    3.DSL 快速参考¶

    3.1 结构¶

    type: <promotion_type>       # full_reduction | discount | gift | nth_discount | tiered | free_shipping | member_discount
phase: <inner|outer>         # execution phase (default: inner)
when:
  <condition>
do:
  <action>
priority: <expression>       # optional sort key
fields:
  <name>:<type>:<label>      # optional config field declarations

    3.2 条件¶

    范围 示例
    购物车 cart.subtotal >= 200.00、cart.items.count >= 3
    项目 item.price >= 50.00、item.quantity >= 2、item.spec.id in [42, 43]、item.tags includes "fruit"
    用户 user.level >= "vip"、user.tags includes "new_user"
    配置 cart.subtotal >= config.threshold
    逻辑 and: / or: 列表，not:

    3.3 行动¶

    行动 示例
    全面减持 discount order config.amount
    百分比 discount order 10%
    百分比上限 discount order 10% max 50.00
    礼物 add gift spec:config.gift_spec count:1
    第 N 项 discount item 3 50%
    分层 包含 from:/less: 行的 tiered: 块
    免费送货 free shipping
    会员折扣 member discount 95%

    3.4 配置字段¶

    fields:
  threshold:number:消费门槛(元)
  amount:number:优惠金额(元)
  gift_spec:spec:赠品规格
  min_qty:number:最低件数

    字段类型：number、spec、string、bool。每次促销都会提供价值 config JSON 并在 DSL 中引用为 config.<name>。

    4. 逐步：创建全额折扣促销¶

    4.1 创建模板¶

    POST /api/v1/manage/promotion-templates

    {
  "name": "满减模板",
  "type": "full_reduction",
  "phase": "inner",
  "dsl": "# Spend X, save Y\n\ntype: full_reduction\nphase: inner\n\nwhen:\n  cart.subtotal >= config.threshold\n\ndo:\n  discount order config.amount\n\npriority: config.amount\nfields:\n  threshold:number:消费门槛(元)\n  amount:number:优惠金额(元)\n"
}

    DSL 在保存时进行解析和验证。语法错误返回 422 line:column详细信息。

    4.2 验证 DSL（可选试运行）¶

    POST /api/v1/manage/promotion-templates/{id}/validate

    返回已解析的 AST 和任何错误。在发布模板之前使用它来捕捉 拼写错误没有副作用。

    4.3 创建促销实例¶

    POST /api/v1/manage/promotions

    {
  "name": "Store A 满200减30",
  "template": "<template-id>",
  "storeCode": "store-a",
  "enabled": true,
  "startTime": "2026-08-01T00:00:00+08:00",
  "endTime": "2026-08-31T23:59:59+08:00",
  "config": { "threshold": 200.00, "amount": 30.00 },
  "conflictMode": "best_price"
}

    4.4 验证可用性¶

    GET /api/v1/app/promotions?storeCode=store-a

    仅显示其时间范围内的 enabled = true 促销活动。如果促销是 缺失，请检查 enabled、startTime/endTime 和 storeCode。

    5. 逐步：第 N 件商品折扣¶

    POST /api/v1/manage/promotion-templates

    {
  "name": "第3件5折",
  "type": "nth_discount",
  "dsl": "# Nth item at discounted price\n\ntype: nth_discount\nphase: inner\n\nwhen:\n  item.quantity >= 3\n\ndo:\n  discount item 3 50%\n"
}

    然后创建绑定目标店铺和规格集的促销实例 （specifications数组就提升了）。

    6. 逐步：分级折扣¶

    POST /api/v1/manage/promotion-templates

    {
  "name": "阶梯满减",
  "type": "tiered",
  "dsl": "# Tiered/ladder discount\n\ntype: tiered\n\nwhen:\n  cart.subtotal >= config.from_1\n\ndo:\n  tiered:\n    - from: 100.00  less: 10.00\n    - from: 200.00  less: 30.00\n    - from: 500.00  less: 80.00\n\nfields:\n  from_1:number:起始门槛(元)\n"
}

    最高匹配等级获胜。

    7. 冲突模式¶

    模式 意义
    best_price 仅适用最优惠的配套促销
    stack 多项促销活动可合并

    在升级实例上设置 conflictMode。当多个促销活动匹配相同时 购物车，best_price挑选单件最佳折扣； stack 让它们结合起来。

    8. 相位（内部与外部）¶

    • 内部：在其他定价步骤之前应用（例如全额折扣、赠品）。
    • 外部：之后应用（例如，减少总额的百分比折扣）。

    选择阶段，使折扣基础符合业务意图。百分比 折扣通常运行outer，因此它适用于已经减少的小计。

    9. 故障排除¶

    症状 可能的原因 修复
    促销活动在应用程序列表中不可见 enabled=false、超出时间范围或错误的storeCode 检查实例字段
    DSL 保存返回 422 语法错误 运行 /validate，修复 line:column
    结帐时未应用折扣 phase 错误，或者 conflictMode 排除了它 审查阶段和冲突模式
    忽略配置值 config.<key> 未在 fields 中声明或在实例 config 中缺失 添加字段声明和提供值
    错误的商店看到促销 storeCode 不匹配 在实例上设置正确的 storeCode

    10. 上线前的检查清单¶

    • [ ] 模板DSL通过/validate解析。
    • [ ] 促销enabled=true和时间窗口正确。
    • [ ] storeCode 匹配目标商店。
    • [ ] config 提供 DSL 引用的每个 config.<key>。
    • [ ] conflictMode 和 phase 符合业务意图。
    • [ ] 应用列表端点返回目标商店的促销信息。
