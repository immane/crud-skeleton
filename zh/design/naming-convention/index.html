    命名约定¶

    平台级命名规则，防止模块前缀和类名再次陷入混乱。所有模块、实体、服务和控制器都必须遵守。

    1. 核心原则¶

    命名空间承载模块；类名带有域概念。类名通常不重复模块前缀——模块所有权由 App\<Module>\命名空间，类名仅表达“这是什么领域概念”。

    // The namespace already states module ownership
namespace App\Trade\Entity;   class Order { ... }
namespace App\Store\Entity;   class StoreOrder { ... }   // Prefix only for disambiguation, see §3

    2. 四个规则¶

    ＃ 规则
    N1 类名=领域概念（最好是裸名）；模块所有权由命名空间
    氮气 仅在两种情况下添加模块前缀：（a）跨模块名称冲突/歧义； (b) 模块内基础设施（发件箱/注册表/网关/提供商等，其中前缀有助于发现）
    N3 服务/控制器/存储库/事件/异常严格镜像实体名称：{Entity}Service、{Entity}Controller、{Entity}Repository。前缀由实体决定；其他一切都遵循实体
    N4 同一模块内的前缀必须一致：要么全部带前缀，要么全部裸露，切勿混合使用前缀和裸露

    3. 前缀决策表¶

    案例 方法 示例
    域概念在整个平台上是独一无二的 裸名 Order、Invoice、Product、User、Material、Media、Category
    跨模块同名/不明确 添加模块前缀 StoreOrder（相对于贸易 Order）、WechatUser（相对于身份 User）、TradeOutboxMessage / StoreOutboxMessage / InventoryOutboxMessage、StoreConsumedEvent / InventoryConsumedEvent
    模块内基础设施 仅在需要时使用职责名称+前缀 PaymentGatewayRegistry、ReservationRequestedMessage、DepositService
    实体名称等于模块名称 保留原名 Wallet、Store、Promotion

    3.1 跨模块冲突组（保留前缀，不得删除）¶

    概念 保留类名
    订单 Trade\Order、Store\StoreOrder
    用户 Identity\User、Wechat\WechatUser
    发件箱留言 Trade\TradeOutboxMessage、Store\StoreOutboxMessage、Inventory\InventoryOutboxMessage
    消费事件 Store\StoreConsumedEvent、Inventory\InventoryConsumedEvent

    对于这些组，即使命名空间不同，删除前缀也会强制任何同时引用两个模块的代码写入 use X as Y 别名 - 脆弱且到处都需要。

    4. 新类的命名清单¶

    添加新课程时，请按顺序问自己：

    1. 它是一个实体吗？ → 将其命名为领域概念；检查§3.1冲突表来决定是否添加前缀。
    2. 是实体的Service/Controller/Repository/Event/Exception吗？ → 严格镜像实体名称（N3）；不要发明自己的前缀。
    3. 是模块内基础设施吗？ → 职责名称；仅当模块前缀不明确或有助于发现时才添加模块前缀。
    4. 与现有模块中的相邻类一致吗？ → 违反 N4（同一模块内前缀不一致）将被视为命名违规。

    反模式（禁止）： - 实体 Transaction 但名为 WalletTransactionService 的服务（N3：服务必须镜像实体名称；不得发明前缀） - 已经有 Stock 和 InventoryStock 的模块（N4：前缀必须在同一模块内一致） - 向非服务类添加 Service 后缀（例如 StoreContextResolver 保留其原始名称；不添加 Service）

    5. 变更日志¶

    • 2026-08-15 · 最小前缀重构：删除了平台范围内不必要的模块前缀 — WalletTransaction→Transaction、WalletVoucher→Voucher、WalletPaymentDeduction→PaymentDeduction、 WalletDepositService→DepositService、WalletReconciliationService→ReconciliationService、 InventoryStock→Stock、InventoryReservation→Reservation、InventoryLedgerEntry→LedgerEntry、 StoreMembership→Membership。 表名称/URL/路由名称不变：零迁移，零 API 损坏。 4 个跨模块冲突组保留其前缀（第 3.1 节）。
