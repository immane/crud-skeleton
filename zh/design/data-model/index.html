    数据模型设计合约¶

    抽象实体约定、属性要求、关系模式、生命周期挂钩和字段规则。 每个学说实体必须遵守本合同。

    1. 实体基础合约¶

    每个实体必须具备：

    元素 要求
    命名空间 App\{Module}\Entity
    PHP 8 属性 #[ORM\Entity]、#[ORM\Table]、#[ORM\HasLifecycleCallbacks]
    主键 $id（int，自动递增）
    创建时间戳 $createdAt（日期时间不可变）
    更新时间戳 $updatedAt（日期时间不可变）
    __toString() 方法 返回人类可读的标识符 
    #[ORM\Entity(repositoryClass: XxxRepository::class)]
#[ORM\Table(name: 'module_table_name')]
#[ORM\HasLifecycleCallbacks]
class Xxx
{
    #[ORM\Id]
    #[ORM\GeneratedValue]
    #[ORM\Column]
    private ?int $id = null;

    #[ORM\Column]
    private ?\DateTimeImmutable $createdAt = null;

    #[ORM\Column]
    private ?\DateTimeImmutable $updatedAt = null;

    public function __toString(): string { return (string)$this->id; }

    #[ORM\PrePersist]
    public function touch(): void
    {
        $this->createdAt = new \DateTimeImmutable();
        $this->updatedAt = new \DateTimeImmutable();
    }
}

    2. 命名约定¶

    2.1 表名¶

    规则 示例
    小写，下划线分隔 common_category
    模块前缀 common_*、trade_*、payment_*、wallet_*、identity_*
    单数名词 wallet 不是 wallets
    连接表 {left}_{right}（例如，common_content_tag）

    2.2 列名¶

    规则 示例
    PHP 中的驼峰命名法 sortOrder、createdAt
    数据库中的snake_case sort_order、created_at
    外键列 {entity}_id（例如，category_id）
    布尔列 动词或形容词（例如 is_deleted、enabled）
    状态栏 名词（例如，status）
    时间戳列 *_at 后缀（例如 expires_at、completed_at）

    2.3 PHP 中的属性命名¶

    规则 示例
    驼峰式 $createdAt、$sortOrder
    布尔值获取器 isEnabled()、isDeleted()
    集合属性 复数名词（例如，$tags、$items）
    关系属性 单数表示 M:1/O:O ($category)，复数表示 1:M/M:M ($items)

    3. 字段类型映射¶

    3.1 标量类型¶

    PHP 类型 学说类型 数据库类型 使用案例
    ?int integer INT ID、计数器、排序顺序
    int bigint 大智 金额（分）
    ?string string VARCHAR(n) VARCHAR(n)
    string text 文本 正文内容、描述
    bool boolean TINYINT(1) 标志、状态切换
    ?float decimal 小数(p,s) 如果需要小数钱
    array json JSON 元数据、配置、快照

    3.2 日期时间类型¶

    PHP 类型 学说类型 数据库类型 使用案例
    ?\DateTimeImmutable datetime_immutable 日期时间 所有时间戳

    规则：始终使用 DateTimeImmutable，切勿使用 DateTime。

    3.3 整体金额（美分合约）¶

    规则 详情
    存储类型 bigint（整数分）
    PHP 属性类型 int
    外部API 十进制（例如，20.00）
    写入时转换 * 100
    读取时转换 / 100
    转换机制 @transform表达或服务方法

    4. 关系契约¶

    4.1 属性要求¶

    每个关系都必须声明： - targetEntity (FQCN) - inversedBy / mappedBy（双向） - cascade策略（显式） - fetch策略（显式，默认LAZY可接受）

    4.2 关系基数¶

    类型 PHP 属性 拥有方 数据库专栏
    多对一 #[ORM\ManyToOne] 当前实体（此处为FK） FK专栏
    一对多 #[ORM\OneToMany] 对面 无列 (mappedBy)
    多对多 #[ORM\ManyToMany] 任一侧 连接表
    一对一 #[ORM\OneToOne] 当前实体（此处为FK） FK + 独特

    4.3 自引用关系¶

    图案 示例 属性
    树/父 类别 -> 家长/孩子 ManyToOne(targetEntity: self::class)、OneToMany(mappedBy: 'parent')
    邻接 评论 -> 家长/回复 ManyToOne(targetEntity: self::class)、OneToMany(mappedBy: 'parent')

    5. 索引和约束合约¶

    5.1 强制¶

    元素 要求
    主键 单个自增整数 id
    外键 所有 FK 列必须有显式索引
    独特的约束 关于自然键（slug、电子邮件、电话、用户名、referenceId）

    5.2 可选（性能）¶

    图案 何时添加
    综合指数 (entity_id, status) 上的频繁查询过滤
    全文索引 body/title 上的内容搜索
    状态索引 频繁的WHERE status = ?查询

    6. 生命周期契约¶

    6.1 所需的生命周期回调¶

    回拨 方法 目的
    #[ORM\PrePersist] touch() 设置 createdAt 和 updatedAt

    6.2 可选的生命周期回调¶

    回拨 使用案例
    #[ORM\PreUpdate] 更新 updatedAt 修改
    #[ORM\PrePersist] 计算派生字段（例如，price = unitPrice * quantity）
    #[ORM\PrePersist] 保存实体快照（例如，productSnapshot）

    7. 特殊图案¶

    7.1 用于外部和跨境身份的 UUID¶

    实体为本地 Doctrine 关系、连接和连接保留整数自动增量 id 存储效率。 UUID 是一个独立的、稳定的身份，用于离开其实体的实体 有界上下文。

    当实体属于以下任一情况时，它必须具有 UUID：

    • 可通过公共 API、URL、Webhook 或第三方集成进行寻址。
    • 包含在跨模块或跨服务事件负载中。
    • 域聚合，稍后可能会移动到自己的数据库/服务。
    • 由幂等性、审计、支付、库存或外部关联流引用。

    纯粹的内部实现记录不需要单独的实体UUID。示例 包括私有连接表或已由其唯一标识的收件箱记录 传入eventId。通过 API 公开的独立管理关系应该 仍然收到 UUID。

    Local database key / Doctrine relation: integer id
Public API path and response identity: uuid
Cross-module/service reference: uuid or immutable business key
Event aggregateId, sourceId, correlationId: uuid

    新的跨界实体使用规范的 UUID 字符串和整数 id：

    #[ORM\Column(type: 'string', length: 36, unique: true)]
private string $uuid;

public function __construct() {
    $this->uuid = UUID::v4();
}

    UUID 不是授权机制。每次查找仍然需要行级 授权和所有权检查。

    7.1.1 UUID 版本策略¶

    • 使用 UUID v4 的现有实体保留其当前标识符；迁移不得 重写标识符仅仅是为了版本统一。
    • 一旦共享 UUID 实用程序支持，新的跨服务聚合应该使用 UUID v7 它，因为时间排序提高了索引局部性。
    • 在 UUID v7 可用之前，UUID v4 对于新实体和事件是可接受的。
    • UUID 格式和版本是外部 UUID 字符串背后的实现细节 合同。消费者不得从 UUID 字节推断业务含义。

    7.2 软删除¶

    #[ORM\Column]
private bool $isDeleted = false;

    使用时间：实体永远不应该被硬删除（审计跟踪、法律要求）。

    结果：所有查询必须过滤 isDeleted = false （通过控制器中的 commonFilter()）。

    7.3 价值快照¶

    当一个实体捕获另一个实体状态的时间点副本时：

    #[ORM\Column(type: 'json', nullable: true)]
private ?array $snapshot = null;

    在创建时填充（在 #[ORM\PrePersist] 或服务方法中），从未更新。

    7.4 乐观锁¶

    #[ORM\Version]
#[ORM\Column]
private int $version = 1;

    使用时间：对同一记录的并发更新存在数据损坏的风险（例如钱包余额）。

    7.5 多态关联¶

    对于引用不同实体类型的评论/反应：

    #[ORM\Column(length: 100)]
private string $entityType;  // e.g., 'App\Common\Entity\Content'

#[ORM\Column]
private int $entityId;

    无 FK 约束（在应用层解决）。

    7.6 JSON 元数据/额外数据¶

    #[ORM\Column(type: 'json', nullable: true)]
private ?array $metadata = null;

#[ORM\Column(type: 'json', nullable: true)]
private ?array $extraData = null;

    使用时间：不需要专用列的可扩展字段。

    8. 存储库合约¶

    每个实体必须有一个专用的存储库：

    namespace App\{Module}\Repository;

use App\{Module}\Entity\Xxx;
use Doctrine\Bundle\DoctrineBundle\Repository\ServiceEntityRepository;
use Doctrine\Persistence\ManagerRegistry;

class XxxRepository extends ServiceEntityRepository
{
    public function __construct(ManagerRegistry $registry)
    {
        parent::__construct($registry, Xxx::class);
    }
}

    8.1 自定义查询方法¶

    • 存储库可以在基本 ServiceEntityRepository 之外添加自定义查询方法
    • 自定义方法返回实体、数组或标量值 - 永远不要使用 QueryBuilder（这是服务层负责组合的）
    • 如果需要跨模块消费，可以为存储库创建接口（例如，ContentRepositoryInterface）

    8.2 用于 IDE 支持的 PHPDoc¶

    • 添加 @method Xxx|null find($id) 和 @method Xxx[] findAll() 文档块

    9. 验证合约¶

    实体通过属性或注释定义验证规则：

    use Symfony\Component\Validator\Constraints as Assert;

#[Assert\NotBlank]
private ?string $name = null;

#[Assert\Email]
private ?string $email = null;

    通过 Symfony Validator 在 BaseService::update() 中调用验证。实体必须声明以下约束： - 必填字段 (NotBlank) - 格式限制（Email、Url、Regex） - 长度限制 (Length) - 范围约束（Range、Positive、PositiveOrZero） - 选择约束（Choice 用于枚举/状态）

    10. 反模式（禁止）¶

    反模式 该怎么办？
    扩展 RestController 或 BaseService 的实体 实体是纯粹的数据对象
    实体方法中的业务逻辑 移至服务层
    将服务注入实体 实体不得使用 DI
    实体中直接 $em->persist() 使用Service层
    可变 DateTime 使用 DateTimeImmutable
    将内部 ID 公开为外部标识符 使用 UUID 进行面向外部的引用
    在代码中将钱存储为浮点/小数 存储为 int（分），在 API 边界处转换
    JSON 中的循环引用无需处理 使用 CircularReferenceHandler 或序列化器组
