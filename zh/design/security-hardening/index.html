    安全强化路线图¶

    本文档概述了建议的 CRUD 骨架安全强化措施。 它描述了期望的最终状态——而不是当前的漏洞。

    有意排除敏感详细信息（文件路径、行号、攻击链）。 报告流程请参见项目的security policy。

    优先级 P0 — 立即¶

    序列化/敏感数据暴露¶

    • [ ] 将序列化器组或 #[Ignore] 属性添加到 User、WechatUser 和 RefreshToken 防止敏感 getter 的实体（getPassword、getSessionKey、getRefreshTokenHash、 等）以免包含在 JSON 响应中。
    • [ ] 向 @expands、@display 和 @select 动态添加字段允许列表（或显式拒绝列表） 参数，以便身份敏感字段和关系遍历无法浮出水面 通过链式 getter 调用或表达式求值。
    • [ ] 对@expands强制执行最大遍历深度，以防止无界关系遍历。
    • [ ] 使用 enable_max_depth 和默认组应用全局序列化器默认上下文，以便 默认情况下，扩展/模块受到保护。

    文件上传¶

    • [ ] 添加 可执行文件扩展名 的拒绝列表（.php、.phtml、.pht、.phar、 .htaccess 等）在媒体上传管道中 - 使用 finfo 验证服务器端而不是 信任客户端提供的 Content-Type 标头。
    • [ ] 在 public/uploads/ 中放置一个 .htaccess (Apache) 或等效配置 禁用 PHP 执行和直接脚本访问。
    • [ ] 对每个用户的上传端点进行速率限制，以防止因洪水而耗尽磁盘。

    身份验证¶

    • [ ] 将 OTP HMAC 机密移至环境变量 (OTP_HMAC_SECRET)，而不是 硬编码文字，因此每个部署都有一个唯一的秘密。
    • [ ] 将 OTP 长度从 6 位增加到 8 位。

    付款¶

    • [ ] 仅在dev和test环境中注册MockGateway；确保它不存在于任何 生产服务容器。

    优先 P1 — 本周¶

    身份验证¶

    • [ ] 集成 Symfony 的 RateLimiter 组件并配置每个帐户 + 每个 IP 策略 /api/auth/login 防止暴力攻击。
    • [ ] 在重复登录失败后添加渐进式退避或验证码要求。
    • [ ] 统一注册错误消息 — 使用单个通用响应，无论哪个 字段（电子邮件/用户名/电话）冲突 - 防止用户枚举。
    • [ ] 强制执行 8–12 个字符的最小密码长度以及混合字符类型要求。
    • [ ] 要求调用者针对 verify_phone OTP 目的进行身份验证，以便只有 登录用户可以验证自己的电话号码。

    序列化¶

    • [ ] 添加带有基于属性或基于组的排除的默认序列化器上下文，如此新 将来添加的实体不会意外暴露敏感的 getter。

    付款¶

    • [ ] 将#[ORM\Version]（乐观锁定）添加到Invoice实体以防止丢失更新 在并发付款处理期间。
    • [ ] 将数据库事务内的markPaid()“已支付”幂等性检查移至 关闭狭窄的并发通知窗口。

    DoS/资源限制¶

    • [ ] 对所有列表端点强制执行最大 limit 值（例如 100 或 200），以便单个 请求无法检索无限数量的行。
    • [ ] 强制@select和@groupBy路径通过分页器而不是返回 直接整个结果集。
    • [ ] 在 Doctrine 配置中添加查询执行时间限制。

    优先 P2 — 本月¶

    身份验证¶

    • [ ] 将 nbf （之前未）声明添加到 JWT 访问令牌。
    • [ ] 验证 decodeAccessTokenWithoutBlacklist 中的 iss（发行者）声明。
    • [ ] 对基于 JTI 的黑名单缓存密钥使用加密哈希（例如 SHA-256），而不是 非加密哈希。
    • [ ] 删除AuthController和OtpController之间的OTP端点重复；保留一个 规范的实施。
    • [ ] 将 App 控制器上的 #[IsGranted] 从方法级别移动到类级别以降低风险 新操作意外丢失注释。
    • [ ] 在失败的 OTP 验证尝试之间添加冷却时间。

    文件上传¶

    • [ ] 在 LocalStorage::store() 中添加路径遍历防护（剥离 ../，拒绝路径分隔符） 无论调用者是谁，存储驱动程序本身都是有弹性的。
    • [ ] 优先选择服务器检测到的图像尺寸 (getimagesize)，而不是客户端提供的元数据。

    付款¶

    • [ ] 将#[ORM\Version]添加到支付流程中涉及的所有实体（Invoice、Order、 Wallet）以防止丢失更新。
    • [ ] 删除无效的refund-notify访问控制规则，或实施相应的 Webhook 控制器。

    DoS/查询安全¶

    • [ ] 为每个实体或一个实体添加允许的 @order 和 @groupBy 字段的允许列表 排序/分组列的最大数量。
    • [ ] 在ExpressionDqlParser::recursiveCompile中添加最大递归深度保护。
    • [ ] 为 @hints 添加允许的 Doctrine 查询提示的允许列表。

    序列化¶

    • [ ] 从 API 错误响应信封中删除异常类名称。
    • [ ] 将 /system/entities/{entityName} 限制为 ROLE_ADMIN 或删除敏感元数据 （列类型、长度）来自响应。

    优先 P3 — 正在进行¶

    横切¶

    • [ ] 集成自动依赖漏洞扫描（Dependabot / GitHub Advisory 数据库）（如果尚未激活）。
    • [ ] 检查任何媒体或用户拥有的实体的 ON DELETE SET NULL 外键 — 确保 删除的用户不会导致以前的私人数据变得公开。
    • [ ] 对所有应用控制器运行定期手动 IDOR 审核：验证 commonFilter + 显式所有权检查涵盖 detail、update、delete 和任何自定义操作方法。
    • [ ] 添加敏感操作的审核日志记录（媒体删除、支付状态更改、钱包 调整）以支持取证分析。
