    API文档合约¶

    /api/doc 如何工作、如何扩展它以及每个新端点必须遵循的规则。

    1. 架构¶

    flowchart TD
    A["Controller #[OA\*] attributes"] --> B["swagger-php (zircote)"]
    B -->|"generates raw OpenAPI paths + generic tags"| C["NelmioApiDocBundle"]
    C -->|"merges config/packages/nelmio_api_doc.yaml<br/>(schemas, security, info)"| D["OpenApiEnricherListener"]
    D -->|"kernel.response event<br/>overrides tags, summaries, descriptions"| E["/api/doc (Swagger UI)<br/>/api/doc.json (raw JSON)"]

    2. 单文件丰富器¶

    文件：src/Core/EventListener/OpenApiEnricherListener.php

    所有 API 文档丰富内容都位于一个文件中。无需更改控制器。

    2.1 标签检测（detectTag()）¶

    从路由的 operationId 中提取模块标签：

    操作 ID 模式 标签
    sys-auth-* 授权
    manage-products-*、app-products-* 产品
    manage-orders-*、app-orders-* 订单
    manage-categories-*、app-categories-* 类别
    manage-tags-*、app-tags-* 标签
    manage-contents-*、app-contents-* 内容
    manage-comments-*、app-comments-* 评论
    manage-pages-*、app-pages-* 页数
    manage-media-*、app-media-* 媒体
    manage-settings-*、app-settings-* 设置
    manage-wallets-*、manage-transactions-* 钱包
    任何其他 manage-{X}-* 或 app-{X}-* {X}（自动标题大小写）

    2.2 摘要/描述覆盖 (META)¶

    META 常量提供关键端点的可选摘要和描述。如果端点不在 META 中，它仍然会获取正确的标记，但使用 #[OA\*] 属性中的默认摘要。

    示例： 

    '/api/v1/manage/orders/{id}/pay' => [
    'summary' => ['post' => 'Pay for order (wallet)'],
    'desc' => ['post' => 'User wallet → system wallet. Sets paidAt. Order must be confirmed.'],
],

    2.3 添加新模块¶

    1. 路由命名：使用manage-{resource}-{action}或app-{resource}-{action}约定
    2. 自动检测：资源名称自动标题大小写为标签
    3. 可选：添加到 detectTag() 中的 $known 映射以获取自定义显示名称： 
      'notification' => 'Notifications', 'notifications' => 'Notifications',
    4. 可选：向 META 添加关键端点的摘要/描述

    3. 模式定义¶

    文件：config/packages/nelmio_api_doc.yaml

    实体模式在 documentation.components.schemas 下定义。每个架构都提供 Swagger UI 中可见的字段级类型、描述、枚举和示例值。

    当前架构：订单、订单项、产品、规格、类别、标签、内容、评论、页面、媒体、设置、钱包、交易、TransferRequest、LoginResponse、UserRef。

    3.1 添加新架构¶

    components:
    schemas:
        NewEntity:
            type: object
            properties:
                id: { type: integer }
                name: { type: string, example: 'Example' }
                status: { type: string, enum: [active, inactive] }

    4. 控制器属性要求¶

    每个端点必须具有 OpenAPI 属性。 View 特征（ListApiViewMixin 等）已经提供了它们。自定义端点需要显式属性：

    #[OA\Post(
    path: '/api/v1/manage/resource/custom-action',
    summary: 'Custom action description',
    requestBody: new OA\RequestBody(
        required: true,
        content: new OA\JsonContent(properties: [
            new OA\Property(property: 'field', type: 'string', example: 'value'),
        ])
    ),
    responses: [
        new OA\Response(response: 200, description: 'Success'),
    ]
)]
#[Route('/resource/custom-action', name: 'manage-resource-custom', methods: ['POST'])]
public function customAction(): Response { ... }

    路由命名至关重要 — name: 前缀决定了 operationId，而 operationId 又决定了模块标签： - manage-products-custom → operationId: post_manage-products-custom → 标签：产品 - app-orders-export → operationId: get_app-orders-export → 标签：订单

    5. 安全文档¶

    承载 JWT 身份验证是全局配置的：

    components:
    securitySchemes:
        bearerAuth:
            type: http
            scheme: bearer
            bearerFormat: JWT

    公共端点（无需身份验证）使用 security: [] 覆盖每个路径。

    6. 响应格式¶

    所有端点返回统一的信封。这在 OpenAPI info.description 中有记录：

    {
    "data": {},
    "code": 200,
    "message": "SUCCESS",
    "paginator": null
}

    适用时的分页元数据： 

    {
    "paginator": {
        "page": 1,
        "limit": 20,
        "pages": 5,
        "total": 100
    }
}

    7. 动态查询参数¶

    列表端点支持这些查询参数（记录在 ListApiViewMixin 中）：

    参数 类型 描述
    page 整数 页码（从 1 开始）
    limit 整数 每页项目
    @filter 字符串 表达式 WHERE（例如 entity.status == "active"）
    @dql 字符串 原始 DQL 子查询
    @order 字符串 排序：field\|ASC 或 field\|DESC
    @select 字符串 DQL SELECT 覆盖
    @sort 字符串 内存中排序表达式
    @expands 字符串 嵌套实体扩展
    @display 字符串 场投影模式

    8. 验证¶

    # Check generated JSON
curl -s http://127.0.0.1:8080/api/doc.json | python3 -m json.tool | head -50

# Check embedded HTML spec
curl -s http://127.0.0.1:8080/api/doc | grep -o '"tags":\[.*\]' | head -1

# Count tags
curl -s http://127.0.0.1:8080/api/doc.json | python3 -c "
import sys,json;from collections import Counter
d=json.load(sys.stdin)
tc=Counter()
for p,ms in d['paths'].items():
    for m,op in ms.items():
        if isinstance(op,dict): tc.update(op.get('tags',[]))
for t in sorted(tc): print(f'  {t}: {tc[t]}')
"
