    核心捆绑设计¶

    核心包（src/Core/）是所有业务模块所依赖的基础框架。 它提供控制器基类、CRUD 服务抽象、动态查询引擎、视图混合系统、序列化器管道和实用程序类。

    1. 概述¶

    核心包不是业务模块——它是框架层。它导出 Common、Trade、Payment、Wallet 和 Identity 模块使用的抽象。核心不能依赖于任何业务模块。

    1.1 核心提供什么¶

    关注 组件
    HTTP 响应 RestController -- 统一 JSON 成功/警告/分页
    增删改查服务 BaseService + BaseServiceInterface -- 具有动态查询的抽象 CRUD
    查看混入 9 个 PHP 特性——列表、详细信息、创建、更新、删除、工作流程、单例
    动态查询 ExpressionDqlParser -- 将表达式编译为 DQL，ExpressionService -- 缓存外观
    序列化器 FlatNormalizer -- 装饰 ObjectNormalizer、CircularReferenceHandler、ObjectCallback
    错误处理 ExceptionInterceptor -- 捕获未处理的 /api 异常， ControllerListener -- 请求日志记录
    公用事业 UUID、RSA、数学、ArrayCommon、StringCase、Inflect、FilterDateTime、FixJSON、位置
    DI ServiceLocatorInterface + DefaultServiceLocator -- 可测试的服务位置

    4. BaseService -- CRUD 服务合约¶

    文件：src/Core/Service/BaseService.php 接口：src/Core/Service/BaseServiceInterface.php

    由三个特征组成：

    BaseService (abstract)
|-- BaseServiceInfrastructureTrait   # EM, Logger, Serializer, Validator, Transactions
|-- BaseServiceReadListTrait         # get(), list() with dynamic queries
|-- BaseServiceMutationTrait         # new(), update(), updateWithoutListener(), remove()

    4.1 BaseService接口方法¶

    方法 签名 描述
    get get(mixed $object, bool $directly=false) 按本地 ID、UUID、条件或 QueryBuilder 查找
    list list($object=null, $order=null, bool $disableRequest=true) 列出或返回 QueryBuilder
    new new() 创建实体实例
    update update($object, array $data=null, bool $noFlush=false) 持久保存数据实体
    updateWithoutListener updateWithoutListener($object, array $data) 批量 DQL 更新（无事件）
    remove remove($object): bool 删除实体

    4.1.1 标识符查找合约¶

    get() 是常见的查找外观。当前的实现解析标量值 通过本地主键。以下是目标兼容性合同 UUID 感知实现；它必须在代码之前被核心回归测试覆盖 更改已发布：

    $service->get(123);                  // local integer primary key
$service->get('123');                // local integer primary key, backward compatible
$service->get('canonical-uuid');     // unique uuid field
$service->get(['uuid' => $uuid]);    // explicit criteria, always unambiguous

    规则：

    1. 整数和纯数字字符串解析为本地主键。
    2. 规范的 UUID 字符串根据实体的 uuid 字段进行解析。
    3. 数组保持明确的 Doctrine 标准，并且 QueryBuilder 处理保持不变。
    4. 没有映射uuid字段的实体返回null或提出明确的发展 UUID 输入错误；它不能默默地重试该值作为主键。
    5. 实现不得使用“id 查找然后 UUID 回退”启发式，因为 它是不明确的并且增加了不必要的查询。

    跨模块服务、事件使用者和外部 API 代码应该使用显式 get(['uuid' => $uuid]) 或特定于模块的 getByUuid() 便捷方法。的 普通的 get($uuid) 形式可用于符合人体工程学的控制器/服务代码，而不是作为 授权快捷方式。

    4.2 动态查询管道（list()方法）¶

    request params
  -> @dql         (DQL WHERE sub-clause)
  -> @filter      (Expression -> ExpressionDqlParser -> DQL WHERE)
      fallback: LegacyEvaluator (in-memory)
  -> @order       (DQL ORDER BY)
  -> @select      (DQL SELECT)
  -> @groupBy     (DQL GROUP BY)
  -> @hints       (Query hints)
  -> @sort        (in-memory sort)
  -> @showDQL     (debug: return compiled DQL)

    4.3 update() 突变管道¶

    Input data
  -> ManyToOne / OneToOne: resolve by ID
  -> ManyToMany / OneToMany: add/remove by ID (uses Inflect for setter naming)
  -> DateTime: deserialize from string
  -> Scalar fields: Symfony Serializer
  -> Symfony Validator
  -> persist + flush (unless $noFlush)

    5.查看Mixin系统¶

    请参阅 Controller Design Contract 了解完整的特征目录和钩子契约。

    特质 路线 目的

    CreateApiViewMixin POST / 单个+批量创建

    TransformContent （被其他人使用） 基于表达式的字段转换

    6.表达式动态查询引擎¶

    6.1 流程¶

    User query string (@filter or @sort)
  -> ExpressionService (PSR-16 cache facade)
    -> ExpressionDqlParser::parse(string $expression)
      -> fragments: [joins, where, parameters]
    -> ExpressionQueryBuilderAssembler::assemble(fragments, QueryBuilder)
      -> complete QueryBuilder

    6.2 表达式Dql解析器¶

    文件：src/Core/Parser/ExpressionDqlParser.php（479行）

    • 将字符串表达式编译为 DQL 片段
    • 支持二元运算符（==、!=、>、<、>=、<=、&&、||、+、-、*、/、matches）
    • 支持一元 ! 运算符
    • 支持链式属性 (entity.getCategory().getName())
    • 根据 Doctrine 元数据验证片段（必须匹配真实实体字段/关系）
    • 常量：ROOT_ALIAS = 'filter_entity'、PARAM_PREFIX = 'filter_parameter_'
    • 缓存：用于编译表达式的 PSR-16 缓存

    6.3 ExpressionQueryBuilderAssembler¶

    文件：src/Core/Parser/ExpressionQueryBuilderAssembler.php（172行）

    • 从解析器片段组装 QueryBuilder
    • 处理 JOIN 的别名重新映射
    • 避免参数名称冲突

    6.4 遗留评估器¶

    当 DQL 编译失败时（例如，表达式引用与 DQL 不兼容的构造），则回退到： - Symfony ExpressionLanguage + 通过 ArrayCommon::filter() / ArrayCommon::sort() 进行内存过滤/排序

    7. 序列化器管道¶

    7.1 标准化器堆栈¶

    Symfony ObjectNormalizer
  -> FlatNormalizer (decorator)
    -> Strips Doctrine proxy internals
    -> Adds __toString to every entity
    -> Collapses related entities to {id, __toString, __metadata}
    -> Auto-parses JSON strings to arrays/objects

    7.2 循环引用处理¶

    CircularReferenceHandler.php -- 返回实体 ID，如果没有 getId()，则返回 spl_object_hash()。

    7.3 SerializerContextFactory¶

    使用 groups、max_depth、enable_max_depth、circular_reference_handler 构建上下文。

    7.4 对象回调¶

    序列化组的静态回调——返回 ID 或 null。

    8. 事件监听器¶

    8.1 异常拦截器¶

    • 订阅kernel.exception
    • 拦截 /api/* 路由上未处理的异常
    • 记录异常
    • 返回 JSON {code, message, data: {class}}
    • 在dev模式下绕过

    8.2 控制器监听器¶

    • 订阅kernel.controller
    • 记录带有用户 ID、URI 和截断正文的 PUT/POST 请求（最大 1KB）

    10.环境变量（核心相关）¶

    核心框架本身没有特殊的环境变量。配置通过config/services.yaml：

    services:
  App\:
    resource: '../src/'
    exclude:
      - '../src/Core/Serializer/Normalizer/FlatNormalizer.php'
      - '../src/*/EventListener/'
      - '../src/Identity/Controller/'
      - '../src/Identity/Security/'
