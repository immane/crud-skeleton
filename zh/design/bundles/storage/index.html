    存储包设计¶

    存储包 (src/Storage/) 提供可插入的文件存储抽象 由标记的驱动程序支持。 Common/CMS 依赖于存储接口，但从不依赖 直接接触云SDK或文件系统。

    1.范围¶

    1.1 目标¶

    存储是基础设施模块，而不是业务模块。它不拥有任何域实体 并且只提供一种功能：

    能力 目的
    文件存储驱动 接受 UploadedFile，将其持久保存到指定存储后端，并返回公共 URL
    文件删除 从其后端删除以前存储的文件
    驱动程序注册表 按名称公开已注册的驱动程序，以便调用者可以选择 local / qiniu / 等。

    1.2 非目标¶

    排除 原因
    媒体实体所有权 媒体实体位于 Common/CMS
    上传端点所有权 控制器位于 Common/CMS 中并依赖于存储抽象
    图像处理/缩略图 单独关注；稍后可以添加为装饰器或管道步骤
    多驱动镜像/同步 第一阶段每次上传使用一个驱动程序；多驱动程序同时写入超出范围
    账户/存储桶管理 云控制台责任

    2. 模块边界¶

    2.1 模块位置¶

    src/Storage/
|-- Service/
|   |-- MediaStorageInterface.php          # Driver contract
|   |-- MediaStorageRegistry.php           # Tagged iterator collection
|   |-- LocalStorage.php                   # Local filesystem (default)
|   |-- QiniuStorage.php                   # Qiniu Kodo cloud storage
|-- Resources/config/
|   |-- services_storage.yaml              # Explicit service wiring for drivers with env vars

    2.2 依赖方向¶

    来自 至 允许 规则
    存储 核心 是的 UUID、配置参数
    存储 常见 没有 存储不得导入媒体实体或 CMS 服务
    常见 存储 是的 常见取决于 MediaStorageInterface 和 MediaStorageRegistry
    存储 七牛SDK 是的 QiniuStorage是七牛SDK唯一导入的地方

    存储是一个叶基础设施模块。它导出接口，而不是实体。

    3. 司机合同¶

    3.1 媒体存储接口¶

    文件：src/Storage/Service/MediaStorageInterface.php

    interface MediaStorageInterface
{
    /** Driver name used in registry and the `storage` query parameter, e.g. "local", "qiniu". */
    public static function getName(): string;

    /**
     * Persist an uploaded file and return a publicly accessible URL.
     *
     * For local storage the URL is a root-relative path such as
     * `/uploads/202601/a1b2c3d4.jpg`.
     * For cloud storage the URL is a full CDN URL such as
     * `https://cdn.example.com/a1b2c3d4.jpg`.
     */
    public function store(UploadedFile $file, string $name): string;

    /** Remove a previously stored file. The `$path` parameter is the value returned by `store()`. */
    public function delete(string $path): void;
}

    驱动程序实现不得从调用者处抛出域异常。他们可能会扔 \RuntimeException 或特定于驱动程序的异常；调用者应该捕获\Throwable。

    3.2 媒体存储注册表¶

    文件：src/Storage/Service/MediaStorageRegistry.php

    final class MediaStorageRegistry
{
    /** @param iterable<MediaStorageInterface> $drivers */
    public function __construct(#[AutowireIterator('media.storage')] iterable $drivers) {}

    /** @throws \RuntimeException when driver name is unknown */
    public function get(string $name): MediaStorageInterface {}

    /** @return string[] */
    public function names(): array {}
}

    所有 MediaStorageInterface 实现都通过 _instanceof 自动标记 media.storage。

    4. 第一阶段驱动程序¶

    4.1 本地存储¶

    文件：src/Storage/Service/LocalStorage.php

    将文件存储在本地文件系统的 public/uploads/ 下。

    行为 详情
    目录布局 {base_path}/{YYYYMM}/{uuid}.{ext}
    公共网址 根相对路径： /uploads/202601/a1b2c3d4.jpg
    删除 unlink() 物理文件
    配置 %media.local.upload_path%、%media.local.base_url%
    依赖关系 无（纯 PHP 文件系统函数）

    LocalStorage 始终启用并且是默认驱动程序。它对于 无需 CDN 的开发、测试和单服务器生产部署。

    4.2 七牛存储¶

    文件：src/Storage/Service/QiniuStorage.php

    将文件存储在七牛云对象存储上并返回 CDN URL。

    行为 详情
    上传 带有上传令牌的七牛SDK上传管理器
    公共网址 {domain}/{filename} 例如https://cdn.example.com/a1b2c3d4.jpg
    删除 七牛桶管理器delete()
    配置 %env(QINIU_ACCESS_KEY)%、%env(QINIU_SECRET_KEY)%、%env(QINIU_BUCKET)%、%env(QINIU_DOMAIN)%
    依赖关系 overtrue/qiniu-filesystem 或 qiniu/php-sdk

    QiniuStorage 是可选的，由调用者在上传时通过传递来切换 storage=qiniu。当七牛环境变量为空时，服务定义应该 要么被删除，要么它的构造函数应该优雅地降级（返回false 来自 supports() / 仅当使用有效凭据调用 store() 时才抛出）。

    5. 调用者合约（通用/媒体）¶

    5.1 媒体实体扩展¶

    通用 Media 实体获得一个额外的标量字段：

    领域 类型 详情
    storage 字符串（20） 上传时使用的驱动程序名称：local、qiniu等

    这允许 MediaService::remove() 在删除时解析正确的驱动程序 物理文件，而不需要调用者记住使用了哪个驱动程序。

    5.2 媒体服务集成¶

    class MediaService extends BaseService
{
    public function __construct(
        ContainerInterface $container,
        private readonly MediaStorageRegistry $storageRegistry,
    ) {}
}
    方法 责任
    createFromUpload(UploadedFile $file, string $storage, array $meta) 解析驱动程序 → 存储文件 → 持久化带有 storage 字段的媒体实体
    remove(Media $media) 从 media.storage 解析驱动程序 → 删除物理文件 → 删除实体

    MediaService 不得导入任何存储驱动程序类或云 SDK。它仅 通过注册表与MediaStorageInterface对话。

    5.3 控制器上传操作¶

    // App/MediaController
#[Route('/upload', name: 'upload', methods: ['POST'])]
public function uploadAction(Request $request): Response
{
    $file = $request->files->get('file');
    $storage = $request->request->get('storage', 'local');
    $media = $this->service->createFromUpload($file, $storage, $request->request->all());
    return $this->success($media, 'Uploaded', 201);
}

    Manage/MediaController 中重复相同的操作模式。

    文件：config/packages/media.yaml

    文件：.env

QINIU_SECRET_KEY=

    文件：src/Storage/Resources/config/services_storage.yaml

    services:
    _defaults:
        autowire: true
        autoconfigure: true

    App\Storage\Service\LocalStorage:
        arguments:
            $basePath: '%media.local.upload_path%'
            $baseUrl: '%media.local.base_url%'

    App\Storage\Service\QiniuStorage:
        arguments:
            $accessKey: '%env(QINIU_ACCESS_KEY)%'
            $secretKey: '%env(QINIU_SECRET_KEY)%'
            $bucket: '%env(QINIU_BUCKET)%'
            $domain: '%env(QINIU_DOMAIN)%'

    文件：config/services.yaml（添加）

    _instanceof:
    App\Storage\Service\MediaStorageInterface:
        tags: ['media.storage']

    7. 请求流程¶

    POST /api/v1/app/media/upload
  Content-Type: multipart/form-data
  Body:
    file: <binary>
    storage: "qiniu"        (optional, defaults to "local")
    alt: "描述文字"           (optional)

Controller::uploadAction()
  → $request->files->get('file')
  → MediaService::createFromUpload(file, storage, meta)
      → MediaStorageRegistry::get('qiniu')
      → QiniuStorage::store(file, uuid.ext) → "https://cdn.example.com/abc.jpg"
      → persist Media { storage: "qiniu", path: "https://cdn.example.com/abc.jpg", ... }
      → return Media JSON

    7.1 删除流程¶

    DELETE /api/v1/manage/media/{id}

Controller::deleteAction()
  → MediaService::get({ id })
  → MediaService::remove(media)
      → MediaStorageRegistry::get(media.storage)
      → QiniuStorage::delete(media.path)
      → remove entity

    8. 驱动程序自动发现¶

    驱动程序由 Symfony 的标记迭代器收集，而不是由硬编码注册表收集：

    # config/services.yaml
_instanceof:
    App\Storage\Service\MediaStorageInterface:
        tags: ['media.storage']

    final class MediaStorageRegistry
{
    public function __construct(
        #[AutowireIterator('media.storage')]
        iterable $drivers,
    ) {
        foreach ($drivers as $driver) {
            $this->drivers[$driver::getName()] = $driver;
        }
    }
}

    添加新驱动程序（例如 S3Storage）仅需要： 1. 创建 src/Storage/Service/S3Storage.php 实现 MediaStorageInterface 2. 如果需要环境变量，请在 services_storage.yaml 中添加服务定义

    MediaStorageRegistry、MediaService 或任何控制器没有变化。

    9.1 单元测试¶

    测试 覆盖范围

    MediaStorageRegistryTest 按名称/未知驱动程序异常/名称列表解析

    9.2 集成测试¶

    测试 覆盖范围

    MediaStorageSwitchingTest 在同一测试中使用 storage=local 和 storage=qiniu 上传

    当 QINIU_ACCESS_KEY 为空时应跳过七牛集成测试 （标记为 @group qiniu 或由 setUp() 中的环境变量检查保护）。

    10. 错误处理¶

    场景 行为
    司机姓名未知 \RuntimeException 来自注册表，由控制器捕获 → warning()
    上传超出 PHP upload_max_filesize Symfony UploadedFile 在驱动程序调用之前进行验证
    驱动程序存储失败 异常传播；媒体实体未持久化（无孤立记录）
    驱动程序删除失败 已记录但实体仍被删除（尽最大努力清理）

    控制器必须在调用驱动程序之前验证上传的文件：

    检查 规则
    文件存在 $request->files->get('file') !== null
    尺寸限制 可通过media.upload.max_size配置（默认10M）
    MIME 许可名单 可通过 media.upload.allowed_mime_types

    11. 文件验证合约¶

    约束 默认 可配置
    最大文件大小 10 MB media.upload.max_size
    允许的 MIME 类型 image/jpeg、image/png、image/gif、image/webp、application/pdf media.upload.allowed_mime_types
    空文件 被拒绝 —

    验证发生在控制器中或之前的 MediaService::createFromUpload() 中 调用驱动程序，因此无效文件永远不会到达存储后端。

    12. 未来的驱动力¶

    相同的接口支持任何存储后端：

    src/Storage/Service/
|-- LocalStorage.php            # First phase (always enabled)
|-- QiniuStorage.php            # First phase (optional)
|-- S3Storage.php               # Future — AWS S3
|-- OssStorage.php              # Future — Alibaba Cloud OSS
|-- CosStorage.php              # Future — Tencent Cloud COS

    每个都是一个实现 MediaStorageInterface 的类。没有注册表或 需要更改调用者代码。

    13. 开放性问题¶

    问题 默认决定
    存储应该拥有媒体实体吗？ 不，媒体保留在 Common/CMS
    public/uploads/ 应该被忽略吗？ 是的
    QiniuStorage 应该位于单独的 Qiniu 捆绑包中吗？ 不在第一阶段；保留在存储中，直到七牛特定的复杂性（帐户管理、回调处理）证明拆分是合理的
    删除应该是同步的还是排队的？ 第一阶段同步
    私有文件是否应该有一个 serve 端点？ 超出范围； public/uploads/由nginx直接服务
