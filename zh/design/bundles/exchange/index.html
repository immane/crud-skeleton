    交换包设计¶

    Exchange 捆绑包 (src/ExchangeBundle/) 是一个抵押支持的积分/货币经济。 它提供汇率、转换引擎、流动性池、抵押品质押、 积分铸造/发行、单位之间的用户交换（转换）以及兑换 — 所有 针对做市商监督的池。 状态：仅设计 - 未实施。

    1. 概述¶

    Exchange 域涵盖自定义、池支持的单元的整个生命周期（例如 POINT）：

    Pledge          Market maker pledges collateral (e.g. 1 CNY) into a pool → issuance ceiling
Mint            POINT are minted up to the pledge ceiling (solvency-constrained)
Exchange        Users convert between units (CNY ↔ POINT, etc.) via the pool — zero-sum
Redemption      Users redeem POINT back to collateral currency → POINT burned, ceiling lowered
Market maker    Manages pledges, sets rates / spread, watches pool exposure

    1.1 范围¶

    范围（设计） 超出范围（推迟）
    费率表（生效日期，混合模型） 预订到 App\Wallet 分类账 (P1+)
    CurrencyConverter（bcmath，显示级精度） 外部速率进给/自动同步
    矿池、质押、铸币、兑换、赎回记录 日元/0-小数货币
    做市商政策（价差、限制） 支付/贸易定价整合
    零和和偿付能力不变量 API表面（P3）

    1.2 捆绑包位置和命名¶

    • 目录：src/ExchangeBundle/
    • 命名空间：App\ExchangeBundle（in-repo；稍后可通过重命名空间提取到独立的作曲家包）
    • 捆绑包类：ExchangeBundle（扩展Symfony\Component\HttpKernel\Bundle\AbstractBundle）

    3. 数据模型¶

    3.1 ExchangeRate — 费率表（混合，生效日期）¶

    单个表同时保存锚行（基础=配置的基础货币）和直接对覆盖。

    领域 类型 笔记
    id 国际PK汽车
    base_currency 字符串（10） 锚行：exchange.base_currency；覆盖行： from 货币
    quote_currency 字符串（10） CHECK base != quote
    rate 小数(20,8) 字符串 CHECK rate > 0;方向 1 base = rate quote
    source 字符串（50）空 'manual'、'maker'、'feed'（保留提要）
    valid_from 日期时间不可变 有效启动
    valid_to datetime_immutable 空 null = 开放式
    created_at / updated_at 日期时间不可变
    • 独特：(base_currency, quote_currency, valid_from)
    • 索引：(base_currency, quote_currency, valid_from)
    • 写入验证（通过 ExchangeRateService::setRate）：rate > 0，base != quote，间隔有效，并且同一对无重叠间隔。

    3.2 Pool + PoolAccount — 流动性池¶

    实体 目的
    Pool 池身份：code（唯一）、name、status、makerPolicy（拥有做市商）
    PoolAccount 池中持有的每种货币一行：pool、currency、balance（次要单位）、outstanding（已发行但尚未赎回单位）

    余额通过LedgerInterface委托给主机分类账（参见§6）； PoolAccount 保留特定于交易所的会计（未偿、上限）。

    3.3 Pledge — 抵押质押¶

    领域 笔记
    pool、pledgor pledgor 是一个不透明的引用（字符串 id/类型），以保持捆绑包与主机无关
    collateral_currency、collateral_amount 例如CNY、1_0000（次要单位）
    coefficient decimal(20,8) — 锚定转换系数（例如 100000000 = 1 CNY ⇒ 100,000,000 POINT）
    status active / released
    created_at

    质押发行上限：collateral_amount × coefficient（针对 POINT 方向）。

    3.4 MintRecord — 发行¶

    领域 笔记
    pledge、unit 正在铸造的单位（例如POINT）
    amount 铸造单位
    reference_id unique — 幂等键
    created_at

    约束：Σ minted(unit) − Σ redeemed(unit) ≤ Σ active pledges × coefficient。

    3.5 ExchangeRecord — 用户转化¶

    领域 笔记
    pool、user（不透明参考）、from / to（货币）、amount、result 全部以小单位表示
    rate decimal(20,8) string — 实际应用的汇率
    rate_path direct / inverse / cross — 用于审计
    reference_id unique — 幂等键
    created_at

    3.6 RedemptionRecord — 救赎¶

    领域 笔记
    pool、user（不透明引用）、unit、amount、payout_currency、payout_amount
    reference_id 独特
    created_at

    赎回会燃烧单位并在可用余额内从池中支付抵押品。

    3.7 MakerPolicy — 做市商政策¶

    领域 笔记
    maker（不透明参考），pool 做市商监管矿池
    spread_bps 应用于中间利率之上的基点利差
    fee_bps 转换费（基点）
    max_exposure 每种货币最大敞口限额（风险防范）
    active

    4. 转换引擎 (CurrencyConverter)¶

    4.1 API¶

    interface CurrencyConverterInterface
{
    /** Convert amount (minor units of $from) to minor units of $to. */
    public function convert(int $amount, string $from, string $to, ?\DateTimeImmutable $at = null): int;

    /** Resolve the rate 1 $from = ? $to, as a decimal string. */
    public function rate(string $from, string $to, ?\DateTimeImmutable $at = null): string;
}

    4.2 算法¶

    1. 规范化两个代码：strtoupper；扩展代码（CNY.ESCROW）在.之前折叠到主单元。
    2. 相同单位，或amount === 0 → 不变返回amount。
    3. 解决比率——先击中胜：
    4. 直接配对：有效(from → to)行。
    5. 逆对：有效(to → from)行，取倒数。
    6. 通过基点交叉：rate = rt / rb，其中rt = 1 base = ? to、rb = 1 base = ? from（每个本身都解析为正向或逆向）。
    7. 缺失率/未知单位 → ExchangeRateNotFoundException。
    8. 使用 bcmath 以 scale 16 进行计算，最后舍入 一次（参见第 5 节）。
    9. 整个调用共享一个at瞬间（当$at为空时捕获一次），因此多重查找解析是一致的。

    4.3 只读，与事务无关¶

    CurrencyConverter 仅执行 findEffective() 读取 - 它从不开始事务，从不刷新，从不写入。在调用者的事务内部，它作为普通的 SELECT 参与（无嵌套、无保存点、无副作用）；调用者拥有事务边界。

    5. 精度与金钱数学¶

    任何地方的金额都是整数小单位（分，×100）——与 App\Wallet 和 App\Payment 一致。

    层 精密
    率存储 DECIMAL(20,8)，映射到 PHP string
    中级数学 bcmath scale 16
    最终结果 整数，通过 bcRoundHalfUp 舍入一次

    5.1 四舍五入¶

    没有漂浮物。以字符串数学形式实现：

    private function bcRoundHalfUp(string $value): int
{
    $sign = $value[0] === '-' ? -1 : 1;
    $abs  = $sign < 0 ? substr($value, 1) : $value;
    $rounded = bcadd($abs, '0.5', 0);
    return $sign * (int) $rounded;
}
    • 半上语义（远离零），精确表示负数（退款流）。

    5.2 方向约定¶

    rate(base, quote) = 1 base = rate quote（每单位，而不是百分比）。因为 from/to 都使用相同的 ×100 指数，所以 cents × rate 已经在 to-cents 中：

    案例 公式
    直接 (from→to) X × rate
    逆 (to→from) X ÷ rate
    交叉过孔底座 X × rt / rb

    5.3 已知限制¶

    • 2 位十进制法币假设：所有支持的单位均使用 ×100。日元/韩元（0 位小数）超出范围；在支持它们之前需要每个货币的指数映射（X × rate × 10^(exp_to − exp_from)）。
    • 灰尘：像1 CNY = 100,000,000 POINT这样的系数意味着1 cent = 1,000,000 POINT；转换 POINT → CNY 总是留下最多 1M POINT 的残差。显示效果良好；兑换必须定义灰尘处理（燃烧/积累/携带到下一个）。

    6. 账本抽象¶

    该捆绑包通过定义自己的账本合约来保持与主机无关；主机应用程序提供实现（重用 App\Wallet 的原子、幂等 TransferService）。

    interface LedgerInterface
{
    /** Credit an account (mint / pool funding). Idempotent via $referenceId. */
    public function credit(string $account, string $currency, int $amount, string $referenceId, string $memo): void;

    /** Debit an account (redemption / pool payout). */
    public function debit(string $account, string $currency, int $amount, string $referenceId, string $memo): void;

    /** Atomic transfer between two accounts (exchange legs). */
    public function transfer(string $fromAccount, string $toAccount, string $currency, int $amount, string $referenceId, string $memo): void;

    public function balance(string $account, string $currency): int;
}
    • 在此应用程序中，实现采用 App\Wallet （钱包 + TransferService，通过 referenceId 实现幂等）。
    • 这避免了第二个分类账并将零和保证保留在一个地方。

    7. 预订流程和零和不变量¶

    每次转换都被记录为池中配对、相等和相反的条目→在铸造之外不会创建或销毁货币；每种货币的总余额得以保留。

    7.1 承诺¶

    wrapInTransaction:
  Ledger.transfer(pledgor → pool[CNY], 1_0000, ref, 'pledge')   # collateral into pool
  Pledge(active) + PoolAccount.outstanding/Ceiling updated

    7.2 薄荷¶

    wrapInTransaction:
  assert Σminted(unit) − Σredeemed(unit) ≤ Σactive_pledges × coefficient   # solvency
  Ledger.credit(pool[POINT], Y, ref, 'mint')                                # mint into pool
  MintRecord

    7.3 兑换 — 用户CNY → POINT¶

    wrapInTransaction:
  Y = converter.convert(X, CNY, POINT, now)          # rate with spread applied by MakerPolicy
  Ledger.transfer(user[CNY]  → pool[CNY], X, ref)    # leg 1
  Ledger.transfer(pool[POINT] → user[POINT], Y, ref) # leg 2
  ExchangeRecord (rate, rate_path)

    零和：user.CNY −X / pool.CNY +X和pool.POINT −Y / user.POINT +Y——矿池是交易对手； CNY 总计和 POINT 总计均被保留。

    7.4 救赎¶

    wrapInTransaction:
  Z = converter.convert(Y, POINT, CNY, now)
  Ledger.transfer(user[POINT]  → pool[POINT], Y, ref)   # burn units
  Ledger.transfer(pool[CNY]    → user[CNY], Z, ref)     # payout collateral
  RedemptionRecord; PoolAccount.outstanding reduced

    7.5 不变量¶

    • 零和：内部转账永远不会改变所有账户中任何货币的总余额。
    • 偿付能力：以抵押货币计的Σ issued(unit) − Σ redeemed(unit) ≤ Σ active pledges × coefficient和pool[collateral] ≥ liabilities。零和保持账簿平衡；承诺使资金池保持偿付能力。
    • 利差是收入，而不是违约：MakerPolicy.spread_bps / fee_bps 在资金池中留下少量剩余；账本仍然通过构建保持平衡。

    7.6 做市商¶

    MakerPolicyService： - 拥有矿池及其质押上限。 - 在 ExchangeService 预订期间将点差/费用应用于中间价格。 - 在预订大额兑换之前，保护每种货币的max_exposure。 - 通过有效的约会拥有率更新（锚行+直接覆盖）。

    8. 评分查找语义¶

    ExchangeRateRepository::findEffective(string $base, string $quote, \DateTimeImmutable $at)：

    • WHERE base = :base AND quote = :quote AND valid_from <= :at AND (valid_to IS NULL OR valid_to > :at)
    • ORDER BY valid_from DESC LIMIT 1

    查找路径（直接→反向→交叉）是固定且可审计的（rate_path on ExchangeRecord）；丢失的比率会抛出而不是默默地降低。

    10. 数据库迁移¶

    与现有迁移样式 (migrations/Version2026XXXXXXXX.php) 匹配的原始 SQL DDL：

    • exchange_rate — CHECK (rate > 0, base != quote)，唯一的(base_currency, quote_currency, valid_from)，索引相同。

    11. 测试¶

    • 单位（CurrencyConverter，假利率回购）：同一单位短路，直接对，反向对，通过基础交叉，半上边界（包括.5，负数），未知单位/无有效利率→例外。
    • 单位（服务，假LedgerInterface）：质押上限数学，铸币厂偿付能力拒绝，交易所复式记账余额效应，赎回支付限额，通过referenceId实现幂等性。
    • 集成（真实存储库）：有效日期查找边界 (valid_from <= at < valid_to)、开放式有效性、最新的多个版本、setRate 重叠拒绝。

    12. 分阶段推出¶

    相 范围 取决于
    P0 Bundle骨架+Rate域+CurrencyConverter（纯只读） —
    P1 LedgerInterface +矿池+质押+铸币（发行+偿付能力） P0
    P2 兑换预订+兑换（零和复式） P1
    P3 Maker 政策 + 管理/应用程序 API + 对账/审计报告 P2

    每个阶段都是可独立测试和审查的。预订App\Wallet（主机LedgerInterface实现）登陆P1。

    13. 开放决策和非目标¶

    • 捆绑包装：首先是in-repo App\ExchangeBundle；稍后可提取。
    • 将POINT赎回人民币：必需 → 强制要求提供抵押品。如果积分变成单向的（赚取/花费，从未兑换），则承诺层就会减少为审计支持。
    • 固定锚定与浮动利率：1 CNY = 100,000,000 POINT作为硬编码系数是固定挂钩（质押上限，无利率查找）；浮动利率使用利率表。两者都是可表达的——预订土地时决定优先顺序。
    • 日元/0-十进制货币：不支持（需要每种货币的指数图）。
    • 外部馈送/自动同步：通过 source 保留；没有实施。
    • 在此设计中没有与PaymentDeductionService/贸易定价集成； PaymentDeductionService 今天仍然强制使用相同的货币。
