    系统合约¶

    跨越整个系统的横切规则：事务、错误处理、日志记录、安全性、 验证、测试和部署。每个模块、服务和控制器都必须遵守这些契约。

    1. 交易合约¶

    1.1 交易边界¶

    事务在服务层进行管理，而不是在控制器中进行管理。

    // In any service:
$this->wrapInTransaction(function ($em) use ($data) {
    // Multiple persist/update operations
    // All-or-nothing semantics
});

    1.2 规则¶

    ＃ 规则
    T1 相关实体的多个突变必须包含在一个事务中
    T2 钱包传输必须使用显式 beginTransaction()/commit()/rollback() 和实体锁 (PESSIMISTIC_WRITE)
    T3 回滚后，EntityManager必须恢复（$em->isOpen()检查）
    T4 控制器不得直接调用 beginTransaction()、commit()、rollback()
    T5 mixin 方法（createAction、batchUpdateAction）自动处理事务包装，除非 @partial=true

    1.3 部分模式合约¶

    当@partial=true时： - 每件商品均独立处理（无交易） - 失败的项目会被默默地跳过 - 成功的物品将被退回

    当@partial=false时（默认）： - 一次交易中的所有商品 - 任何失败都会回滚所有项目

    2. 错误处理合约¶

    2.1 异常层次结构¶

    \Exception
  |-- RuntimeException
  |     |-- InsufficientFundsException      (Wallet module)
  |     |-- WalletFrozenException           (Wallet module)
  |     |-- SameWalletTransferException     (Wallet module)
  |     |-- OrderInvalidTransitionException (Trade module)
  |     |-- SpecificationNotFoundException  (Trade module)
  |     |-- PaymentGatewayNotFoundException (Payment module)
  |     |-- PaymentVerificationException    (Payment module)
  |     |-- InvoiceInvalidTransitionException (Payment module)
  |     |-- InvoiceAmountMismatchException  (Payment module)
  |-- MessageErrorHttpException             (Core - user-facing)
  |-- MessageSuccessHttpException           (Core - success with custom message)

    2.2 扔到哪里¶

    层 可能会抛出
    实体 不
    存储库 仅原则例外
    服务 业务异常（特定于模块）
    控制器 NO（捕获并转换为 warning()）

    2.3 全局异常处理¶

    ExceptionInterceptor 捕获 /api/* 路由上未处理的异常：

    Exception -> catch -> log -> JSON response {code, message, class}

    在 dev 模式下，绕过（标准 Symfony 异常页面）。

    2.4 控制器错误处理模式¶

    try {
    // ... business logic ...
} catch (ValidatorException $e) {
    return $this->warning($e->getMessage(), 400, '', 400);
} catch (NotFoundHttpException $e) {
    return $this->warning($e->getMessage(), 404, '', 404);
} catch (\Exception $e) {
    return $this->warning($e->getMessage() ?: RestController::UNKNOWN_ERROR, 500, '', 500);
}

    控制器必须捕获域异常并转换为 warning() 响应——绝不让未处理的异常传播。

    3. 日志合约¶

    3.1 日志通道¶

    频道 目的
    app 一般应用日志
    doctrine Doctrine ORM 查询（仅限开发）
    security 认证/授权事件

    3.2 记录什么¶

    活动 水平 内容
    请求正文（PUT/POST） 信息 用户 ID、URI、截断正文 (1KB)
    未处理的异常 错误 异常类、消息、跟踪
    钱包转账 信息 发件人/收件人钱包、金额、参考 ID
    一次性密码发送 信息 电话（屏蔽），用途
    代币轮换异常 警告 检测到重用，撤销所有令牌

    3.3 不记录什么¶

    • 明文密码、令牌、OTP 代码
    • 包含敏感数据的完整请求正文（截断为 1KB）
    • 生产中的个人数据 (PII)

    4. 验证合约¶

    4.1 验证层¶

    层 机制 什么
    控制器（输入） $requiredCreateProperties、$acceptedCreateProperties 现场存在/白名单
    控制器（输入） processCreateContent() 钩子 定制业务验证
    服务 Symfony 验证器 ($this->getValidator()->validate($entity)) 实体约束验证
    实体 #[Assert\*] 属性 声明性字段约束

    4.2 验证顺序¶

    Controller field whitelist
  -> Controller hook validation (processCreateContent/processUpdateContent)
    -> @transform expression evaluation
      -> Service::update() -> Symfony Validator -> Entity constraints

    4.3 错误消息合约¶

    • 验证错误：简短、面向用户、本地化（通过翻译器）
    • 错误代码：HTTP 状态代码
    • 字段级错误：按字段名称键入

    5. 安全合约¶

    5.1 身份验证¶

    组件 责任
    JwtAuthenticator 从 Authorization: Bearer 中提取 JWT、验证、创建 Passport
    TokenManager 创建/解码/撤销 JWT 访问令牌，管理刷新令牌生命周期
    User 实体 实现 UserInterface、PasswordAuthenticatedUserInterface

    5.2 授权¶

    机制 哪里
    #[IsGranted('ROLE_ADMIN')] 管理控制器（类级别）
    commonFilter() 覆盖 行级数据范围（例如，用户只能看到自己的订单）
    security.yaml 访问控制 路由模式级防火墙规则

    5.3 令牌安全规则¶

    ＃ 规则
    S1 访问令牌：RS256 签名、7200s TTL
    S2 刷新令牌：不透明，HMAC-SHA256 在数据库中散列，1 年 TTL
    S3 令牌轮换：每次使用时都会更换刷新令牌
    S4 重用检测：如果使用撤销/替换的刷新令牌，则撤销所有用户令牌
    S5 JWT 黑名单：撤销访问令牌 JTI 存储在具有 TTL 的缓存中直至自然过期
    S6 不得提交私钥（在 .env.dev 或保管库中）
    S7 所有 API 端点在生产中都使用 HTTPS

    5.4 限速合约¶

    资源 限制 存储
    OTP 请求（每部电话） 每 60 秒冷却时间 1 次 Redis / 缓存
    OTP 验证（每部手机） 最多尝试 5 次 Redis / 缓存
    登录（每个IP） 实现定义 应用级

    6. 序列化合约¶

    6.1 标准化器管道¶

    ObjectNormalizer (Symfony)
  -> FlatNormalizer (decorator)
    -> DateTimeNormalizer (custom)
      -> CircularReferenceHandler (fallback)

    6.2 FlatNormalizer 规则¶

    规则 行为
    教义代理 剥离（内部已移除）
    __toString 添加到每个序列化实体
    相关实体 折叠到 {id, __toString, __metadata}
    字段中的 JSON 字符串 自动解析为数组/对象
    可遍历集合 标准化为数组
    超出最大深度 循环引用处理程序回退

    6.3 序列化器组¶

    通过 SerializerContextFactory 支持： - groups：序列化器组名称数组 - max_depth：最大序列化深度 - enable_max_depth：是否强制深度限制

    7. 测试合同¶

    7.1 覆盖范围要求¶

    • 最小值：90% 线路覆盖率（在 CI 中强制执行）
    • 测试环境：APP_ENV=test，SQLite数据库

    7.2 测试类别¶

    类别 延伸 目的
    单位 PHPUnit\Framework\TestCase 隔离逻辑（实体、实用程序、计算器）
    内核 IntegrationKernelTestCase 具有启动内核、服务访问、DB
    网页 IntegrationWebTestCase 完整的 HTTP 请求/响应周期
    回归 变化 API合约稳定性

    7.3 测试命名约定¶

    图案 示例
    {Class}Test CategoryTest.php、OrderServiceTest.php
    {Module}ApiRegressionTest CommonModulesApiRegressionTest.php
    {Module}IntegrationTest WalletApiIntegrationTest.php

    7.4 测试数据库合约¶

    • 每个测试方法都从一个干净的模式开始
    • 模式是从 DatabaseBootstrapTrait 中的 Doctrine 模式工具（而不是迁移）创建的
    • 按测试或按类别插入测试数据装置
    • 每次测试都会包装事务并回滚（自动回滚）

    7.5 静态分析合约¶

    • PHPStan：配置的 src/ 范围内的级别 8；运行composer phpstan
    • Rector：CI 针对 Doctrine Collection/Repository PHPDoc 规则进行试运行 composer rector:types:check
    • Broader Rector：composer rector 是选择加入的，必须在应用更改之前进行审核
    • 运行时：对 Composer、Symfony、PHPUnit、PHPStan 和 Rector 命令使用 PHP 8.4 或更高版本

    8. 代码风格契约¶

    8.1 PHP¶

    规则 详情
    PHP版本 >= 8.4
    类型声明 严格输入 (declare(strict_types=1))
    物业类型 显式（无仅文档块类型）
    返回类型 尽可能明确
    可空 ?Type 语法
    命名空间 src/ 下的 PSR-4 App\
    使用语句 按字母顺序排列

    8.2 命名¶

    元素 大会 示例
    课程 帕斯卡案例 CategoryService
    方法 驼峰式 getEnabledCategories()
    属性 驼峰式 $serviceClass
    常数 UPPER_SNAKE UNKNOWN_ERROR
    接口 *Interface 后缀 BaseServiceInterface
    抽象类 Abstract* 或 Base* 前缀 BaseService
    性状 *Trait 后缀或描述性 ListApiViewMixin
    测试 *Test 后缀 CategoryTest

    8.3 文件组织¶

    规则 详情
    每个文件一个类 无一例外
    文件名=类名 CategoryService.php 包含 class CategoryService
    特征文件 与特质同名
    接口文件 与接口同名

    9. 事件系统合约¶

    9.1 学说生命周期事件¶

    活动 监听器模式 示例
    prePersist 实体生命周期回调 touch() 用于时间戳
    postLoad 实体侦听器或订阅者 导出场计算
    onFlush 事件订阅者 审计日志

    9.2 Symfony 内核事件¶

    活动 听众 目的
    kernel.exception ExceptionInterceptor 全局 API 错误到 JSON 的转换
    kernel.controller ControllerListener PUT/POST

    9.3 工作流程事件¶

    活动 订阅者 目的
    workflow.{name}.transition OrderWorkflowListener 转换后操作（设置时间戳）

    9.4 自定义事件（可选）¶

    通过 Symfony EventDispatcher 调度自定义事件以实现解耦的跨模块通信：

    • src/{Module}/Event/中的事件类
    • src/{Module}/EventListener/ 中的听众/订阅者

    10. CLI 命令合约¶

    10.1 命令结构¶

    #[AsCommand(name: 'app:module:action', description: '...')]
class XxxCommand extends Command
{
    // Inject services via constructor
    protected function execute(InputInterface $input, OutputInterface $output): int
    {
        return Command::SUCCESS;
    }
}

    10.2 命名约定¶

    app:{module}:{entity}:{action}

    命令 模块 目的
    app:identity:user:create 身份 从 CLI 创建用户
    fission:expire 彩票 过期任务

    10.3 命令要求¶

    • 必须通过 #[AsCommand] 属性注册
    • 必须优雅地处理错误（没有未捕获的异常）
    • 必须输出长时间运行的操作的进度
    • 必须返回Command::SUCCESS或Command::FAILURE

    11. 部署和 CI 合同¶

    11.1 CI 管道¶

    文件：.github/workflows/ci.yml

    步骤 行动
    1 设置 PHP 8.4
    2 安装依赖项 (composer install)
    3 使用独立的 SQLite URL 运行 PHPStan Level 8
    4 使用隔离的 SQLite URL 运行 Rector type-rule dry-run
    5 启动PostgreSQL服务并准备测试数据库
    6 运行具有覆盖率的 PHPUnit 并强制执行最低 90% 的行覆盖率

    11.2 码头工人¶

    • compose.yaml：MySQL 8
    • compose.override.yaml：端口映射+Mailpit
    • 在应用程序启动之前对所有服务进行健康检查

    11.3 环境¶

    环境 APP_ENV APP_DEBUG 数据库
    生产 prod false MySQL
    分期 staging false MySQL
    发展 dev true MySQL（Docker）
    测试 test true SQLite

    12. 重大变更政策¶

    改变 允许 需要
    添加新的 mixin 特征 是的 文档
    添加新的钩子方法 是（使用默认实现） 文档
    更改钩子方法签名 不 主要版本碰撞
    删除 mixin 方法 不 主要版本碰撞
    更改回复信封格式 不 主要版本碰撞
    添加查询参数 是的 向后兼容
    删除支持的查询参数 不 弃用通知 + 主要版本更新
    更改 BaseServiceInterface 不 跨模块影响评估
    添加新模块 是的 遵循模块合同

    13. 文件合同¶

    13.1 每个模块所需的文档¶

    文件 地点 内容
    设计文档 docs/design/{module}.md 业务流程、API设计、数据模型草图
    API使用指南 docs/api/{module}-api.md 端点列表、curl 示例、身份验证
    OpenAPI 规范 代码属性 #[OA\*] 自动生成于 /api/doc

    13.2 代码文档规则¶

    • 关于接口和抽象方法的 PHPDoc（合约文档）
    • 对自记录代码没有评论（命名良好的方法/变量）
    • @deprecated 已弃用功能的注释以及迁移说明
