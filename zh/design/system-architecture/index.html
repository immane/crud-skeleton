    系统架构合约¶

    抽象架构规则、层边界和依赖方向。 所有模块、服务和控制器必须遵守本合同。

    1. 层架构¶

    flowchart TD
    A["Request/Response"] --> B["HTTP Layer<br/>(Controllers / View Mixins)<br/>Only layer touching Request/Response"]
    B -->|"(Service Interface only)"| C["Service Layer<br/>All business logic, transactions, validation"]
    C -->|"(Repository only)"| D["Repository Layer<br/>Data access queries (Doctrine repositories)"]
    D -->|"(Entities only)"| E["Entity Layer (Domain Model)<br/>Pure data objects, no business logic"]
    E -->|"(Doctrine ORM)"| F["Infrastructure (ORM, Cache, Serializer)<br/>Framework-provided"]

    1.1 层依赖规则¶

    规则 来自 至 允许
    R1 控制器 服务 是
    R2 控制器 实体 是（仅键入提示/返回）
    R3 控制器 存储库 否 -- 通过服务
    R4 控制器 实体管理器 否 -- 通过服务
    R5 服务 存储库 是
    R6 服务 实体 是
    R7 服务 实体管理器 是
    R8 服务 其他服务 是（通过 DI）
    R9 实体 存储库 不
    R10 实体 服务 不
    R11 实体 实体管理器 不

    2. 垂直切片（模块）结构¶

    每个业务域都是src/下的一个独立模块：

    src/{Module}/
|-- Controller/
|   |-- App/              # Public/read-only endpoints
|   |-- Manage/           # Admin CRUD endpoints
|-- Entity/               # Domain entities (Doctrine)
|-- Repository/           # Data access (ServiceEntityRepository)
|-- Service/              # Business logic (extends BaseService)
|-- Exception/            # Module-specific exceptions
|-- EventListener/        # Module-specific event subscribers
|-- Command/              # CLI commands
|-- Resources/config/     # Module-specific DI configuration

    2.1 每个模块的强制工件¶

    神器 要求
    实体类 PHP 8 属性（Doctrine ORM），整数自增 id
    存储库类 扩展 ServiceEntityRepository
    服务类别 扩展 BaseService，实现 {Name}ServiceInterface
    服务接口 扩展BaseServiceInterface（可以为空）
    应用程序控制器 只读公共端点
    管理控制器 由 ROLE_ADMIN

    3.跨模块通信合约¶

    3.1 允许¶

    来自 至 机制
    任何业务模块 核心 DI（autowire 核心服务）
    业务模块A 业务模块B DI（自动装配B的服务接口）
    任何模块 身份 DI（当前用户的TokenStorage）

    3.2 禁止¶

    图案 原因
    直接跨模块实体访问 使用服务接口
    直接跨模块存储库访问 使用服务接口
    循环模块依赖 违反层架构
    核心导入业务模块 核心是基础

    3.3 模块接口合约¶

    • 每个模块导出服务接口（例如，CategoryServiceInterface）
    • 其他模块仅使用那些接口，从不具体实现
    • 通过services.yaml自动发现接口

    3.4 跨境身份合约¶

    模块和未来的服务不得将本地自动增量数据库 ID 交换为 持久的参考。每个跨界聚合公开一个 UUID 或另一个明确的 记录不可变的业务密钥。

    背景 使用的标识符
    一个模块内的本地学说关系 允许使用整数 id
    公共 API 路由/响应 UUID
    跨模块边界的服务接口 UUID 或记录的不可变业务密钥
    集成事件聚合/源/相关 ID UUID
    未来服务数据库关系 仅 UUID/业务密钥；没有跨服FK

    事件仅携带标量快照和外部身份。它不得携带 Doctrine 实体、存储库、EntityManager 或本地主键作为持久的 参考。 UUID 查找不授予访问权限；接收模块仍然强制执行其 自己的授权和所有权规则。

    4. 核心框架（src/Core/）¶

    Core 提供了基础抽象。它不能依赖于任何业务模块。

    4.1 核心导出（公共 API）¶

    出口 类型 消费者
    RestController 抽象类 所有控制器
    BaseService 抽象类 所有服务
    BaseServiceInterface 接口 所有服务接口
    ExpressionDqlParser 服务 动态查询编译
    FlatNormalizer 串行器标准化器 串行器管道
    ExceptionInterceptor 事件监听器 全局API错误处理
    查看混入 PHP 特性 所有控制器模板
    实用类 静态助手 任何地方

    4.2 核心约束¶

    • 不得引用任何业务模块名称空间
    • 不得包含特定于域的业务规则
    • 扩展点通过覆盖钩子提供（不是修改）

    5. 依赖注入合约¶

    5.1 自动装配¶

    • 默认情况下自动装配所有 src/ 类 (config/services.yaml App\)
    • 显式排除（在 services.yaml 中手动连接）：
    • 装饰器（例如，FlatNormalizer装饰serializer.normalizer.object）
    • 安全组件（JwtAuthenticator、TokenManager）
    • SMS/OTP 基础设施适配器
    • 事件监听器（用于排序）

    5.2 控制器的 Setter 注入¶

    扩展 RestController 的控制器通过 #[Required] 接收这些：

    依赖 方法
    RequestStack setRequestStack()
    SerializerInterface setSerializer()
    TranslatorInterface setTranslator()

    5.3 服务定位器¶

    服务使用 ServiceLocatorInterface （生产：DefaultServiceLocator 包装 ContainerInterface；测试：mock）来延迟访问： - EntityManager、记录器、TokenStorage、RequestStack、序列化器、验证器

    5.4 标记服务合同¶

    实现管道接口的服务会被自动标记：

    services:
  App\Trade\Service\Pricing\:
    resource: '../src/Trade/Service/Pricing/'
    tags: ['trade.price_calculator']

    通过getPriority(): int方法排序，按优先级顺序执行。

    6. 请求生命周期¶

    Request
  -> public/index.php
  -> App\Kernel (MicroKernelTrait)
  -> config/routes.yaml (prefix routing + namespace scan)
  -> Security firewall (JwtAuthenticator intercepts ^/api)
  -> Controller action (mixin method)
  -> Service method (business logic)
  -> Doctrine EntityManager (persistence)
  -> RestController::success()/warning() (JSON response)

    6.1 路线注册¶

    范围 机制
    身份路由 (/api/auth/*) 控制器上的直接 #[Route] 属性
    业务 API 路由 (/api/v1/*) config/routes.yaml 前缀 + 命名空间扫描
    API 文档 (/api/doc) NelmioApiDocBundle 路由配置

    6.2 安全管道¶

    路线模式 安全
    /api/doc、/api/doc.json 公共访问
    /api/auth/login、/api/auth/otp/*、/api/auth/token/refresh、/api/auth/logout 公共访问
    /api/v1/manage/* 角色管理员
    /api/* IS_AUTHENTICATED_FULLY

    7. 环境合同¶

    文件 范围 必须包含
    .env 默认值（所有环境） APP_ENV、APP_DEBUG、KERNEL_CLASS
    .env.test 测试 DATABASE_URL (SQLite)，测试模式切换
    .env.example 模板（已提交） 所有可用的环境变量及文档
    .env.local 本地覆盖（gitignored） 开发人员特定值

    解析顺序：.env -> .env.{env} -> .env.local -> .env.{env}.local

    8. 基础设施合同¶

    8.1 数据库¶

    环境 数据库 配置
    生产 MySQL 8 DATABASE_URL 环境变量
    测试 SQLite var/test.db
    发展 MySQL（Docker） compose.yaml

    8.2 迁移¶

    • migrations/下的学说迁移
    • 每次迁移一次添加/更改一个模块的表
    • 文件命名：Version{YYYYMMDD}{HHMMSS}.php
    • 模式必须进行版本控制——无需手动更改数据库

    8.3 缓存¶

    缓存 后端 目的
    cache.app 文件系统/Redis 应用程序缓存
    PSR-16（表达式缓存） Symfony 缓存适配器 编译的DQL表达式缓存
    智威汤逊黑名单 Symfony 缓存（基于 TTL） 撤销访问令牌 JTI

    8.4 序列化器¶

    • 默认规范化器：FlatNormalizer（装饰ObjectNormalizer）
    • 循环引用处理程序：返回实体ID或spl_object_hash
    • max_depth + enable_max_depth + 用于深度控制的序列化器组
    • 日期/日期时间：自定义 DateTimeNormalizer
