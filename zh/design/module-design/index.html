    模块设计合同¶

    创建新业务模块的规则。 src/下的每个模块都必须遵循这个结构和契约。 这是使用新域扩展系统的蓝图。

    1. 模块骨架¶

    创建新的业务模块{Module}时：

    src/{Module}/
|-- Controller/
|   |-- App/{Entity}Controller.php         # Public read endpoints
|   |-- Manage/{Entity}Controller.php      # Admin CRUD endpoints
|-- Entity/{Entity}.php                    # Doctrine entity
|-- Repository/{Entity}Repository.php      # Data access
|-- Service/{Entity}Service.php            # Business logic
|-- Service/{Entity}ServiceInterface.php   # Service contract
|-- Exception/                             # Module-specific exceptions (optional)
|-- EventListener/                         # Event subscribers (optional)
|-- Command/                               # CLI commands (optional)
|-- Resources/config/                      # DI and routing (optional)

    2. 文件级合约¶

    2.1 实体合约¶

    • 位置：src/{Module}/Entity/{Name}.php
    • 命名空间：App\{Module}\Entity
    • 必须：实现 __toString()，声明 touch() 生命周期钩子，使用 PHP 8 属性
    • 必须：遵循Data Model Design Contract
    • 不得：包含业务逻辑、DI 或服务引用

    2.2 存储库合约¶

    • 位置：src/{Module}/Repository/{Name}Repository.php
    • 命名空间：App\{Module}\Repository
    • 必须：扩展ServiceEntityRepository
    • 必须：在构造函数中接受 ManagerRegistry
    • 五月：添加返回实体/数组/标量的自定义查询方法
    • 不能：返回原始 QueryBuilder （这是服务层关心的问题）
    • 五月：如果被其他模块使用，则声明 {Name}RepositoryInterface

    2.3 服务接口契约¶

    • 位置：src/{Module}/Service/{Name}ServiceInterface.php
    • 命名空间：App\{Module}\Service
    • 必须：扩展 App\Core\Service\BaseServiceInterface
    • 可能：为空（如果基本接口涵盖所有需要的方法）
    • 可能：添加特定于模块的方法签名
    interface CategoryServiceInterface extends BaseServiceInterface
{
    // Module-specific methods go here (optional)
}

    2.4 服务实施合同¶

    • 位置：src/{Module}/Service/{Name}Service.php
    • 命名空间：App\{Module}\Service
    • 必须：扩展App\Core\Service\BaseService
    • 必须：实施 {Name}ServiceInterface
    • 必须：接受 ContainerInterface、实体类 FQCN、可选定位器/表达式服务
    • 应该：包含所有业务逻辑、验证和事务管理
    • 不得：直接访问请求（使用 getCurrentRequest()）
    • 不得：返回原始 HTTP 响应（这是控制器的工作）
    class CategoryService extends BaseService implements CategoryServiceInterface
{
    public function __construct(
        ContainerInterface $container,
        ?ServiceLocatorInterface $locator = null,
        ?ExpressionServiceInterface $expressionService = null,
        ?LegacyEvaluator $legacyEvaluator = null
    ) {
        parent::__construct(
            $container,
            Category::class,
            $locator,
            $expressionService,
            $legacyEvaluator
        );
    }
}

    2.5 控制者合约¶

    控制器有两个角色。有关完整详细信息，请参阅Controller Design Contract。

    应用程序控制器（公共只读）¶

    • 位置：src/{Module}/Controller/App/{Name}Controller.php
    • 命名空间：App\{Module}\Controller\App
    • 必须：扩展 RestController
    • 必须：使用 ApiView、DetailApiViewMixin、ListApiViewMixin 特征
    • 必须：设置 $serviceClass 属性
    • 应该：覆盖commonFilter()以范围数据（例如，enabled = true）
    • 不得：创建、更新或删除实体

    管理控制器（管理员 CRUD）¶

    • 位置：src/{Module}/Controller/Manage/{Name}Controller.php
    • 命名空间：App\{Module}\Controller\Manage
    • 必须：扩展 RestController
    • 必须：使用 ApiView、ListApiViewMixin、DetailApiViewMixin、CreateApiViewMixin、UpdateApiViewMixin、DeleteApiViewMixin 特征
    • 必须：设置 $serviceClass 属性
    • 必须：在课堂上使用 #[IsGranted('ROLE_ADMIN')] 进行防护
    • 应该：声明 $requiredCreateProperties、$acceptedCreateProperties、$acceptedUpdateProperties
    • 可能：覆盖自定义逻辑的钩子方法

    3. 模块注册合约¶

    3.1 路由注册¶

    将模块的控制器添加到 config/routes.yaml：

    api_{module}_app:
  resource:
    path: '../src/{Module}/Controller/App/'
    namespace: App\{Module}\Controller\App
  prefix: /api/v1
  type: attribute

api_{module}_manage:
  resource:
    path: '../src/{Module}/Controller/Manage/'
    namespace: App\{Module}\Controller\Manage
  prefix: /api/v1
  type: attribute

    3.2 DI 注册¶

    如果模块需要自定义服务配置，则创建：

    # src/{Module}/Resources/config/services_{module}.yaml
services:
  _defaults:
    autowire: true
    autoconfigure: true
  App\{Module}\:
    resource: '../../'
    exclude: '../../{Entity,Exception,Resources}'

    在 config/services.yaml 中导入： 

    imports:
  - { resource: '../src/{Module}/Resources/config/services_{module}.yaml' }

    否则，自动装配将通过全局 App\ 资源覆盖所有内容。

    3.3 迁移¶

    在 migrations/ 中为每个模块创建单个迁移：

    php bin/console make:migration

    命名约定：Version{YYYYMMDD}{HHMMSS}.php

    4. 模块依赖规则¶

    4.1 允许的依赖关系¶

    模块 可能取决于
    任何业务模块 核心（始终），其他业务模块（通过服务接口）
    身份 核心
    核心 什么都没有（基础）

    4.2 模块隔离检查表¶

    创建新模块时，验证：

    • [ ] 模块与其他模块没有循环依赖关系
    • [ ] 模块导出至少一个*ServiceInterface
    • [ ] 模块不从其他模块导入具体服务（使用接口）
    • [ ] 模块的实体不被其他模块中的控制器直接引用
    • [ ] 模块的服务是独立的（不泄漏 DB 连接或 EM）

    5. 模块测试合同¶

    每个模块必须具有：

    测试套件 地点 覆盖目标
    实体单元测试 tests/{Module}/Entity/ __toString()、getter/setter、生命周期
    服务测试 tests/{Module}/Service/ 所有公共服务方式
    集成测试 tests/{Module}/Integration/ API端点，完整的请求/响应周期

    5.1 测试基类¶

    测试类型 延伸 目的
    单元测试 PHPUnit\Framework\TestCase 纯逻辑测试
    内核测试 IntegrationKernelTestCase 启动内核后，数据库访问
    网页测试 IntegrationWebTestCase 完整的 HTTP 请求/响应

    5.2 测试数据库¶

    • 测试环境使用SQLite (var/test.db)
    • 模式是根据测试引导中的 Doctrine 迁移创建的
    • 每个测试方法都包装在一个事务中并回滚

    6. 例外合同¶

    特定于模块的异常必须：

    • 扩展：\RuntimeException 或 \Exception
    • 命名：描述性（InsufficientFundsException、OrderInvalidTransitionException）
    • 被抛出：在服务层（绝不在控制器或实体中）
    • 被捕获：在控制器层（通过 mixin try/catch 块）
    • 记录：通过 ExceptionInterceptor 获取 /api/* 路由上未处理的异常

    6.1 异常响应映射¶

    ExceptionInterceptor 捕获的未处理异常返回：

    {
  "code": "{status_code}",
  "message": "{exception_message}",
  "data": {
    "class": "{exception_class}"
  }
}

    7. 配置合约¶

    特定于模块的配置（如果需要超出环境变量）：

    • 位置：config/packages/{module}.yaml 或 src/{Module}/Resources/config/
    • 环境覆盖：通过 YAML 中的 %env(...)%，而不是硬编码
    • 敏感值：始终通过环境变量，从不在提交的文件中

    8. 模块清单（新模块创建）¶

    添加新业务域时，请按顺序完成以下步骤：

    1.设计实体（首先是YAML或草图，然后是PHP类） 2.创建Doctrine迁移 3. 实施存储库 4. 实现服务接口+服务类 5. 实现应用程序控制器（只读） 6. 实施管理控制器（CRUD） 7、在config/routes.yaml中注册路由 8. 为所有端点添加 OpenAPI #[OA\*] 属性 9. 编写实体单元测试 10. 编写服务单元测试 11.编写API集成测试 12. 验证 CI 通过（最低覆盖率 90%）
