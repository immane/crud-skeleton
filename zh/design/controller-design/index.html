    控制器设计合约¶

    控制器层遵循 组合优于继承 模式，使用 PHP 特征作为“混合”契约。 这与 farm-neighbor (src/LamProject/CoreBundle/View/) 使用的合约完全相同。 控制器通过 use-ing 特征而不是通过深层类层次结构来组合行为（列表、详细信息、创建、更新、删除、工作流）。

    1. 核心原理¶

    Controller = RestController (base)
           + ApiView (service binding + common filter)
           + [ListApiViewMixin | DetailApiViewMixin | CreateApiViewMixin | ...]
           + Business-specific hook overrides

    每个控制器都是通过组装特征来构建的，而不是通过扩展单一的 CRUD 基类来构建。

    2. Trait Catalog（控制器合约工具包）¶

    2.1 强制：ApiView¶

    文件：src/Core/View/ApiView.php 必须由使用：每个控制器

    声明服务绑定和数据范围的契约：

    trait ApiView
{
    protected ?string $serviceClass = null;  // REQUIRED: set in controller

    protected function commonFilter()         // OVERRIDE: scope data
    {
        return [];  // return array criteria OR QueryBuilder
    }
}

    合同： - 控制器必须将 $serviceClass 设置为相应服务的 FQCN - 控制器应该覆盖 commonFilter() 以应用所有权/范围过滤器 - commonFilter() 返回：(a) 标准关联数组，或 (b) QueryBuilder 实例

    2.2 列表：ListApiViewMixin¶

    文件：src/Core/View/ListApiViewMixin.php

    注册 GET / 并提供分页列表端点：

    路线 方法 行动
    GET / 列表动作 具有动态查询的分页集合

    挂钩方法（可重写）：

    钩 签名 当被呼叫时 目的
    listFilter($filter) protected 在 service.list() 之前修改过滤条件
    listProcessor($entities) protected 在 service.list() 之后转换结果集
    listResponses($entities) protected JSON 序列化之前 最终反应塑造

    OpenAPI 参数（已记录）： page、limit、@order、@dql、@select、@groupBy、@hints、@filter、@sort、@expands、@display、@showDQL

    2.3 详细信息：DetailApiViewMixin¶

    文件：src/Core/View/DetailApiViewMixin.php

    寄存器GET /{id}（需要数字ID）：

    路线 方法 行动
    GET /{id} 详细动作 按 ID 的单个实体

    挂钩方法：

    钩 签名 当被呼叫时 目的
    detailFilter($filter) protected 在 mixIdToCommonFilter 之后，在 get 之前修改查找条件
    detailProcessor($entity) protected 在 service.get() 之后 改造实体
    detailResponse($entity) protected JSON 序列化之前 塑造反应

    2.4 创建：CreateApiViewMixin¶

    文件：src/Core/View/CreateApiViewMixin.php

    注册 POST / 以支持单个对象和数组输入：

    路线 方法 行动
    POST / 创建动作 创建单个或批量实体

    查询参数：@partial（非事务性）、@transform（表达式转换器）

    属性 控制器可以声明：

    物业 类型 目的
    $requiredCreateProperties string[] 输入中必须出现的字段
    $acceptedCreateProperties string[] 输入

    挂钩方法：

    钩 签名 当被呼叫时 目的
    defaultCreateValues() protected 加工前 提供默认值
    processCreateContent(array $content, $entity) protected 变换后、保存前 修改/验证内容
    processEntity($content, $entity) protected new() 之后，更新之前 修改新实体
    afterCreated($entity) protected 保存成功后 创建后挂钩

    输入模式： - 单个对象{}：直接返回创建的实体 - 数组[{}, {}, ...]：返回已创建实体的数组，包装在事务中（除非@partial=true）

    2.5 更新：UpdateApiViewMixin¶

    文件：src/Core/View/UpdateApiViewMixin.php

    注册两条路由：

    路线 方法 行动
    PUT /{id} 更新操作 单一实体更新
    POST /batch-update 批量更新操作 批量更新插入（创建或更新）

    查询参数：@mode=mixed|strict、@basis=field1,field2、@partial、@transform

    属性 控制器可以声明：

    物业 类型 目的
    $requiredUpdateProperties string[] 更新输入中必须存在的字段
    $acceptedUpdateProperties string[] 更新输入中可能存在的字段

    挂钩方法（更新路径）：

    钩 签名 当被呼叫时 目的
    defaultUpdateValues() protected 加工前 提供更新的默认值
    processUpdateContent(array $content, $entity) protected 变换后、保存前 修改/验证更新内容
    afterUpdated($entity) protected 保存成功后 更新后挂钩

    兼容性挂钩（默认情况下委托更新挂钩 - 仅在需要时覆盖）：

    钩 默认代表
    defaultValues() 如果没有特定的覆盖，则由创建和更新使用
    processContent($content, $entity) 如果没有特定的覆盖，则由创建和更新使用
    after($entity) 如果没有特定的覆盖，则由创建和更新使用

    批量更新插入逻辑（POST /batch-update 和 @mode=mixed）： 1. 对于数组中的每个项目，尝试通过 @basis 字段查找现有实体 2. 如果找到：update() (MODE_UPDATE) 3. 如果没有找到：new() + update() (MODE_CREATE) 4. 使用@mode=strict：跳过不存在的项目（仅更新）

    2.6 删除：DeleteApiViewMixin¶

    文件：src/Core/View/DeleteApiViewMixin.php

    寄存器DELETE /{id}：

    路线 方法 行动
    DELETE /{id} 删除操作 删除实体

    挂钩方法：

    钩 签名 当被呼叫时 目的
    deletionFilter($filter) protected 查找前 添加范围以防止未经授权的删除

    2.7 单例：SingleCreateAndUpdateApiViewMixin¶

    文件：src/Core/View/SingleCreateAndUpdateApiViewMixin.php

    对于每个范围只有一行的资源（例如，用户设置）：

    路线 方法 行动
    PUT / 更新操作 获取或创建单例，然后更新

    挂钩方法：defaultCreateValues()、defaultUpdateValues()

    2.8 单例详细信息：SingleDetailApiViewMixin¶

    文件：src/Core/View/SingleDetailApiViewMixin.php

    路线 方法 行动
    GET / 详细动作 获取单个资源（无 ID）

    使用 commonFilter() 来标识哪一行。

    2.9 工作流程：WorkflowApiViewMixin¶

    文件：src/Core/View/WorkflowApiViewMixin.php

    对于 Symfony Workflow 状态机管理的实体：

    路线 方法 行动
    GET /todo 待办事项行动 列出具有可用转换的实体
    GET /{id}/transitions 可用的TransitionsAction 获取实体的启用转换
    POST /{id}/do/{transition} 执行转换操作 执行工作流程转换
    PUT /{id}/status-reset 重置标记操作 重置状态机标记（仅限管理员）

    属性控制器必须声明： - protected $workflow; -- 工作流服务 ID（例如 'state_machine.order'）

    3. 控制器组装模式¶

    3.1 标准管理 CRUD 控制器¶

    #[IsGranted('ROLE_ADMIN')]
class CategoryController extends RestController
{
    use ApiView;
    use ListApiViewMixin;
    use DetailApiViewMixin;
    use CreateApiViewMixin;
    use UpdateApiViewMixin;
    use DeleteApiViewMixin;

    protected ?string $serviceClass = CategoryService::class;

    protected array $requiredCreateProperties = ['name'];
    protected array $acceptedCreateProperties = ['name', 'slug', 'description', 'parent', 'enabled'];
    protected array $acceptedUpdateProperties = ['name', 'slug', 'description', 'parent', 'enabled', 'sortOrder'];
}

    3.2 公共只读控制器¶

    class CategoryController extends RestController
{
    use ApiView;
    use ListApiViewMixin;
    use DetailApiViewMixin;

    protected ?string $serviceClass = CategoryService::class;

    protected function commonFilter()
    {
        return ['enabled' => true];  // Only show enabled categories
    }
}

    3.3 自定义业务逻辑控制器（超越 CRUD）¶

    当控制器需要 mixins 未涵盖的端点时，请添加自定义操作方法：

    class OrderController extends RestController
{
    use ApiView;
    use ListApiViewMixin;
    use DetailApiViewMixin;

    protected ?string $serviceClass = OrderService::class;

    #[Route('/my-orders', name: 'my-orders', methods: ['GET'])]
    public function myOrdersAction(): Response
    {
        $service = $this->get($this->serviceClass);
        $filter = $this->commonFilter();  // scopes to current user
        $entities = $service->list($filter);
        return $this->success($entities);
    }
}

    3.4 支持工作流的控制器¶

    #[IsGranted('ROLE_ADMIN')]
class OrderController extends RestController
{
    use ApiView;
    use ListApiViewMixin;
    use DetailApiViewMixin;
    use UpdateApiViewMixin;           // For updating draft orders
    use WorkflowApiViewMixin;         // For state transitions

    protected ?string $serviceClass = OrderService::class;
    protected $workflow = 'state_machine.order';

    protected array $acceptedUpdateProperties = ['notes', 'metadata'];
}

    4.Hook执行顺序¶

    4.1 获取列表管道¶

    commonFilter()
  -> listFilter()
    -> service.list(filter)
      -> listProcessor(entities)
        -> listResponses(entities)
          -> success(response)

    4.2 获取详细信息管道¶

    commonFilter()
  -> mixIdToCommonFilter(id)
    -> detailFilter(filter)
      -> service.get(filter)
        -> detailProcessor(entity)
          -> detailResponse(entity)
            -> success(response)

    4.3 POST 创建管道¶

    json_decode(content)
  -> check input type (object vs array)
    -> service.new()
      -> requiredCreateProperties check
        -> acceptedCreateProperties filter
          -> defaultCreateValues()
            -> @transform (expression)
              -> processCreateContent(content, entity)
                -> processEntity(content, entity)
                  -> service.update(entity, content)
                    -> afterCreated(entity)
                      -> success(response)

    4.4 PUT 更新管道¶

    json_decode(content)
  -> mixIdToCommonFilter(id)
    -> service.get(filter)
      -> requiredUpdateProperties check
        -> acceptedUpdateProperties filter
          -> defaultUpdateValues()
            -> @transform (expression)
              -> processUpdateContent(content, entity)
                -> service.update(entity, content)
                  -> afterUpdated(entity)
                    -> success(response)

    4.5 删除管道¶

    mixIdToCommonFilter(id)
  -> deletionFilter(filter)
    -> service.get(filter)
      -> service.remove(entity)
        -> success(...) | warning(...)

    5. 合约规则¶

    5.1 必须规则¶

    ＃ 规则
    R1 控制器必须扩展 RestController
    R2 控制器必须 use ApiView 特征
    R3 控制器必须设置 protected ?string $serviceClass
    R4 应用程序（公共）控制器不得使用创建/更新/删除混合
    R5 管理（admin）控制器必须由 #[IsGranted('ROLE_ADMIN')]
    R6 管理 CRUD 控制器必须声明 $requiredCreateProperties 和 $acceptedCreateProperties
    R7 每个公共操作都必须具有 #[OA\*] OpenAPI 属性
    R8 控制器不得直接调用 EntityManager
    R9 控制器不得直接调用存储库
    R10 所有业务逻辑必须经过服务层

    5.2 应该规则¶

    ＃ 规则
    S1 应用程序控制器应该覆盖 commonFilter() 以范围数据
    S2 自定义验证应该放在 processCreateContent() / processUpdateContent() 挂钩中
    S3 保存后副作用应该进入 afterCreated() / afterUpdated() 钩子
    S4 删除应通过 deletionFilter() 或 commonFilter() 验证所有权

    5.3 不得制定规则¶

    ＃ 规则
    N1 不得将 EntityManager 注入控制器
    氮气 不得将业务逻辑放入钩子方法中（委托给服务）
    N3 不得绕过标准 CRUD 操作的 serviceClass 绑定
    N4 不得使用 $_GET、$_POST、$_REQUEST 超全局变量（使用 Request 对象）
    N5 不得修改 mixin 特征文件以满足特定于模块的需求（而是覆盖钩子）

    6. 与农场邻居的比较¶

    该合同与农场邻居的合同结构相同：

    方面 农场邻居 粗骨架
    基类 LamProject\CoreBundle\Controller\RestController App\Core\Controller\RestController
    混音地点 LamProject\CoreBundle\View\ App\Core\View\
    性状名称 相同（ListApiViewMixin、CreateApiViewMixin 等） 相同的名字
    钩子方法签名 相同 相同
    服务绑定 $serviceClass $serviceClass
    字段白名单 $requiredCreateProperties等 相同
    @ 查询语法 相同的表达引擎 相同
    混合批量更新插入 @mode=mixed + @basis 相同

    差异很小（命名空间、Symfony 版本 3.4→8.1、注释→属性），但合约语义是相同的。
