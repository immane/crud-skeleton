    API设计合约¶

    统一响应格式、URL 约定、HTTP 方法语义、身份验证、分页和查询参数。 每个 API 端点必须遵守此合同。

    1.统一响应包络¶

    每个 API 响应都将数据包装在标准化信封中：

    {
  "data": {},
  "code": 200,
  "message": "SUCCESS",
  "paginator": {}
}

    1.1 字段¶

    领域 类型 当存在时 描述
    data 任何 永远 响应负载（对象、数组、空值或标量）
    code 整数 永远 HTTP 状态代码（镜像响应状态）
    message 字符串 永远 人类可读的状态（成功）或错误描述（警告）
    paginator 对象 分页时 分页元数据（当前页、总页数、总项目数、每页）

    1.2 成功响应¶

    由 RestController::success($data, $message, $status) 生成：

    {
  "data": { "id": 1, "title": "..." },
  "code": 200,
  "message": "SUCCESS"
}
    场景 状态 留言
    获取列表/详细信息 200 200 “成功”
    发布创建 201 201 “成功”
    放置更新 200 200 “成功”
    删除 删除 204 204 “成功”

    1.3 错误响应¶

    由 RestController::warning($error_msg, $error_code, $raw_data, $status) 生成：

    {
  "code": 400,
  "message": "Validation failed: email is required",
  "data": ""
}
    场景 状态
    验证错误 400
    没有找到 404
    认证失败 401
    授权失败 403
    服务器错误 500

    1.4 分页器对象¶

    {
  "paginator": {
    "page": 1,
    "limit": 20,
    "pages": 5,
    "total": 100
  }
}

    2. URL 约定¶

    2.1 基本前缀¶

    范围 前缀
    认证 /api/auth
    业务 API（公共） /api/v1/app
    业务 API（管理员） /api/v1/manage
    文档 /api/doc

    2.2 资源命名¶

    大会 示例 理由
    小写，连字符 /api/v1/manage/order-items 可读的网址
    复数名词 /categories 不是 /category 一致的休息
    没有尾部斜杠 /categories/{id} 干净的网址
    基本 URL 中没有动词 通过 POST /categories 创建 HTTP 方法语义
    路径中的 ID /{id} 其中 id 是 \d+ 直接资源访问
    子资源 /orders/{id}/items 关系范围

    2.3 特殊路由（非CRUD）¶

    运营 URL 模式 示例
    批量更新插入 POST /{resource}/batch-update POST /categories/batch-update
    工作流程待办事项 GET /{resource}/todo GET /orders/todo
    工作流程转换 GET /{resource}/{id}/transitions GET /orders/5/transitions
    工作流程执行 POST /{resource}/{id}/do/{transition} POST /orders/5/do/confirm
    工作流程重置 PUT /{resource}/{id}/status-reset PUT /orders/5/status-reset

    3. HTTP 方法语义¶

    方法 增删改查 幂等 身体 路径 ID
    获取 阅读（合集） 是的 没有 没有
    获取 阅读（详细） 是的 没有 是的
    发布 创建 没有 是的 没有
    放置 更新（完全替换） 是的 是的 是的
    删除 删除 是的 没有 是的

    3.1 岗位专业化¶

    变体 路径 身体 目的
    创建单 POST / {} 单一实体创建
    创建批次 POST / [{}, {}, ...] 一笔交易中的多个实体
    批量更新插入 POST /batch-update [{}, {}, ...] 与 @basis + @mode=mixed 幂等批量同步
    单例更新插入 PUT / {} 单行资源（获取或创建）

    4. 身份验证¶

    4.1 令牌格式¶

    Authorization: Bearer {access_token}
    • 访问令牌：RS256 JWT、7200s TTL（默认）
    • 刷新令牌：不透明的 HMAC-SHA256 哈希，存储在服务器端，1 年 TTL

    4.2 公共端点（无需身份验证）¶

    端点 方法
    /api/auth/login 发布
    /api/auth/otp/request 发布
    /api/auth/otp/verify 发布
    /api/auth/token/refresh 发布
    /api/auth/logout 发布
    /api/doc、/api/doc.json 获取

    4.3 角色层次结构¶

    ROLE_USER
  |-- ROLE_ADMIN
    • Public /api/v1/app/*：不需要角色（可以是只读）
    • 管理员/api/v1/manage/*：需要ROLE_ADMIN

    5.查询参数（动态查询系统）¶

    5.1 列出端点参数(GET /)¶

    参数 类型 描述
    page 整数 页码（从 1 开始）
    limit 整数 每页项目
    @filter 字符串 基于表达式的 WHERE 条件
    @dql 字符串 原始 DQL WHERE 子条款
    @order 字符串 以逗号分隔 field|ASC 或 field|DESC
    @select 字符串 DQL SELECT 子句覆盖
    @groupBy 字符串 DQL 分组依据
    @hints 字符串 教义查询提示
    @sort 字符串 内存中排序表达式（后备）
    @expands 字符串 逗号分隔的嵌套实体扩展
    @display 字符串 场投影模式（complex、reduce 或表达式）
    @showDQL 布尔 调试模式：返回已编译的 DQL 作为响应

    5.2 创建/更新参数¶

    参数 方法 类型 描述
    @partial 发布、放置 布尔 非事务模式（跳过失败的项目）
    @transform 发布、放置 字符串 基于表达式的字段值转换
    @mode POST（批量更新） 字符串 mixed（更新插入），strict（仅更新）
    @basis POST（批量更新） 字符串 用于 upsert

    5.3 表达式语法 (@filter / @sort / @transform)¶

    操作员 意义 示例
    == 平等 entity.status == "active"
    != 不等于 entity.price != 0
    > 大于 entity.age > 18
    < 小于 entity.price < 100
    >= 大于或等于 entity.count >= 5
    <= 小于或等于 entity.rating <= 4.5
    && 逻辑与 a == 1 && b == 2
    \|\| 逻辑或 a == 1 \|\| b == 2
    ! 逻辑非 !entity.deleted
    matches 文字子字符串或 /regex/flags 匹配 entity.title matches "paper"、entity.title matches "/^paper.*/i"
    链接属性 属性遍历 entity.getCategory().getName()

    普通的 matches 值在编译为 contains 样式的 LIKE 之前会被转义。 正则表达式文字支持 i、m、s 和 x； g 和 u 被接受，但没有 数据库副作用。未知的正则表达式标志被拒绝。

    5.4 表达式函数（在表达式中可用）¶

    命名空间 功能
    Math abs、ceil、floor、round、max、min、add、sub、mul、div、mod、pow、sqrt
    ArrayCommon in_array、count、merge、push、key_exist、filter、map、reduce
    Datetime get($time, $timezone) -- 返回日期时间

    6. 内容类型和请求正文¶

    方向 内容类型
    请求 application/json
    回应 application/json
    • 请求正文必须是有效的 JSON
    • 无效的 JSON 返回 400 { message: "Invalid JSON" }

    7.OpenAPI 文档¶

    • 每个端点必须携带 NelmioApiDocBundle 的 #[OA\*] 属性
    • Swagger UI：/api/doc
    • OpenAPI JSON：/api/doc.json
    • 属性必须包括：方法标签、参数（带类型）、响应模式、请求正文模式

    7.1 每个端点所需的属性¶

    行动 属性
    列表 #[OA\Get] 记录了所有查询参数
    详情 #[OA\Get] 与 @expands 参数
    创建 #[OA\Post] 与 @partial、@transform 参数、请求正文架构
    更新 #[OA\Put] 与 @transform 参数，请求主体架构
    删除 #[OA\Delete] 带有响应描述
    批量更新 #[OA\Post] 与 @mode、@basis、@partial、@transform、请求正文架构
    工作流程 #[OA\Get] / #[OA\Post] / #[OA\Put] 匹配动作

    8. 响应编码规则¶

    8.1 实体序列化¶

    • 循环引用解析为{ "id": N, "__toString": "...", "__metadata": {} }
    • DateTime 字段序列化为 ISO 8601 字符串
    • JSON 字段自动从字符串解析为对象/数组
    • 条令代理/内部字段被剥离

    8.2 字段选择 (@display)¶

    模式 行为
    complex 利用元数据进行深度扩展
    reduce 浅薄，仅ID+toString用于关系
    表达 通过表达式语法自定义字段映射
    （无） 平坦归一化（默认）

    8.3 嵌套扩展 (@expands)¶

    示例：@expands=category,tags

    折叠的实体关系通过 __metadata 扩展为嵌套对象。
