    开始使用¶

    此页面使应用程序运行并向您展示如何验证它的工作原理。 支持两种路径：Docker Compose（推荐，包含所有内容）和 本机 PHP（使用本地安装的 PHP 工具链）。

    先决条件¶

    工具 版本 目的
    Docker 引擎 + Compose v2 最新稳定 运行完整的服务堆栈 (compose.yaml)
    PHP 8.4+（项目约束>=8.4） 本机设置； CLI 需要 pdo_mysql、openssl、zip、intl 扩展
    作曲家 2.x 依赖关系和自动加载管理
    OpenSSL 任何最近的 生成 RSA JWT 密钥对
    MySQL 8 客户端 8.x 可选 — 用于检查容器数据库的本机 mysql CLI

    在装有 Homebrew 的 macOS 上，该项目已针对 PHP 8.5 进行了测试 (/opt/homebrew/opt/php)。 Homebrew 的 PHP 8.4 也可以工作 — 请参阅 Troubleshooting 如果 php 解析为旧版本。

    compose.yaml 中的服务¶

    docker compose up -d --build 启动单个网络堆栈。只有nginx， database、redis和mailer发布主机端口； PHP 容器从来不会这样做。

    服务 图像/构建 目的 主机端口（默认）
    app 从 Dockerfile 构建PHP-FPM 为 Symfony API 提供服务 —
    worker 同一张图片 async 传输的信使消费者 —
    scheduler 同一张图片 循环运行发件箱-发布和预订/结算管家 —
    nginx nginx:alpine PHP-FPM 的反向代理；服务 / → public/ ${APP_PORT:-8080}:80
    database mysql:8.4 主存储（学说） 3306:3306 通过 compose.override.yaml
    redis redis:7-alpine 缓存、OTP 存储、速率限制器支持 —
    mailer axllent/mailpit 电子邮件捕获器（Mailpit UI） ${MAILPIT_UI_PORT:-8025}:8025

    worker 和 scheduler extends: app，因此它们共享相同的图像和环境。 nginx 有一个到 GET /health/ready 的全路径就绪探测。

    Docker 快速入门¶

    # 1. Build images and start every service
docker compose up -d --build

# 2. Apply the latest database schema
docker compose exec app php bin/console doctrine:migrations:migrate --no-interaction

# 3. Create an administrator account (email, screen name, password)
docker compose exec app php bin/console app:identity:user:create admin@example.com admin 'P@ssw0rd' --admin

    这足以登录并使用 API。 JWT密钥对已生成 自动在第一个容器上通过 docker/app/entrypoint.sh 启动 var/jwt/。首次运行不需要环境文件 - compose.yaml 提供安全的开发默认值。

    常用后续命令：

    # Tail app logs
docker compose logs -f app

# Reset the database (dev only)
docker compose exec app php bin/console doctrine:schema:drop --force
docker compose exec app php bin/console doctrine:migrations:migrate --no-interaction

# Stop the stack (keep volumes)
docker compose down

    本机 PHP 设置¶

    可选的 compose.override.yaml 绑定源树并公开 MySQL 和 Mailpit 本地，但您也可以直接在主机上运行所有内容：

    # 1. Install dependencies (Docker is not required for this step)
composer install

# 2. Create your local environment file
cp .env .env.local

    在执行后续步骤之前配置 .env.local：

    APP_ENV=dev
APP_SECRET=your-secret
DATABASE_URL="mysql://app:!ChangeMe!@127.0.0.1:3306/app?serverVersion=8.0&charset=utf8mb4"

JWT_PRIVATE_KEY_PATH=%kernel.project_dir%/var/jwt/jwt_private.pem
JWT_PUBLIC_KEY_PATH=%kernel.project_dir%/var/jwt/jwt_public.pem
JWT_PASSPHRASE=
REFRESH_TOKEN_SECRET=your-refresh-secret

    生成 JWT 密钥对¶

    JWT 身份验证器使用 RS256 签署访问令牌，因此私有/公共 RSA 对 是必需的。在 var/jwt/ (.gitignored) 下创建它：

    mkdir -p var/jwt

# Private key (optionally guarded by a passphrase)
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 \
  -out var/jwt/jwt_private.pem

# Public key derived from the private key
openssl rsa -in var/jwt/jwt_private.pem -pubout -out var/jwt/jwt_public.pem

# Restrict permissions: the private key must not be world-readable
chmod 600 var/jwt/jwt_private.pem

    如果您设置了 JWT_PASSPHRASE，请使用以下命令重新运行私钥生成 -aes256 和（可选）-pass pass:...，并将 JWT_PASSPHRASE 设置为相同 .env.local 中的值。

    创建数据库并运行迁移¶

    php bin/console doctrine:database:create
php bin/console doctrine:migrations:migrate

    提供 API 服务¶

    php -S localhost:8000 -t public/

    APP_ENV=dev中内置的服务器足以满足本地工作；该应用程序也完全 nginx 背后的功能（请参阅 docker/nginx/default.conf 了解生产形态）。

    JWT 环境变量¶

    变量 默认（撰写） 目的
    JWT_PRIVATE_KEY_PATH /var/www/html/var/jwt/jwt_private.pem 用于签署访问令牌的 RSA 私钥 (PEM) 的路径
    JWT_PUBLIC_KEY_PATH /var/www/html/var/jwt/jwt_public.pem 用于验证的 RSA 公钥 (PEM) 的路径
    JWT_PASSPHRASE （空） 保护私钥的可选密码
    REFRESH_TOKEN_SECRET dev-refresh-secret-change-me 用于刷新令牌散列和轮换的 HMAC 秘密
    ACCESS_TOKEN_TTL 7200（秒） 访问令牌生命周期
    REFRESH_TOKEN_TTL 31536000（秒） 刷新令牌生命周期

    相关可选变量：OTP_REDIS_DSN、ALIYUN_*（短信）、WECHAT_* （微信登录/支付）、MAILER_DSN、MESSENGER_TRANSPORT_DSN、INVENTORY_ENABLED。 完整参考请参见.env.example。

    验证设置¶

    # Swagger UI (also available at http://localhost:8000/api/doc natively)
curl -s http://localhost:8080/api/doc | head -c 200

# Health/readiness returns JSON when the app, DB, and Redis are reachable
curl -s http://localhost:8080/health/ready

    登录并捕获令牌：

    curl -s -X POST http://localhost:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@example.com","password":"P@ssw0rd"}'

    使用返回的 token 进行经过身份验证的调用：

    curl -s http://localhost:8080/api/v1/profile \
  -H "Authorization: Bearer <token>"

    故障排除¶

    症状 可能的原因 修复
    Doctrine\DBAL\Exception\DriverException: could not find driver 缺少 pdo_mysql PHP 扩展 检查php -m \| grep -i mysql。在 macOS Homebrew 上：brew install php 捆绑它；确保 /opt/homebrew/opt/php/bin/php 位于 PATH 的第一位
    JWT ... key not found / 401 受保护的路由 JWT 密钥未生成，或路径不匹配 .env.local 运行上面的 openssl 命令并验证 JWT_PRIVATE_KEY_PATH / JWT_PUBLIC_KEY_PATH 是绝对的并指向现有的 PEM 文件
    Permission denied 当应用程序读取私钥时 私钥模式太开放 chmod 600 var/jwt/jwt_private.pem （它被 git 忽略）
    Address already in use: 8080 / 8000 另一个进程占用了端口 docker compose — 设置APP_PORT=8090 docker compose up -d；本机 - 选择另一个端口，例如php -S localhost:8001 -t public/
    php 是 macOS 上的旧版本（例如 7.4） 自制 php 未链接/第一个 运行 /opt/homebrew/opt/php/bin/php bin/console ... 或 PATH="/opt/homebrew/opt/php/bin:$PATH" php ...
    迁移失败并显示 Unknown database 'app' 数据库未创建 docker compose exec app php bin/console doctrine:database:create（本机：在没有 exec 的情况下运行相同的操作）
    邮件未到达 Mailpit 未运行或 DSN 错误 Native：启动Mailpit（docker compose up -d mailer）并使用MAILER_DSN=smtp://127.0.0.1:1025；检查 UI http://localhost:8025
