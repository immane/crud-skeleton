    国际化 (i18n)¶

    该项目使用 Symfony 的翻译组件来处理面向用户的字符串和 通过构建管道自动将文档翻译成中文。 本文档涵盖这两个系统。

    1. 运行时翻译（API 消息）¶

    1.1 配置¶

    config/packages/translation.yaml：

    framework:
    default_locale: zh
    translator:
        default_path: '%kernel.project_dir%/translations'
        providers:
    • 翻译从 translations/ 加载。
    • default_locale 是 zh — 不携带区域设置信号的新请求 解析为简体中文。
    • 消息存储为名为 messages.{locale}.yaml 的 YAML 文件。

    1.2 支持的语言环境¶

    语言环境 文件 语言
    en translations/messages.en.yaml 英语
    zh translations/messages.zh.yaml 中文（简体）
    zh_Hant translations/messages.zh_Hant.yaml 中文（繁体）
    ja translations/messages.ja.yaml 日语

    这四个代码是规范的SUPPORTED_LOCALES src/Core/EventListener/LocaleListener.php。

    1.3 键约定——英文字符串是键¶

    翻译键是原始英文消息字符串本身，而不是 符号ID：

    # translations/messages.en.yaml
"Wallet": "Wallet"
# translations/messages.zh.yaml
"Wallet": "钱包"

    因此 messages.en.yaml 主要是文档 - 它将每个键映射到 本身 - 因为 Symfony 的翻译器会在不存在时退回到返回密钥 找到翻译了。该文件记录了每个可翻译的字符串：

    • 实体名称（Category、Order、Transaction、...）
    • 实体字段名称（Id、Uuid、Name、Slug、camelCase → 纯文本）
    • 错误/状态消息用作异常键

    1.4 翻译发生的地方¶

    框架通过 $translator->trans($key) 在这些处读取消息 点：

    网站 机制
    异常响应 ExceptionInterceptor — /api/* 上的每个未捕获的异常都通过 $this->translator->trans($exception->getMessage()) 路由；异常消息是关键
    控制器错误 RestController::warning()、AuthController::error()、OtpController::error()、LoginController::error()都经过翻译器
    JWT 失败 JwtAuthenticator::onAuthenticationFailure() 在返回 JSON 之前转换错误
    实体元数据 /system/entities/{entityName} 翻译字段描述（例如 createdAt → 创建时间）

    因此，呈现了抛出 new \RuntimeException('Insufficient funds') 的服务 如果 "Insufficient funds" 存在于相应的请求语言环境中 区域设置文件。

    2. 区域设置检测¶

    src/Core/EventListener/LocaleListener.php 在 kernel.request 运行（优先级 20) 并应用以下决议顺序：

    flowchart TD
    A[Request] --> B{_locale query param?}
    B -- yes, supported --> C[setLocale canonical]
    B -- yes, unsupported --> D[silently ignored<br/>request keeps default locale]
    B -- no --> E{Accept-Language header?}
    E -- yes --> F[parse by q-weight,<br/>highest supported wins]
    E -- no --> G[request keeps default_locale `zh`]
    1. ?_locale= 查询参数 — 最高优先级。支持的值 (en、zh、zh_Hant、ja) 直接应用；不受支持的一个是 被忽略（请求保留其现有区域设置）。这也会短路 标题检查。
    2. Accept-Language header — 已解析（尊重 q 权重，最高的在前） 并映射到规范的语言环境：
    标头值 规范
    zh-CN、zh-Hans zh
    zh-TW、zh-HK、zh-Hant、zh-Hant-TW zh_Hant
    en-US、en-GB en
    ja-JP、ja_JP ja

    裸露的 zh/en/ja/zh_Hant 也可以解析（它们位于 直接SUPPORTED_LOCALES）。映射表为LOCALE_MAP 听众。 3. 后备 — 如果没有任何匹配项，请求将保留框架 default_locale，配置为zh。

    注意：听众的 PHPDoc 和 README（§“国际化”）说 后备是en。实际运行时配置 config/packages/translation.yaml设置了default_locale: zh，所以不支持 或缺少语言环境信号当前解析为 简体中文，而不是 英语。如果更改 default_locale，请同时更新配置和 评论保持一致。

    仅处理主要请求（$event->isMainRequest()）；子请求 （ESI 等）保持不变。

    3. 添加按键/新语言¶

    3.1 向现有语言环境添加新密钥¶

    1. 使用英文字符串作为messages.en.yaml中的key（key = value）。
    2. 将与翻译后的值相同的键添加到messages.zh.yaml中， messages.zh_Hant.yaml、messages.ja.yaml。 3、服务层抛出异常/返回消息；的 现有的拦截器/控制器路径会为您翻译它。

    3.2 添加新语言¶

    1. 创建translations/messages.{locale}.yaml。 Symfony 自动发现文件 在 translations/ 目录中 — 不需要配置注册。
    2. 将区域设置代码添加到 SUPPORTED_LOCALES，如果您需要详细代码 像 xx-XX 一样映射到它，添加一个条目到 LOCALE_MAP src/Core/EventListener/LocaleListener.php。

    4. 翻译文档管道¶

    文档（docs/，英文 Markdown）通过 a 镜像到 docs-zh/（中文） 脚本，并且两者都通过 mkdocs 内置到双语静态站点中。

    4.1 scripts/translate-docs.py¶

    使用免费的 deep-translator Google 端点镜像 docs/ → docs-zh/ （无 API 密钥）。

    • Prerequisite: pip install deep-translator
    • Usage: 
      python scripts/translate-docs.py                          # full mirror
python scripts/translate-docs.py design/bundles/payment.md # single file
    • Skips the research/ and ai/ directories.
    • Preserves: YAML frontmatter, fenced code blocks, inline code, HTML comments, images, and links — each is "stashed" before translation and restored after, so code and URLs are never mangled.
    • Splits the body into paragraphs and translates in chunks (< 4500 chars to respect the free API limit). A failed chunk is kept as the original English with a WARN line.

    4.2 scripts/build-docs.sh¶

    Full bilingual build (bash scripts/build-docs.sh). It:

    1. Runs translate-docs.py (docs → docs-zh).
    2. Copies the binary/text assets that should not be translated (assets/, research/, openapi/, ai/, javascripts/) from docs/ to docs-zh/.
    3. Generates two mkdocs configs from the single mkdocs.yml:
    4. mkdocs-en.yml — English, site_dir: site, adds language alternate links (/crud-skeleton/ ↔ /crud-skeleton/zh/).
    5. mkdocs-zh.yml — docs_dir: docs-zh, site_dir: site/zh, theme language: zh, nav labels translated via a static MAP (Home → 首页, Wallet → Wallet (钱包), ...) with a Google-translator fallback for unknown short labels.
    6. Builds both, mkdocs build -f ... --clean.

    Output:

    Site Config URL (local preview)
    English mkdocs-en.yml site/index.html
    Chinese mkdocs-zh.yml site/zh/index.html

    The source of truth for topics/nav is mkdocs.yml (site_name: CRUD Skeleton, Material theme, Mermaid support via extra_javascript). The generated mkdocs-en.yml / mkdocs-zh.yml are build artifacts — edit mkdocs.yml (and the MAP in build-docs.sh) and re-run the script.

    4.3 Translated READMEs¶

    The repo also ships hand-maintained translated README variants (see README §"Internationalization"):

    Language File
    Chinese (Simplified) README.zh-cn.md
    Chinese (Traditional) README.zh-hant.md
    Japanese README.ja.md

    These are independent of the docs-zh/ machine translation and are maintained manually.

    Summary¶

    • API strings: keys are English message strings in translations/messages.*.yaml; four locales (en, zh, zh_Hant, ja), default zh.
    • Detection: ?_locale= → Accept-Language (q-weighted, mapped via LOCALE_MAP) → framework default_locale.
    • Docs: docs/ → docs-zh/ via translate-docs.py; bilingual site built by build-docs.sh into site/ and site/zh/.
