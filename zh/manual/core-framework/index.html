    核心框架——深入探讨¶

    src/Core 包是粗骨架的核心。它提供了基础 控制器契约、可重用的视图混合、基于特征的服务层、 动态查询/表达式引擎、序列化器管道、内核事件侦听器、 实用程序、异常和 Prometheus 风格的指标注册表。

    本文档描述了每个类、其角色及其关键方法。它是一个 参考 — 有关实用食谱，请参阅 core-usage.md 并了解 查询参数参见query-system.md。

    1. 控制器层¶

    src/Core/Controller/RestController.php¶

    基本控制器合约。每个 API 控制器都扩展 RestController （它扩展了AbstractController）。它集中响应塑造， 分页、请求处理和依赖项访问。

    依赖项通过 #[Required] 设置器注入（setRequestStack、 setSerializer、setTranslator、setServiceContainer) 所以子控制器 只需要在自己的模块中声明其特定于模块的依赖关系 构造函数。请参阅config/services.yaml中的_instanceof接线。

    主要成员：

    会员 目的
    UNKNOWN_ERROR 默认警告消息'Api error occurred'。
    resolveService(string $id): object 从容器中解析任意服务 ID，如果丢失则抛出异常。
    getService(): object 返回控制器的 $service 属性（必须是一个对象）。
    getRequestStack() / getSerializer() / getTranslator() 带防护装置的惰性访问器。
    pagination(mixed $collection): array 应用 page/limit 查询参数并返回 {items, paginator}。处理 QueryBuilder （通过 Doctrine Paginator）、数组和 ArrayCollection。
    success(mixed $content, string $message, int $status): Response 构建标准信封{data, code: 0, message}（加上可选的paginator）。当 $status === 204 时，将 204 作为空主体返回。运行分页和请求处理（@expands、@display）。
    warning(string $msg, int $code, mixed $raw, int $status): Response 使用翻译后的消息构建错误信封 {code, message, raw_data}。
    requestProcess(mixed $collection) 应用于success()内部。处理 @expands、@display（复杂/JSON 投影/reduce），拉取请求驱动的视图整形。

    src/Core/Controller/HealthController.php¶

    容器/负载均衡器探针，公共（无 JWT） - 它们位于外部 /api 防火墙，以便编排器可以在没有令牌的情况下轮询它们。

    路线 方法 目的
    /health/live 获取 活跃度探测 — 当 PHP 处理请求时始终为 200。
    /health/ready 获取 准备就绪 — 运行 SELECT 1 （数据库）以及可选的 Redis 探针；当硬依赖项关闭时，返回降级的 503。

    Redis 探针 (checkRedis()) 是无依赖性的：它打开一个原始 TCP 套接字 并发送 RESP PING。当OTP_REDIS_DSN为空时返回disabled， ok 位于 +PONG 上，否则错误字符串。详细信息绝不会泄露给 匿名来电者；相反，它们会被记录。

    src/Core/Controller/MetricsController.php¶

    在 /metrics（公共）处提供 Prometheus 文本说明格式。 内存中的请求指标（计数器、持续时间直方图、飞行中的仪表）是 每个 PHP-FPM 工作人员。 DB 支持的计量表 — 每个主题的发件箱待办事项 （trade_outbox_message、store_outbox_message、inventory_outbox_message） 和失败的信使消息 - 在每次抓取时实时计算，因此它们是 对所有工人都是准确的。刮擦失败增加 metrics_scrape_errors_total。

    src/Core/Controller/System/EntityController.php¶

    自省端点（扩展 RestController）位于 /system/entities。

    路线 目的
    GET /system/entities 列出每个 Doctrine 管理的实体的 FQCN。
    GET /system/entities/{entityName} 返回字段映射（类型、columnName、可为空、长度等）、关联映射（类型、targetEntity），以及每个属性的人性化纯文本标签及其翻译。 entityName 使用斜杠而不是反斜杠（例如 App/Common/Entity/Category）。

    src/Core/Controller/System/RouterController.php¶

    在 GET /system/router 处，返回在 Symfony 路由器中注册的每个路由 由路线名称键入。

    src/Core/Controller/DefaultController.php¶

    顶级默认控制器（此处未详细介绍；请参阅该文件）。

    2.视图层¶

    视图层将配置好的控制器简单地转变为完整的 REST 端点 通过撰写特征。每个 mixin 定义路由 (#[Route])、OpenAPI 属性 (#[OA\*]) 和操作方法。控制者通过 use 选择加入。

    src/Core/View/ApiView.php¶

    提供共享过滤助手的基本 trait。不是定义的 mixin 路线本身；它提供了commonFilter扩展点和标准 读取 mixins 使用的合并。

    会员 目的
    entityNotFoundMessage() 默认'Entity not found'。
    commonFilter() 扩展点：返回一个数组或QueryBuilder限制控制器上的所有查询（例如['enabled' => true]或['user' => $this->getUser()]）。
    mixIdToCommonFilter(int\|string $id) 将 id 合并到公共过滤器中；当 id 是有效的 UUID 时，使用 uuid 作为键，否则使用 id。
    mixToCommonFilter(array $data) 将 $data 合并到通用过滤器中。对于QueryBuilder，它附加AND alias.key = :key条件。

    标准 CRUD mixins¶

    这些是视图层的核心内容。每个用作：

    use ApiView, DetailApiViewMixin, ListApiViewMixin,
    CreateApiViewMixin, UpdateApiViewMixin, DeleteApiViewMixin;
    米辛 路线 方法 行为
    ListApiViewMixin /（名称list） 获取 调用service->list($this->listFilter($this->commonFilter()), null, false)，然后调用listProcessor/listResponses。
    DetailApiViewMixin /{id}（名称detail） 获取 mixIdToCommonFilter，然后是detailFilter、detailProcessor、detailResponse。 404 失踪时。
    CreateApiViewMixin /（名称create） 发布 接受单个对象或数组（批量）。强制执行 requiredCreateProperties / acceptedCreateProperties，应用 defaultCreateValues、processCreateContent、processEntity、afterCreated。批量/事务性除非 @partial。
    UpdateApiViewMixin /{id}（放置，update）； /batch-update（发布） 放置/发布 通过 id 进行单次更新，并通过 @mode 和 @basis 进行批量/更新插入模式。强制执行 requiredUpdateProperties / acceptedUpdateProperties。
    DeleteApiViewMixin /{id}（名称delete） 删除 deletionFilter，service->get，然后service->remove；成功时返回 204，失败时返回 404。

    CreateApiViewMixin要点¶

    • 使用FixJSON::getJSONType()确定输入形状（object→单个， array → 批次）。
    • 如果定义了 requiredCreateProperties，则每个列出的属性必须存在于 抛出有效负载或 ValidatorException ("{Property} is required")。
    • 如果定义了acceptedCreateProperties，则仅转发那些密钥。
    • @partial（布尔值）禁用周围事务； @transform 实现内容转换。
    • 返回带有创建的实体（或实体数组）的201。

    UpdateApiViewMixin要点¶

    • 单次更新：PUT /{id}，通过mixIdToCommonFilter查找。
    • 批量更新：POST /batch-update。
    • @mode：update或mixed（默认mixed = upsert：没有匹配时创建）。
    • @basis：用于匹配现有实体的逗号分隔字段。
    • @partial：如果为 false，则将整个批次包装在一个事务中。
    • 通过执行 requiredUpdateProperties / acceptedUpdateProperties propertyCannotBeEmpty。
    • 在混合模式下，它可能会调用创建代码路径（defaultCreateValues， processCreateContent、afterCreated）。

    作用域混入¶

    米辛 路线 行为
    ScopedListApiViewMixin /{scopeId}（名称list） 调用摘要scopedListFilter($scopeId)，然后调用service->list(...)。
    ScopedDetailApiViewMixin /{scopeId}/{id}（名称detail） 调用抽象 scopedDetailFilter($scopeId, $id) 并在没有匹配项时返回 404。

    “单一资源”混合¶

    对于单例资源（例如用户自己的单个配置文件/设置 记录）而不是集合：

    米辛 路线 行为
    SingleDetailApiViewMixin /（名称detail） GET — 返回 commonFilter() 找到的任何内容（可能为 null）。
    SingleCreateAndUpdateApiViewMixin /（名称update） PUT — 更新插入单个记录：如果 commonFilter() 找不到任何内容，则它创建（通过 filterCreateProperties + defaultCreateValues 过滤），否则更新（filterUpdateProperties + defaultUpdateValues）。

    WorkflowApiViewMixin¶

    为声明 $workflow 的控制器添加 Symfony Workflow 助手 服务（通常是 $serviceClass）：

    路线 方法 行为
    /todo 获取 列出至少一个已启用转换的实体。
    /{id}/transitions 获取 列出实体启用的转换。
    /{id}/do/{transition} 发布 在事务内应用转换（可以选择首先更新实体）。当 can() 失败时抛出 TRANSITION_CANNOT_APPLY。
    /{id}/status-reset 放置 仅ROLE_ADMIN — 重置工作流程标记。

    注意：许多模块（例如 Trade OrderController）实现工作流操作 内联而不是使用这个特征——当它适合时更喜欢这个特征，或者遵循 贸易控制器提供更多控制。

    TransformContent 特征¶

    启用 @transform （或 $transformer 参数）重写提交的 通过 Symfony ExpressionLanguage 的内容。对于变压器中的每个字段 映射它解析目标实体的属性元数据以检测 Doctrine 关系，对于一对一关系，解析匹配的 *Service，以便您 可以写这样的东西：

    category: "Service.get({'name': ':value'}).getId()"

    它公开 Service （带有 get/list 的网关，包装已解析的服务 并返回身份对象）、entity、Math和ArrayCommon到 表达。当字段不是不动产时抛出INVALID_CONTENT_FIELD。

    ApiViewMessages¶

    用于共享面向用户的消息的常量/帮助器集：

    恒定 价值
    SUCCESS SUCCESS
    ENTITY_NOT_FOUND Entity is not found
    INVALID_JSON Invalid JSON
    INVALID_CONTENT_FIELD Invalid content field
    CREATE_FAILED Create failed
    BATCH_UPDATE_ERROR Batch update error
    CONTENT_TYPE_ERROR Content type error.
    TRANSITION_CANNOT_APPLY Current transition cannot be applied.
    propertyRequired($p) "{P} is required"
    propertyCannotBeEmpty($p) "{P} cannot be empty."

    3.服务层¶

    src/Core/Service/BaseServiceInterface.php¶

    该合约由BaseService执行。 TEntity 上的通用。

    Method Signature Purpose
    get ($object, bool $directly = false) Resolve an entity from an id, criteria array, QueryBuilder, or an object with getId().
    list ($object = null, $order = null, bool $disableRequest = true) List entities or return a configured QueryBuilder. When $disableRequest is false, consult the current request for @filter/@order/@select/@groupBy/@hints/@sort.
    new () Create a new entity instance.
    update ($object, ?array $data, bool $noFlush = false) Persist a data array onto an entity; flush unless $noFlush.
    remove ($object): bool Remove and flush.
    wrapInTransaction (callable $fn): mixed Run a callable inside a DB transaction with all-or-nothing semantics.

    src/Core/Service/BaseService.php¶

    Abstract base that assembles the three concern traits and wires shared state through the constructor: container, entity class, locator, entity manager, repository, logger, current user (from the token storage), and optional ExpressionServiceInterface / LegacyEvaluator.

    src/Core/Service/ServiceLocatorInterface.php & DefaultServiceLocator.php¶

    A small interface decoupling BaseService from the container, which keeps test fakes lightweight. It exposes getEntityManager, getLogger, getTokenStorage, getRequestStack, getSerializer, getValidator (return types documented via PHPDoc so fakes stay untyped). DefaultServiceLocator implements it by pulling those services from the container, returning null / NullLogger gracefully when absent. Autowired as App\Core\Service\ServiceLocatorInterface. DefaultServiceLocator is registered as that interface alias in config/services.yaml.

    Service concerns (src/Core/Service/Concern/)¶

    BaseServiceInfrastructureTrait¶

    Shared infrastructure accessors and helpers:

    Member Purpose
    listResultToCollection($list): ArrayCollection (static) Normalize a QueryBuilder result or array into an ArrayCollection.
    externalExpressionValues(): array Values exposed to expressions: math/Math, datetime/Datetime, ArrayCommon.
    getEntityManager() / getRepository() / getLogger() / getSerializer() / getValidator() / getRequestStack() Lazy accessors, with fallbacks (e.g. a hand-rolled Serializer when none is registered).
    getCurrentRequest() Current request via the request stack.
    getQueryBuilderFactory() / getExpressionService() / getLegacyEvaluator() Lazy creators of the query engine collaborators.
    wrapInTransaction(callable $fn): mixed Begins a transaction, flushes before commit, rolls back on any Throwable, and resets a closed EntityManager. Falls back to plain execution for fake/mock EM (no beginTransaction).
    resetEntityManager() Rebound a fresh manager/repository after a connection failure.

    BaseServiceReadListTrait¶

    Implements get() and list() (see query-system.md for the full list() behavior).

    • get() handles: null (→ null), QueryBuilder (single result), an object with getId(), an associative criteria array (findOneBy), a valid UUID string (matched against a uuid field when present), or a plain id (rep->find).
    • list() builds a QueryBuilder from the entity class, applies an associative array as equality conditions, and — when $disableRequest is false — processes @dql, @filter, @select, @groupBy, @order, @hints, @showDQL, and the in-memory @sort/@filter fallback.
    • Privileged parameters @dql, @sort, @hints are restricted to ROLE_ADMIN; @showDQL is restricted to the dev environment. @select is guarded against accessing identity data.

    BaseServiceMutationTrait¶

    Implements new(), update(), remove().

    • new() instantiates the entity, bypassing a required constructor if needed.
    • update() maps data onto the entity: it reflects property attributes to detect relations — to-one (ManyToOne/OneToOne) relations are resolved by id and set via the setter; to-many (ManyToMany/OneToMany) collections are diffed and add/remove methods called; date-like properties are converted with new \DateTime(...). Remaining scalar fields are deserialized via the Symfony Serializer with object_to_populate. It validates the entity and persists (flushing unless $noFlush). Throws ValidatorException on null objects, missing related entities (NotFoundHttpException), and "Duplication entries" on a UniqueConstraintViolationException.
    • remove() gets, removes and flushes, returning success.

    4. Parser & Expression Engine¶

    See query-system.md for the complete user-facing query reference. Here we document the classes.

    src/Core/Parser/ExpressionDqlParser.php¶

    Compiles an @filter expression into safe QueryBuilder fragments (joins, where, parameters). It parses with Symfony ExpressionLanguage, then walks the AST (recursiveCompile) supporting a strict, safe node set.

    Supported operators map to DQL:

    Operator DQL fragment
    == / != = / !=
    > >= < <= same
    && / || AND / OR
    + - * / same
    matches REGEXP(...) = TRUE for /pattern/flags, else LIKE '%...%'

    Notable members:

    Member Purpose
    setExpression / setDataClass / setValues Configure the parser (builder style). setValues keeps an entity signature key.
    compile(int $cacheTtl = 3600): self Parse + compile; uses a PSR-16 cache when available. Throws ValidatorException on syntax/compile errors.
    getWhere() / getJoins() / getParameters() Compiled fragments.
    getFragments(): array Returns {joins, where, params} — DB-agnostic; the assembler applies them.
    getSource(?QueryBuilder $qb = null): string Full DQL source of the compiled expression.
    validateFragments(EntityManagerInterface $em): void Re-resolves every join path and where token against Doctrine metadata, throwing ValidatorException for unknown aliases/properties.

    Attribute chains like entity.getCategory().getName() produce joins (filter_entity_category etc.) and a final filter_entity_category.name reference. A top-level bare attribute compiles to prop IS NOT NULL.

    src/Core/Parser/ExpressionQueryBuilderAssembler.php¶

    Applies ExpressionDqlParser fragments onto a Doctrine QueryBuilder.

    Method Purpose
    buildQueryBuilder(parser, $options = []): QueryBuilder Create a fresh SELECT root FROM dataClass root and apply the fragments.
    applyToQueryBuilder($qb, parser, $options = []): QueryBuilder Apply fragments to an existing QueryBuilder (remaps root alias, dedupes joins/aliases, renames colliding parameter names, and applies leftJoin + andWhere + params).

    src/Core/Service/ExpressionService.php (+ interface ExpressionServiceInterface)¶

    Central wrapper that turns a filter string into a {qb, parameters} result (used by BaseServiceReadListTrait). It caches compiled DQL + parameters via a PSR-16 cache, otherwise parses/validates/assembles through the parser + assembler. parseAndAssemble() is protected so unit tests can override it.

    src/Core/Service/QueryBuilderFactory.php¶

    Simple factory for creating QueryBuilder roots: create($dataClass, $rootAlias = 'entity') (an alias of createRootQueryBuilder) returns a SELECT alias FROM dataClass alias. Keeps creation in one place so BaseService can delegate and tests can mock it.

    src/Core/Service/LegacyEvaluator.php¶

    Provides the in-memory fallback for @filter and @sort using Symfony ExpressionLanguage.

    Method Purpose
    evaluate($expr, $context = []) Evaluate against globals+context; returns false and logs on error.
    evaluateBool($expr, $context = []): bool Boolean-cast convenience (used when filtering/sorting in memory, e.g. @sort comparing x/y).

    5. Serializer¶

    src/Core/Serializer/SerializerContextFactory.php¶

    Builds canonical serializer contexts. Recognized options: groups (array|string) and max_depth (int, with enable_max_depth defaulting to true).

    src/Core/Serializer/CircularReferenceHandler.php¶

    Static, dependency-free circular-reference handler: returns the object's id when it has getId(), otherwise spl_object_hash. Referenced from serializer config.

    src/Core/Serializer/Normalizer/FlatNormalizer.php¶

    Decorates the default object normalizer (registered as app.serializer.method_normalizer, decorating serializer.normalizer.object) to produce the project's "flat" entity representation:

    • Avoids normalizing Doctrine internal objects (Doctrine\ORM\*, Doctrine\Persistence\*) — stringifies or returns the class name.
    • Adds __toString at the top level when present.
    • Reduces related objects to {id, __toString, __metadata}.
    • Expands traversable collections of related objects.
    • JSON-decodes string-valued fields (excluding numeric strings) into objects.
    • On normalization failure returns {id, __toString} or {__class}.

    src/Core/Serializer/Normalizer/CircularReferenceHandler.php¶

    A second, stricter circular handler: returns ['id' => $id] when the object has a scalar id, otherwise throws "Every entity should have getId method".

    src/Core/Serializer/Callbacks/ObjectCallback.php¶

    Serializer callback (handle(object)): returns the object's getId(), else null. Useful as a callback map entry for specific properties.

    6. Kernel Event Listeners¶

    Registered in config/services.yaml (and some in the Core bundle services.yaml).

    AccessLogListener¶

    Responds to kernel.response (priority -5). Logs POST/PUT/DELETE requests to the monolog.logger.access channel in the form {user} {METHOD} {uri} | {status} | REQ: ... | RES: .... Bodies are truncated at 4096 chars. Auth paths (/api/auth, /api/wechat) have their bodies hidden.

    ControllerListener¶

    Responds to kernel.controller. Logs PUT/POST requests with the operating user id and a 1 KB-truncated body ("User [#$operator] Requests $method $uri: ...").

    ExceptionInterceptor¶

    Responds to kernel.exception. Only acts on /api/... URLs. Logs the exception, returns JSON {code, message, class} with an appropriate status when out of dev. (If the environment equals dev.disabled it re-throws so Symfony shows the debug page.)

    LocaleListener¶

    Responds to kernel.request (priority 20). Sets the request locale from _locale query param or the Accept-Language header. Supported locales: en, zh, zh_Hant, ja. Maps verbose forms (zh-CN → zh, zh-TW → zh_Hant, ja-JP → ja, etc.).

    MetricsListener¶

    Responds to kernel.request (priority 10) and kernel.response (priority -1). Records http_requests_total (counter by method/route/status), http_request_duration_seconds (histogram), and http_requests_inflight (gauge). Skips sub-requests and /health, /metrics, /_profiler, /_wdt, /api/doc paths.

    OpenApiEnricherListener¶

    响应kernel.response（优先级-10）。后处理 /api/doc.json 和 /api/doc 响应以丰富 OpenAPI 规范：注入 规范标签，来自 META 地图的每个端点摘要/描述， 媒体上传端点的多部分上传请求主体，并剥离 通用 mixin 标签（List、Detail、Create、Update、Delete、Workflow）。 标签是从路由名称自动检测的（manage-*/app-*资源段， system-*、wechat-*、sys-auth）。

    RateLimitListener¶

    响应kernel.controller（优先级10）。应用由以下键控的速率限制 客户端 IP 到公共端点：

    限制器 路径
    auth_login ^/api/auth/login$
    auth_register ^/api/auth/register$
    otp_request ^/api/auth/otp/request$
    otp_verify ^/api/auth/otp/verify$
    wechat_login ^/api/wechat/miniapp/login$、^/api/wechat/oauth/callback$
    payment ~^/api/v1/app/orders/.+/payment$~、~^/api/v1/(app\|manage)/invoices/.+/pay~

    超出时，它会用标准中的 429 响应替换控制器 信封 {data, code, message} 加上 Retry-After 标头。限制器是 通过服务定位器注入（auth_login、auth_register、otp_request、 otp_verify、wechat_login、payment）。

    8. 异常 (src/Core/Exception/)¶

    班级 目的
    MessageErrorHttpException HttpException 带有状态 403，可选 redirectUrl 标头。用于业务“错误”控制流。
    MessageSuccessHttpException HttpException 带有状态 200，可选 redirectUrl 标头。用于业务“成功”控制流消息有效负载。

    两者均由 ExceptionInterceptor 处理并在 JSON 中进行翻译 message 字段。

    9. 指标注册表 (src/Core/Metrics/MetricsRegistry.php)¶

    一个轻量级的、内存中的 Prometheus 风格的注册表（无外部客户端）。

    方法 目的
    incCounter($name, $labels, $by = 1) 增加一个计数器。
    setGauge($name, $labels, $value) / getGauge(...) 设置/读取仪表。
    observe($name, $labels, $value, $buckets = null) 记录直方图观察（默认存储桶 HISTOGRAM_BUCKETS 以秒为单位）。
    render(): string 渲染 Prometheus 文本展示格式 (v0.0.4)。

    METADATA中注册的指标名称：app_info、http_requests_total、 http_request_duration_seconds、http_requests_inflight、 app_outbox_backlog、app_messenger_failed、metrics_scrape_errors_total。 计数器/直方图是针对每个工人的； DB 支持的仪表是在抓取时实时计算的。
