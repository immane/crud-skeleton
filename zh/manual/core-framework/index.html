    核心框架——深入探讨¶

    src/Core 包是粗骨架的核心。它提供了基础 控制器契约、可重用的视图混合、基于特征的服务层、 动态查询/表达式引擎、序列化器管道、内核事件侦听器、 实用程序、异常和 Prometheus 风格的指标注册表。

    本文档描述了每个类、其角色及其关键方法。它是一个 参考 — 有关实用食谱，请参阅 core-usage.md 并了解 查询参数参见query-system.md。

    1. 控制器层¶

    src/Core/Controller/RestController.php¶

    基本控制器合约。每个 API 控制器都扩展 RestController （它扩展了AbstractController）。它集中响应塑造， 分页、请求处理和依赖项访问。

    依赖项通过 #[Required] 设置器注入（setRequestStack、 setSerializer、setTranslator、setServiceContainer) 所以子控制器 只需要在自己的模块中声明其特定于模块的依赖关系 构造函数。请参阅config/services.yaml中的_instanceof接线。

    主要成员：

    会员 目的
    UNKNOWN_ERROR 默认警告消息'Api error occurred'。
    resolveService(string $id): object 从容器中解析任意服务 ID，如果丢失则抛出异常。
    getService(): object 返回控制器的 $service 属性（必须是一个对象）。
    getRequestStack() / getSerializer() / getTranslator() 带防护装置的惰性访问器。
    pagination(mixed $collection): array 应用 page/limit 查询参数并返回 {items, paginator}。处理 QueryBuilder （通过 Doctrine Paginator）、数组和 ArrayCollection。
    success(mixed $content, string $message, int $status): Response 构建标准信封{data, code: 0, message}（加上可选的paginator）。当 $status === 204 时，将 204 作为空主体返回。运行分页和请求处理（@expands、@display）。
    warning(string $msg, int $code, mixed $raw, int $status): Response 使用翻译后的消息构建错误信封 {code, message, raw_data}。
    requestProcess(mixed $collection) 应用于success()内部。处理 @expands、@display（复杂/JSON 投影/reduce），拉取请求驱动的视图整形。

    src/Core/Controller/HealthController.php¶

    容器/负载均衡器探针，公共（无 JWT） - 它们位于外部 /api 防火墙，以便编排器可以在没有令牌的情况下轮询它们。

    路线 方法 目的
    /health/live 获取 活跃度探测 — 当 PHP 处理请求时始终为 200。
    /health/ready 获取 准备就绪 — 运行 SELECT 1 （数据库）以及可选的 Redis 探针；当硬依赖项关闭时，返回降级的 503。

    Redis 探针 (checkRedis()) 是无依赖性的：它打开一个原始 TCP 套接字 并发送 RESP PING。当OTP_REDIS_DSN为空时返回disabled， ok 位于 +PONG 上，否则错误字符串。详细信息绝不会泄露给 匿名来电者；相反，它们会被记录。

    src/Core/Controller/MetricsController.php¶

    在 /metrics（公共）处提供 Prometheus 文本说明格式。 内存中的请求指标（计数器、持续时间直方图、飞行中的仪表）是 每个 PHP-FPM 工作人员。 DB 支持的计量表 — 每个主题的发件箱待办事项 （trade_outbox_message、store_outbox_message、inventory_outbox_message） 和失败的信使消息 - 在每次抓取时实时计算，因此它们是 对所有工人都是准确的。刮擦失败增加 metrics_scrape_errors_total。

    src/Core/Controller/System/EntityController.php¶

    自省端点（扩展 RestController）位于 /system/entities。

    路线 目的
    GET /system/entities 列出每个 Doctrine 管理的实体的 FQCN。
    GET /system/entities/{entityName} 返回字段映射（类型、columnName、可为空、长度等）、关联映射（类型、targetEntity），以及每个属性的人性化纯文本标签及其翻译。 entityName 使用斜杠而不是反斜杠（例如 App/Common/Entity/Category）。

    src/Core/Controller/System/RouterController.php¶

    在 GET /system/router 处，返回在 Symfony 路由器中注册的每个路由 由路线名称键入。

    src/Core/Controller/DefaultController.php¶

    顶级默认控制器（此处未详细介绍；请参阅该文件）。

    2.视图层¶

    视图层将配置好的控制器简单地转变为完整的 REST 端点 通过撰写特征。每个 mixin 定义路由 (#[Route])、OpenAPI 属性 (#[OA\*]) 和操作方法。控制者通过 use 选择加入。

    src/Core/View/ApiView.php¶

    提供共享过滤助手的基本 trait。不是定义的 mixin 路线本身；它提供了commonFilter扩展点和标准 读取 mixins 使用的合并。

    会员 目的
    entityNotFoundMessage() 默认'Entity not found'。
    commonFilter() 扩展点：返回一个数组或QueryBuilder限制控制器上的所有查询（例如['enabled' => true]或['user' => $this->getUser()]）。
    mixIdToCommonFilter(int\|string $id) 将 id 合并到公共过滤器中；当 id 是有效的 UUID 时，使用 uuid 作为键，否则使用 id。
    mixToCommonFilter(array $data) 将 $data 合并到通用过滤器中。对于QueryBuilder，它附加AND alias.key = :key条件。

    标准 CRUD mixins¶

    这些是视图层的核心内容。每个用作：

    use ApiView, DetailApiViewMixin, ListApiViewMixin,
    CreateApiViewMixin, UpdateApiViewMixin, DeleteApiViewMixin;
    Mixin Route(s) Methods Behavior
    ListApiViewMixin / (name list) GET Calls service->list($this->listFilter($this->commonFilter()), null, false), then listProcessor / listResponses.
    DetailApiViewMixin /{id} (name detail) GET mixIdToCommonFilter, then detailFilter, detailProcessor, detailResponse. 404 when missing.
    CreateApiViewMixin / (name create) POST Accepts a single object or array (batch). Enforces requiredCreateProperties / acceptedCreateProperties, applies defaultCreateValues, processCreateContent, processEntity, afterCreated. Batch/transactional unless @partial.
    UpdateApiViewMixin /{id} (PUT, update); /batch-update (POST) PUT/POST Single update by id plus batch/upsert mode via @mode and @basis. Enforces requiredUpdateProperties / acceptedUpdateProperties.
    DeleteApiViewMixin /{id} (name delete) DELETE deletionFilter, service->get, then service->remove; returns 204 on success, 404 when missing.

    CreateApiViewMixin key points¶

    • Determines input shape with FixJSON::getJSONType() (object → single, array → batch).
    • If requiredCreateProperties is defined, each listed property must exist in the payload or a ValidatorException ("{Property} is required") is thrown.
    • If acceptedCreateProperties is defined, only those keys are forwarded.
    • @partial (boolean) disables the surrounding transaction; @transform enables content transformation.
    • Returns 201 with the created entity (or array of entities).

    UpdateApiViewMixin key points¶

    • Single update: PUT /{id}, looks up via mixIdToCommonFilter.
    • Batch update: POST /batch-update.
    • @mode: update or mixed (default mixed = upsert: create when no match).
    • @basis: comma-separated fields used to match existing entities.
    • @partial: when false, wraps the whole batch in one transaction.
    • Enforces requiredUpdateProperties / acceptedUpdateProperties via propertyCannotBeEmpty.
    • In mixed mode it may call the create code path (defaultCreateValues, processCreateContent, afterCreated).

    Scoped mixins¶

    Mixin Route Behavior
    ScopedListApiViewMixin /{scopeId} (name list) Calls the abstract scopedListFilter($scopeId) then service->list(...).
    ScopedDetailApiViewMixin /{scopeId}/{id} (name detail) Calls abstract scopedDetailFilter($scopeId, $id) and returns 404 when nothing matches.

    "Single resource" mixins¶

    For resources that are singletons (e.g. a user's own single profile/settings record) rather than collections:

    Mixin Route Behavior
    SingleDetailApiViewMixin / (name detail) GET — returns whatever commonFilter() finds (may be null).
    SingleCreateAndUpdateApiViewMixin / (name update) PUT — upserts the single record: if commonFilter() finds nothing it creates (filtering via filterCreateProperties + defaultCreateValues), otherwise updates (filterUpdateProperties + defaultUpdateValues).

    WorkflowApiViewMixin¶

    Adds Symfony Workflow helpers for a controller that declares a $workflow service (and typically a $serviceClass):

    Route Method Behavior
    /todo GET Lists entities with at least one enabled transition.
    /{id}/transitions GET Lists enabled transitions for an entity.
    /{id}/do/{transition} POST Applies a transition inside a transaction (optionally updating the entity first). Throws TRANSITION_CANNOT_APPLY when can() fails.
    /{id}/status-reset PUT ROLE_ADMIN only — resets the workflow marking.

    Note: Many modules (e.g. Trade OrderController) implement workflow actions inline rather than using this trait — prefer the trait when it fits, or follow the Trade controllers for more control.

    TransformContent trait¶

    Enables @transform (or the $transformer argument) to rewrite submitted content through Symfony ExpressionLanguage. For each field in the transformer map it resolves the target entity's property metadata to detect Doctrine relations and, for a to-one relation, resolves the matching *Service so you can write things like:

    category: "Service.get({'name': ':value'}).getId()"

    It exposes Service (a gateway with get/list wrapping the resolved service and returning identity objects), entity, Math, and ArrayCommon to the expression. Throws INVALID_CONTENT_FIELD when a field is not a real property.

    ApiViewMessages¶

    Constant/helper set for shared user-facing messages:

    Constant Value
    SUCCESS SUCCESS
    ENTITY_NOT_FOUND Entity is not found
    INVALID_JSON Invalid JSON
    INVALID_CONTENT_FIELD Invalid content field
    CREATE_FAILED Create failed
    BATCH_UPDATE_ERROR Batch update error
    CONTENT_TYPE_ERROR Content type error.
    TRANSITION_CANNOT_APPLY Current transition cannot be applied.
    propertyRequired($p) "{P} is required"
    propertyCannotBeEmpty($p) "{P} cannot be empty."

    3. Service Layer¶

    src/Core/Service/BaseServiceInterface.php¶

    The contract implemented by BaseService. Generic over TEntity.

    方法 签名 目的
    get ($object, bool $directly = false) 从 id、条件数组、QueryBuilder 或带有 getId() 的对象解析实体。
    list ($object = null, $order = null, bool $disableRequest = true) 列出实体或返回配置的QueryBuilder。当$disableRequest为false时，查询当前请求的@filter/@order/@select/@groupBy/@hints/@sort。
    new () 创建一个新的实体实例。
    update ($object, ?array $data, bool $noFlush = false) 将数据数组持久化到实体上；除非$noFlush，否则冲洗。
    remove ($object): bool 取出并冲洗。
    wrapInTransaction (callable $fn): mixed 使用全有或全无语义在数据库事务内运行可调用对象。

    src/Core/Service/BaseService.php¶

    组装三个关注点特征并连接共享状态的抽象基础 通过构造函数：容器、实体类、定位器、实体管理器， 存储库、记录器、当前用户（来自令牌存储）和可选 ExpressionServiceInterface / LegacyEvaluator。

    src/Core/Service/ServiceLocatorInterface.php & DefaultServiceLocator.php¶

    一个小接口，将 BaseService 与容器解耦，从而保持 测试假货轻量。它公开 getEntityManager、getLogger、 getTokenStorage、getRequestStack、getSerializer、getValidator（返回 通过 PHPDoc 记录类型，因此假货保持无类型）。 DefaultServiceLocator 通过从容器中提取这些服务来实现它，返回 null / NullLogger 缺席时保持优雅。自动连线为 App\Core\Service\ServiceLocatorInterface。 DefaultServiceLocator 被注册为该接口别名 config/services.yaml。

    服务问题 (src/Core/Service/Concern/)¶

    BaseServiceInfrastructureTrait¶

    共享基础设施访问器和助手：

    会员 目的
    listResultToCollection($list): ArrayCollection（静态） 将 QueryBuilder 结果或数组标准化为 ArrayCollection。
    externalExpressionValues(): array 暴露给表达式的值：math/Math、datetime/Datetime、ArrayCommon。
    getEntityManager() / getRepository() / getLogger() / getSerializer() / getValidator() / getRequestStack() 惰性访问器，具有后备功能（例如，当没有注册时，手动滚动 Serializer）。
    getCurrentRequest() 通过请求堆栈的当前请求。
    getQueryBuilderFactory() / getExpressionService() / getLegacyEvaluator() 查询引擎协作者的懒惰创建者。
    wrapInTransaction(callable $fn): mixed 开始事务，在提交之前刷新，回滚任何 Throwable，并重置已关闭的 EntityManager。回退到假/模拟 EM 的普通执行（无 beginTransaction）。
    resetEntityManager() 连接失败后重新启动新的管理器/存储库。

    BaseServiceReadListTrait¶

    实现get()和list()（参见query-system.md 完整的 list() 行为）。

    • get() 句柄：null（→ null）、QueryBuilder（单个结果）、一个对象 与 getId()、关联条件数组 (findOneBy)、有效的 UUID 字符串（如果存在，则与 uuid 字段匹配），或普通 id （rep->find）。
    • list() 从实体类构建 QueryBuilder，应用 关联数组作为相等条件，并且 — 当 $disableRequest 为 false — 处理 @dql、@filter、@select、@groupBy、@order、 @hints、@showDQL 和内存中 @sort/@filter 后备。
    • 特权参数@dql、@sort、@hints仅限于 ROLE_ADMIN; @showDQL 仅限于 dev 环境。 @select 是 防止访问身份数据。

    BaseServiceMutationTrait¶

    实现new()、update()、remove()。

    • new() 实例化实体，如果需要则绕过所需的构造函数。
    • update() 将数据映射到实体：它将属性属性反映到 检测关系 — 一对一 (ManyToOne/OneToOne) 关系通过以下方式解决 id 并通过 setter 设置；一对多 (ManyToMany/OneToMany) 集合是 diffed 和添加/删除方法调用；类似日期的属性转换为 new \DateTime(...)。剩余的标量字段通过以下方式反序列化 使用 object_to_populate 的 Symfony 序列化器。它验证实体并 持续存在（除非$noFlush，否则刷新）。如果为 null，则抛出 ValidatorException 对象、缺少相关实体 (NotFoundHttpException) 以及 "Duplication entries" 位于 UniqueConstraintViolationException 上。
    • remove() 获取、删除和刷新，返回成功。

    4. 解析器和表达式引擎¶

    请参阅 query-system.md 了解完整的面向用户的查询 参考。在这里我们记录课程。

    src/Core/Parser/ExpressionDqlParser.php¶

    将 @filter 表达式编译为安全的 QueryBuilder 片段（连接、 其中，参数）。它使用 Symfony ExpressionLanguage 进行解析，然后遍历 AST (recursiveCompile) 支持严格、安全的节点集。

    支持的运算符映射到 DQL：

    操作员 DQL 片段
    == / != = / !=
    > >= < <= 相同
    && / || AND / OR
    + - * / 相同
    matches REGEXP(...) = TRUE 代表 /pattern/flags，否则 LIKE '%...%'

    著名成员：

    会员 目的
    setExpression / setDataClass / setValues 配置解析器（构建器样式）。 setValues 保留 entity 签名密钥。
    compile(int $cacheTtl = 3600): self 解析+编译；使用 PSR-16 缓存（如果可用）。语法/编译错误时抛出 ValidatorException。
    getWhere() / getJoins() / getParameters() 编译的片段。
    getFragments(): array 返回 {joins, where, params} — 与数据库无关；汇编器应用它们。
    getSource(?QueryBuilder $qb = null): string 已编译表达式的完整 DQL 源。
    validateFragments(EntityManagerInterface $em): void 根据 Doctrine 元数据重新解析每个连接路径和位置标记，对于未知的别名/属性抛出 ValidatorException。

    像 entity.getCategory().getName() 这样的属性链会产生连接 （filter_entity_category 等）和最后的 filter_entity_category.name 参考。顶级裸属性编译为 prop IS NOT NULL。

    src/Core/Parser/ExpressionQueryBuilderAssembler.php¶

    将 ExpressionDqlParser 片段应用到 Doctrine QueryBuilder 上。

    方法 目的
    buildQueryBuilder(parser, $options = []): QueryBuilder 创建一个新的 SELECT root FROM dataClass root 并应用片段。
    applyToQueryBuilder($qb, parser, $options = []): QueryBuilder 将片段应用到现有的 QueryBuilder（重新映射根别名、删除重复连接/别名、重命名冲突参数名称以及应用 leftJoin + andWhere + 参数）。

    src/Core/Service/ExpressionService.php（+接口ExpressionServiceInterface）¶

    将过滤器字符串转换为 {qb, parameters} 结果的中央包装器 （由 BaseServiceReadListTrait 使用）。它通过一个缓存编译的 DQL + 参数 PSR-16 缓存，否则通过解析器解析/验证/组装 + 汇编器。 parseAndAssemble() 受到保护，因此单元测试可以覆盖它。

    src/Core/Service/QueryBuilderFactory.php¶

    用于创建 QueryBuilder 根的简单工厂：create($dataClass, $rootAlias = 'entity')（createRootQueryBuilder 的别名）返回 SELECT alias FROM dataClass alias。将创作保留在一处，因此 BaseService 可以委托并且测试可以模拟它。

    src/Core/Service/LegacyEvaluator.php¶

    使用 Symfony 为 @filter 和 @sort 提供内存中回退 ExpressionLanguage。

    方法 目的
    evaluate($expr, $context = []) 根据全局+上下文进行评估；返回 false 并登录错误。
    evaluateBool($expr, $context = []): bool 布尔转换方便（在内存中过滤/排序时使用，例如 @sort 比较 x/y）。

    5. 序列化器¶

    src/Core/Serializer/SerializerContextFactory.php¶

    构建规范的序列化器上下文。识别的选项：groups (array|string) 和 max_depth (int，enable_max_depth 默认为 true）。

    src/Core/Serializer/CircularReferenceHandler.php¶

    静态、无依赖的循环引用处理程序：返回对象的 id 当它有getId()时，否则spl_object_hash。参考自 串行器配置。

    src/Core/Serializer/Normalizer/FlatNormalizer.php¶

    装饰默认的对象规范化器（注册为 app.serializer.method_normalizer，装饰 serializer.normalizer.object) 生成项目的“扁平”实体 代表：

    • 避免规范化 Doctrine 内部对象（Doctrine\ORM\*、 Doctrine\Persistence\*) — 字符串化或返回类名。
    • 如果存在，则在顶层添加 __toString。
    • 将相关对象减少到{id, __toString, __metadata}。
    • 扩展相关对象的可遍历集合。
    • JSON 将字符串值字段（不包括数字字符串）解码为对象。
    • 标准化失败时返回 {id, __toString} 或 {__class}。

    src/Core/Serializer/Normalizer/CircularReferenceHandler.php¶

    第二个更严格的循环处理程序：当对象 有一个标量 id，否则抛出 "Every entity should have getId method"。

    src/Core/Serializer/Callbacks/ObjectCallback.php¶

    序列化器回调（handle(object)）：返回对象的getId()，否则 null。作为特定属性的回调映射条目​​很有用。

    6. 内核事件监听器¶

    已在 config/services.yaml 中注册（以及一些在 Core 包中） services.yaml）。

    AccessLogListener¶

    响应kernel.response（优先级-5）。日志POST/PUT/DELETE 以表单形式向 monolog.logger.access 通道发出请求 {user} {METHOD} {uri} | {status} | REQ: ... | RES: ...。正文被截断 4096 个字符。身份验证路径（/api/auth、/api/wechat）的主体被隐藏。

    ControllerListener¶

    响应kernel.controller。使用操作记录 PUT/POST 请求 用户 ID 和 1 KB 截断的正文 ("User [#$operator] Requests $method $uri: ...")。

    ExceptionInterceptor¶

    响应kernel.exception。仅作用于 /api/... URL。记录 异常，返回具有适当状态的 JSON {code, message, class} 当退出开发时。 （如果环境等于 dev.disabled 它会重新抛出 Symfony 显示调试页面。）

    LocaleListener¶

    响应kernel.request（优先级20）。设置请求区域设置 _locale 查询参数或 Accept-Language 标头。支持的区域设置： en、zh、zh_Hant、ja。映射详细形式 (zh-CN → zh、zh-TW → zh_Hant、ja-JP→ja等）。

    MetricsListener¶

    响应kernel.request（优先级10）和kernel.response（优先级10） -1）。记录http_requests_total（按方法/路线/状态计数器）， http_request_duration_seconds（直方图）和http_requests_inflight （仪表）。跳过子请求和 /health、/metrics、/_profiler、/_wdt、 /api/doc 路径。

    OpenApiEnricherListener¶

    响应kernel.response（优先级-10）。后处理 /api/doc.json 和 /api/doc 响应以丰富 OpenAPI 规范：注入 规范标签，来自 META 地图的每个端点摘要/描述， 媒体上传端点的多部分上传请求主体，并剥离 通用 mixin 标签（List、Detail、Create、Update、Delete、Workflow）。 标签是从路由名称自动检测的（manage-*/app-*资源段， system-*、wechat-*、sys-auth）。

    RateLimitListener¶

    响应kernel.controller（优先级10）。应用由以下键控的速率限制 客户端 IP 到公共端点：

    限制器 路径
    auth_login ^/api/auth/login$
    auth_register ^/api/auth/register$
    otp_request ^/api/auth/otp/request$
    otp_verify ^/api/auth/otp/verify$
    wechat_login ^/api/wechat/miniapp/login$、^/api/wechat/oauth/callback$
    payment ~^/api/v1/app/orders/.+/payment$~、~^/api/v1/(app\|manage)/invoices/.+/pay~

    超出时，它会用标准中的 429 响应替换控制器 信封 {data, code, message} 加上 Retry-After 标头。限制器是 通过服务定位器注入（auth_login、auth_register、otp_request、 otp_verify、wechat_login、payment）。

    7. 实用程序类 (src/Core/Utils)¶

    班级 目的/关键方法
    UUID UUID 生成/验证：v3、v4、v4c（紧凑版 v4）、v5、is_valid。
    Math 静态数学助手（random、locationDistance）以及完整 PHP 数学函数集（abs、trig、log、带有 PHP_ROUND_HALF_* 模式的舍入等）的包装器，暴露给表达式。
    StringCase dashesToCamelCase($string, $capitalizeFirstCharacter = false)。

    8. 异常 (src/Core/Exception/)¶

    班级 目的
    MessageErrorHttpException HttpException 带有状态 403，可选 redirectUrl 标头。用于业务“错误”控制流。
    MessageSuccessHttpException HttpException 带有状态 200，可选 redirectUrl 标头。用于业务“成功”控制流消息有效负载。

    两者均由 ExceptionInterceptor 处理并在 JSON 中进行翻译 message 字段。

    9. 指标注册表 (src/Core/Metrics/MetricsRegistry.php)¶

    一个轻量级的、内存中的 Prometheus 风格的注册表（无外部客户端）。

    方法 目的
    incCounter($name, $labels, $by = 1) 增加一个计数器。
    setGauge($name, $labels, $value) / getGauge(...) 设置/读取仪表。
    observe($name, $labels, $value, $buckets = null) 记录直方图观察（默认存储桶 HISTOGRAM_BUCKETS 以秒为单位）。
    render(): string 渲染 Prometheus 文本展示格式 (v0.0.4)。

    METADATA中注册的指标名称：app_info、http_requests_total、 http_request_duration_seconds、http_requests_inflight、 app_outbox_backlog、app_messenger_failed、metrics_scrape_errors_total。 计数器/直方图是针对每个工人的； DB 支持的仪表是在抓取时实时计算的。
