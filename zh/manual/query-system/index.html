    动态查询系统 — 完整参考¶

    动态查询系统由BaseServiceReadListTrait::list()驱动 (src/Core/Service/Concern/BaseServiceReadListTrait.php) 和表达式 src/Core/Parser/ 加上 src/Core/Service/ExpressionService.php 中的引擎。 任何基于 ListApiViewMixin 构建的列表端点（或使用以下命令调用的任何服务） list(..., false) — 即 $disableRequest = false) 接受这些查询 GET 请求上的参数。

    该系统有两层：

    1. SQL/DQL 层 — @filter、@dql、@order、@select、@groupBy、 @hints 被编译到 Doctrine QueryBuilder 中。
    2. 内存层 — @sort （当 DQL 编译失败时，还有 @filter 非管理员）在 PHP 中根据已获取的结果集进行评估。

    1. 参数参考¶

    参数 类型 等级 描述 示例
    page 整数 SQL 页码（从 1 开始） 2
    limit 整数 SQL 每页项目数（通过控制器默认 100；分页器遵循 page/limit） 20
    @filter 表达 DQL + 后备 表达式 WHERE 子句 entity.status == "active"
    @dql 数据查询 SQL 用作 id IN (...) 的原始 DQL 子查询entity.price > 100
    @order 列表 SQL 排序依据字段 createdAt\|DESC
    @select 列表 SQL SELECT 覆盖（投影） entity.id, entity.name
    @groupBy 表达 SQL GROUP BY 子句 entity.category
    @hints JSON SQL Doctrine 查询上设置的查询提示 {"hint.name": "value"}
    @sort 表达 内存中 内存比较器（仅限管理员） x.getPrice() <=> y.getPrice()
    @showDQL 布尔 信息 转储生成的 DQL（仅限开发） true
    @expands JSON 查看 嵌套关系扩展 (__metadata) category,tags
    @display 字符串 查看 响应投影：complex、reduce、JSON 投影 reduce
    @transform JSON 查看 基于表达式的内容转换（创建/更新操作） {"category": "Service.get(...)"}
    @partial 布尔 查看 禁用周围事务（创建/批量更新） true
    @mode 字符串 查看 批量更新模式：update / mixed (upsert) mixed
    @basis 列表 查看 批量更新/更新插入的匹配字段 id,sku

    视图级参数（@expands、@display、@transform、@partial、 @mode、@basis) 由 RestController::success()/requestProcess() 应用 和创建/更新混合 - 它们不是 list() 本身的一部分，但是 在 CRUD 端点上对其进行补充。为了完整起见，本参考文献涵盖了它们。

    2. 核心查询参数¶

    page / limit¶

    对结果集进行分页。 RestController::pagination() 应用它们 服务器端（通过 Doctrine Paginator 通过 QueryBuilder 获得准确的 总计，或在数组/ArrayCollection 和 array_slice 上）。生成的 paginator 元数据如下所示：

    {
  "total": 100, "page": 2, "limit": 20, "pages": 5,
  "has_previous": true, "has_next": true
}

    @filter¶

    根据根别名 entity 计算的表达式。相同的语法是 可用作原始 QueryBuilder 片段（DQL 层）和内存中的片段 谓词（后备）。

    支持的运算符（客户端 @filter 和服务器 DqlExpression 共享）：

    操作员 意义 DQL 映射
    == / != 等于/不等于 = / !=
    > >= < <= 比较 相同
    && / || 逻辑与/或 AND / OR
    ! 逻辑非（属性检查） prop IS NULL 对孩子
    in / not in 收藏会员 IN (:param) / NOT IN (:param) — 绑定为数组参数；空 in [] 变为 1 = 0，空 not in [] 变为 1 = 1
    matches 正则表达式 / LIKE REGEXP(...) = TRUE 或 LIKE '%...%'
    + - * / 算术 相同

    字段引用是根别名加上点的吸气剂，例如 entity.status、entity.getCategory().getName()（链式属性访问 生成必要的连接）。裸属性（无运算符）编译为 prop IS NOT NULL。

    示例：

    # Equality
@filter=entity.status == "active"

# Comparison + logic
@filter=entity.price >= 100 && entity.status != "deleted"

# Chained attribute (joins category)
@filter=entity.getCategory().getName() == "Electronics"

# Regex match
@filter=entity.email matches "/@example\.com$/i"

# LIKE match (plain string pattern → %...%)
@filter=entity.name matches "pro"

# NOT — attr is null
@filter=!entity.deletedAt

    访问和回退：需要内存中评估的@filter（例如 当 DQL 编译失败或过滤器触及非持久数据时） 仅限管理员。对于非管理员，会引发 DQL 编译错误 AccessDeniedHttpException；管理员回退到 每个实体上的LegacyEvaluator::evaluateBool()。

    服务器拥有的 DqlExpression 与客户端 @filter：DqlExpression 重用 相同的表达式编译器，但变量绑定在 PHP 代码中（例如 new DqlExpression('entity.getUser() == user', ['user' => $this->getUser()]) 或new DqlExpression('entity.getStoreUuid() in this.getAllowedStoreUuids()') — 后者是显式绑定的简写，仅在内部可用 commonFilter() 通过 ApiView::resolvedCommonFilter()）。它从不使用 LegacyEvaluator，永远不会退回到内存过滤和编译 或元数据验证失败是一个 500 配置错误，拒绝 请求。与 commonFilter() 数组一样，它会自动使用 AND 编辑 id/uuid由mixIdToCommonFilter添加，因此无法进行详细/更新/删除 绕过了。带有空集合的 in/not in 被编译为常量 谓词 1 = 0 / 1 = 1 而不是无效的 IN ()。

    @dql¶

    原始 DQL 子查询，其匹配 id 用作 id IN (subquery)：

    @dql=SELECT e.id FROM App\Trade\Entity\Product e WHERE e.price > 100

    仅限于ROLE_ADMIN。

    @order¶

    排序依据字段。以逗号分隔的 field|DIRECTION 对：

    @order=createdAt|DESC,id|ASC

    如果您按链接路径排序（joiner 函数 寄存器 leftJoin）。非管理员注意： @order 本身没有门控，但是 DQL 编译必须是安全的。

    @select¶

    覆盖 SELECT 子句（投影）。链式路径扩展为连接：

    @select=entity.id, entity.name, entity.category.name

    由 assertSafeSelect() 保护：选择 App\Identity\* 实体或 user|profile|password|roles|email|phone|phoneVerified|refreshToken|sessionKey|rawData 中的任何一个 引发 AccessDeniedHttpException （“@select 无法访问身份数据。”）。 当@select（或@groupBy）存在时，list()返回查询结果 直接而不是 QueryBuilder。

    @groupBy¶

    附加 GROUP BY 子句：

    @groupBy=entity.category

    与 @select 一样，链式路径会自动连接并使用它直接返回结果。

    @hints¶

    应用于执行查询的 Doctrine 查询提示的 JSON 对象：

    @hints={"Doctrine\\ORM\\Query::HINT_FORCE_PARTIAL_LOAD": true}

    仅限于ROLE_ADMIN。

    @sort¶

    内存中比较器表达式使用 x 和 y 计算作为两个 正在比较的实体（使用 LegacyEvaluator::evaluateBool；真实的结果 首先对 x 进行排序）。因为它在 PHP 中运行，所以它仅限于 ROLE_ADMIN。

    @sort=x.getTotalAmount() > y.getTotalAmount()

    当存在 @sort 时，将应用 DQL 层过滤器结果，但排序 在内存中回退到usort。

    @showDQL¶

    当为真时，端点不会返回结果而是抛出 ValidatorException('DQL: ' . $qb->getDQL())，显示为 JSON 错误 显示生成的 DQL。对于调试很有用。仅在 dev 中可用 环境（否则任何环境都会引发AccessDeniedHttpException）。

    3.视图级参数¶

    在查询之后应用，在 RestController::success()/requestProcess() 中，并且 在创建/更新 mixin 中。

    @expands¶

    点关系的 JSON 数组（允许单引号，FixJSON 处理它们） 通过附加 __metadata 属性（对象本身）来扩展链 每个相关节点，因此平面序列化器可以包含它：

    # GET /api/v1/manage/contents?@expands=['category','tags']

    @display¶

    控制响应投影：

    • @display=reduce — 每个项目都变为{id, __toString}。
    • @display=<json array> — 例如['id','name','category.name'] 产生 具有请求字段的平面对象（通过 getter 遍历的虚线路径）。
    • @display=<json object> — 键是输出字段，值是 ExpressionLanguage 表达式用 entity、Math 计算，以及 ArrayCommon。
    • 省略（默认 complex） — 完整序列化实体。

    示例：

    # GET /api/v1/app/products?@display={"title":"entity.name","score":"Math.round(entity.price/100)"}

    @transform¶

    由 CreateApiViewMixin、UpdateApiViewMixin 和 Single* mixins 使用。一个 JSON 对象将字段映射到重写的 ExpressionLanguage 表达式 提交的内容。 :value 替换为提交的字段值，并且 Service（相关实体服务的网关）、entity、Math、 ArrayCommon可用。

    # POST /api/v1/manage/contents
# body:    {"title": "Hi", "category": "Test"}
# @transform={"category": "Service.get({'name': ':value'}).getId()"}

# GET /api/v1/manage/contents?@transform={"category":"Service.get({'name':':value'}).getId()"}

    对于实体上的一对一关系，匹配的 *Service 通过以下方式自动解析 约定（类名中的 Entity → Service）。返回相关的 实体的 ID。

    @partial¶

    布尔值。在创建和批量更新时，当 false （默认）整个批次是 包含在一笔交易中；当true每个项目单独处理并且 事务包装器被跳过（部分模式批量更新也会吞掉 每个项目的例外）。

    @mode和@basis（批量更新）¶

    UpdateApiViewMixin::batchUpdateAction (POST /batch-update):

    • @mode=update — 仅更新现有匹配项。
    • @mode=mixed (默认) — upsert: 当不存在匹配的实体时创建。
    • @basis — 逗号分隔的字段，用于匹配每个字段的现有实体 提交的行（例如 @basis=id,sku）。当为空时，不发生匹配（事务 用于更新插入决策）。
    # POST /api/v1/manage/products/batch-update?@basis=sku&@mode=mixed

    4. list() 工作流程如何工作¶

    （摘自BaseServiceReadListTrait::list()。）

    1. 构建 root — 带有 root 的服务实体类上的 QueryBuilder 别名entity；关联的 $object 数组变为 entity.key = :value_key 条件；传递的 QueryBuilder 按原样使用。
    2. @dql — 附加为 id IN (subDql)。
    3. @filter — 由ExpressionService::buildFilter()编译 → ExpressionDqlParser → ExpressionQueryBuilderAssembler;由此产生的 ids 通过 id IN (filterQb) 应用并合并参数。开 编译失败，非管理员获得AccessDeniedHttpException，管理员失败 回到内存过滤。
    4. @select / @groupBy — 应用； joiner 派生出 leftJoin 虚线路径。
    5. @order — 应用 (field|DIRECTION)，根据需要派生连接。
    6. @hints — 在执行的查询上设置。
    7. @showDQL — 使用生成的 DQL 抛出异常。
    8. 如果@select/@groupBy存在→返回查询结果。
    9. 否则返回 QueryBuilder （供控制器分页） — 或者， 当过滤器/订单回退到内存中时，获取结果并应用 @filter (evaluateBool) 和 @sort (usort) 超过它们。

    5. 安全总结¶

    参数 需要 ROLE_ADMIN 笔记
    @dql ✅ 原始 SQL 表面
    @sort ✅ 内存中评估
    @hints ✅ 原始查询提示
    @filter 仅适用于内存中回退 允许 DQL-fast-path；非管理员故障 → AccessDeniedHttpException
    @showDQL ✅（环境门控） 仅dev
    @select 有守卫，没有门禁 assertSafeSelect() 阻止身份数据
    DqlExpression（commonFilter 服务器范围） N/A — 代码拥有 失败关闭，从不PUBLIC_ACCESS；编译/验证失败 → 500，从不内存中回退

    DqlExpression 是服务器拥有的行级 @filter 对应项 授权：commonFilter()可能返回new DqlExpression(...)；它共享 运算符集（包括 in/not in），但在 PHP 中构造，通过绑定 withCriteria()/withContext() 并在任何查询执行之前进行验证。

    6. 操作员和人员注释¶

    • 链式属性访问使用根别名 entity.getX().getY() 形式 @filter; DQL 层将它们映射到联接 (filter_entity_x_y)。
    • 具有 /pattern/flags 值的 matches 编译为 REGEXP(...) = TRUE （支持的标志 gimsux）；普通字符串编译为 LIKE '%...%' ! 逃跑。
    • 过滤器表达式内可用的 ExternalExpressionValues 包括 math/Math、datetime/Datetime和ArrayCommon。

    有关解析内部结构和类级详细信息，请参阅 core-framework.md（§4 解析器和表达式引擎）。
