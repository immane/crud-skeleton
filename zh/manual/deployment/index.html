    Docker 部署¶

    本文档是运行CRUD Skeleton的操作参考 码头工人。它反映了自述文件“Docker 部署”部分（从 README.md:646) 并记录每个服务、变量和启动步骤 细节。

    架构¶

    flowchart LR
    Client[Client / Browser] -->|:8080| Nginx[nginx:alpine]
    Nginx -->|/api/*| Fpm["PHP-FPM 8.4<br/>(app, Symfony)"]
    Nginx -->|/api/doc| Swagger[Swagger UI<br/>NelmioApiDoc]
    Fpm --> MySQL[(MySQL 8)]
    Fpm --> Redis[(Redis 7<br/>OTP / cache)]
    Fpm --> Mailpit[Mailpit<br/>email dev]
    Fpm --> Worker[Messenger worker<br/>handlers / outbox]
    Fpm --> Scheduler[Scheduler<br/>outbox publish]

    所有服务都加入一个 internal Docker 网络；没有容器暴露 到公共互联网，除了 nginx （和 database / mailer 主机端口 在开发覆盖中）。

    服务¶

    服务 图像/构建 目的
    app 从 Dockerfile 构建 PHP-FPM 8.4，Symfony 应用程序
    worker 扩展 app 运行 messenger:consume async （异步消息处理程序）
    scheduler 扩展 app 无限循环发布发件箱+管家命令
    nginx nginx:alpine 反向代理→ app:9000，来自public/的静态文件
    database mysql:${MYSQL_VERSION:-8.4} MySQL 8.4，通过 mysql_data 卷持久化
    redis redis:7-alpine OTP存储+缓存，通过redis_data卷持久化
    mailer axllent/mailpit 捕获出站 SMTP 邮件，Web UI 位于 :8025（开发端口）

    每项服务注释¶

    • app — 运行 php-fpm，侦听端口 9000。启动由 容器入口点（参见JWT keys）。它depends_on database 服务的运行状况检查和 redis 容器。 ./var 是 绑定安装到 /var/www/html/var，以便缓存、日志和 JWT 密钥持续存在 跨容器重建。
    • worker — 与 app 相同的图像和环境，但覆盖命令 无限期地消耗 async 传输：
    php bin/console messenger:consume async --time-limit=3600 --memory-limit=256M --no-interaction

    该进程每小时重新启动一次（或者当内存超过 256M 时更早）重新启动一次 避免泄漏。 app在工人开始工作之前必须是健康的。

    • 调度程序 — 非 Docker 化的 cron 替换。运行一个 while : 循环 按时间间隔执行发件箱发布和内务管理命令 （OUTBOX_PUBLISH_INTERVAL，默认5秒）：
    php bin/console app:trade:outbox:publish --no-interaction
php bin/console app:store:outbox:publish --no-interaction
php bin/console app:inventory:outbox:publish --no-interaction
php bin/console app:inventory:reservations:release-expired --no-interaction
php bin/console app:settlement:allocations:requeue-due --no-interaction
php bin/console app:settlement:outbox:publish --no-interaction

    请参阅 Scheduler commands 了解每个功能的作用。

    • nginx — 唯一发布的服务。 APP_PORT 变量（默认 8080) 映射主机 → 容器端口 80。它将 public/ 只读挂载，并且 虚拟主机配置docker/nginx/default.conf。它的健康检查请求 http://localhost/health/ready 通过完整堆栈（nginx → PHP-FPM → Symfony → DB/Redis），因此容器只有在应用程序运行后才“健康” 确实可以服务流量。
    • 数据库 — 默认为 MySQL 8.4（MYSQL_VERSION，例如 8.4 或 8.0）。 数据位于命名的 mysql_data 卷中。健康检查用途 mysqladmin ping 与应用程序凭据。
    • redis — Redis 7，用于 OTP 存储和缓存。没有端口暴露在 基本撰写文件； dev 覆盖仅打开数据库和邮件程序端口。
    • 邮件程序 — Mailpit (axllent/mailpit)。网络内 1025 上的 SMTP， UI 发布于 MAILPIT_UI_PORT（默认 8025）。接受免身份验证 SMTP，因此 smtp://mailer:1025 开箱即用。

    编写文件¶

    文件 角色
    compose.yaml 基础定义：所有服务，安全开发默认为机密
    compose.override.yaml 在开发中自动加载：APP_ENV=dev，调试，完整源代码绑定安装，公开3306 + 1025
    compose.prod.yaml 生产：强制 prod，调试关闭，需要真正的秘密

    compose.override.yaml 由 docker compose 自动应用 （由于 compose.yaml/compose.override.yaml 邻居规则）。对于 生产中您必须显式传递这两个文件：

    docker compose -f compose.yaml -f compose.prod.yaml --env-file .env.prod.local up -d --build

    compose.prod.yaml 强制 APP_ENV=prod / APP_DEBUG=0 并使用 :?required 对于 APP_SECRET、REFRESH_TOKEN_SECRET、MYSQL_PASSWORD 和 MYSQL_ROOT_PASSWORD — 如果没有它们，堆栈将拒绝启动。

    环境变量¶

    核心 Symfony（始终需要）¶

    变量 默认（开发） 目的
    APP_ENV prod（基础）/dev（覆盖） Symfony 环境
    APP_DEBUG 0（覆盖1） 调试模式
    APP_SECRET dev-secret-change-me Symfony 应用揭秘
    DATABASE_URL mysql://app:!ChangeMe!@database:3306/app?... Doctrine DSN，从 MYSQL_* 变量构建
    DEFAULT_URI http://localhost 规范应用程序 URI

    JWT/身份验证¶

    变量 默认 目的
    JWT_PRIVATE_KEY_PATH /var/www/html/var/jwt/jwt_private.pem 容器中的RSA私钥路径
    JWT_PUBLIC_KEY_PATH /var/www/html/var/jwt/jwt_public.pem 容器中的RSA公钥路径
    JWT_PASSPHRASE （空） 私钥的密码
    ACCESS_TOKEN_TTL 7200 访问令牌生命周期（秒）
    REFRESH_TOKEN_TTL 31536000（1 年） 刷新令牌生命周期（秒）
    REFRESH_TOKEN_SECRET dev-refresh-secret-change-me 用于刷新令牌的 HMAC-SHA256 密钥

    OTP / SMS（可选 - 空则禁用）¶

    变量 默认
    OTP_REDIS_DSN redis://redis:6379/0
    ALIYUN_ACCESS_KEY_ID （空）
    ALIYUN_ACCESS_KEY_SECRET （空）
    ALIYUN_SMS_REGION cn-hangzhou
    ALIYUN_SMS_SIGN_NAME （空）
    ALIYUN_SMS_TEMPLATE_LOGIN_OTP （空）
    ALIYUN_SMS_TEMPLATE_VERIFY_PHONE （空）
    ALIYUN_SMS_DRY_RUN true

    OTP_REDIS_DSN 还门控 /health/ready 探针的 Redis 部分 — 空值报告 disabled 并被视为健康。

    微信（可选 — 空则禁用）¶

    小程序：WECHAT_MINIAPP_APP_ID、WECHAT_MINIAPP_SECRET。

    公众号：WECHAT_OFFICIAL_APP_ID、WECHAT_OFFICIAL_SECRET、 WECHAT_OFFICIAL_TOKEN、WECHAT_OFFICIAL_AES_KEY。

    微信支付V3：WECHAT_PAY_MCH_ID、WECHAT_PAY_SECRET_KEY、 WECHAT_PAY_PRIVATE_KEY、WECHAT_PAY_CERTIFICATE、WECHAT_PAY_NOTIFY_URL （加上 WECHAT_PAY_PLATFORM_CERT、WECHAT_PAY_PUB_KEY_ID、 WECHAT_PAY_PUB_KEY_PATH — 参见 .env.example）。

    基础设施¶

    变量 默认 目的
    MAILER_DSN smtp://mailer:1025 网络内的Mailpit
    MESSENGER_TRANSPORT_DSN doctrine://default?auto_setup=0 信使async运输（主义）
    INVENTORY_ENABLED 0 布尔值；切换库存功能路径
    OUTBOX_PUBLISH_INTERVAL 5 调度程序循环睡眠（秒）
    MYSQL_DATABASE / MYSQL_USER / MYSQL_PASSWORD / MYSQL_ROOT_PASSWORD app / app / !ChangeMe! / !RootChangeMe! MySQL 设置
    MYSQL_VERSION 8.4 MySQL 镜像标签
    APP_PORT 8080 nginx 的主机端口
    MAILPIT_UI_PORT 8025 Mailpit UI 的主机端口

    环境文件设置¶

    Symfony 和 Docker Compose 从不同的文件读取环境变量。的 下表显示了每种情况下加载的文件：

    场景 文件读取 笔记
    原生 PHP（本地） .env 然后 .env.local .env.local 覆盖 .env；永远不要犯
    Docker Compose（开发） .env（或--env-file） compose.yaml 具有安全的开发默认值，因此不需要任何文件
    Docker Compose（产品） .env.prod.local 通过 --env-file 复制自 .env.prod.example

    生成秘密¶

    # APP_SECRET / REFRESH_TOKEN_SECRET (32+ random bytes)
openssl rand -hex 32

# Strong DB passwords
openssl rand -base64 24

    切勿提交 .env.local 或 .env.prod.local。保守生产秘密 提交的 .env 文件。

    JWT 密钥¶

    容器入口点 docker/app/entrypoint.sh 管理密钥对：

    • 如果两个密钥都已存在，则它们将按原样重用。
    • 在非产品环境中，丢失的密钥会自动生成到 标准路径（2048 位 RSA）并保留在已安装的 ./var/jwt 下 目录（主机上的var/jwt）。私钥是用mode写的 600。
    • 在 prod (APP_ENV=prod) 中，缺少键会中止启动并出现错误 — 必须首先在主机上生成密钥。

    开始之前在主机上生成生产密钥：

    mkdir -p var/jwt
openssl genpkey -algorithm RSA -out var/jwt/jwt_private.pem -pkeyopt rsa_keygen_bits:2048
openssl rsa -pubout -in var/jwt/jwt_private.pem -out var/jwt/jwt_public.pem
chmod 600 var/jwt/jwt_private.pem

    如果私钥有密码，则设置JWT_PASSPHRASE .env.prod.local。

    构建图像¶

    Dockerfile 的目标是一个小的最终图像（约 90 MB）： php:8.4-fpm-alpine + 扩展（pdo、pdo_mysql、intl、zip、 opcache) + 作曲家。首先安装依赖项（缓存层） composer install --no-dev --no-scripts，然后复制应用程序源并 --no-dev --optimize 自动装载机已转储。 var/ 创建并拥有 www-data。

    # Dev — build and start everything
docker compose up -d --build

# Explicit env file (custom ports / credentials / integrations)
cp .env.example .env.docker.local
docker compose --env-file .env.docker.local up -d --build

# Production
docker compose -f compose.yaml -f compose.prod.yaml --env-file .env.prod.local up -d --build

    不要将生产机密放入提交的 .env 文件中。

    首次运行和迁移¶

    开发（覆盖自动应用）：

    docker compose up -d --build
docker compose exec app php bin/console doctrine:migrations:migrate --no-interaction
docker compose exec app php bin/console app:identity:user:create admin@example.com admin 'P@ssw0rd' --admin

    生产：

    docker compose -f compose.yaml -f compose.prod.yaml --env-file .env.prod.local up -d --build
docker compose -f compose.yaml -f compose.prod.yaml --env-file .env.prod.local \
  exec app php bin/console doctrine:migrations:migrate --no-interaction
docker compose -f compose.yaml -f compose.prod.yaml --env-file .env.prod.local \
  exec app php bin/console app:identity:user:create admin@example.com admin 'P@ssw0rd' --admin

    迁移链也经过 CI (.github/workflows/migrations.yml) 验证， 它针对新的 MySQL 8.4 从头开始应用每次迁移，并且 检查doctrine:migrations:status。

    有用的迁移命令：

    docker compose exec app php bin/console doctrine:migrations:status   # pending?
docker compose exec app php bin/console doctrine:migrations:migrate   # apply

    健康检查¶

    两个端点都位于 src/Core/Controller/HealthController.php 中并且是 公共（在 /api 防火墙之外），因此协调器和负载均衡器 可以在没有令牌的情况下轮询它们。

    /health/live¶

    活性探针。当 PHP 可以服务时总是回答 200 {"status":"ok"} 请求。用它来检测楔入过程。

    /health/ready¶

    就绪探针。回应：

    // 200 — ready
{"status": "ok", "checks": {"database": "ok", "redis": "ok"}}
// 200 — ready, redis optional
{"status": "ok", "checks": {"database": "ok", "redis": "disabled"}}
// 503 — degraded
{"status": "degraded", "checks": {"database": "error", "redis": "ok"}}
    • database — SELECT 1 通过默认的 Doctrine 连接。错误是 记录，从不回显（避免将驱动程序详细信息泄露给匿名呼叫者）。
    • redis — 无依赖性 TCP PING（RESP PING → +PONG）。已报道 当OTP_REDIS_DSN为空时disabled，否则ok/error。

    仅当数据库为 ok 并且 redis 为时，服务才准备就绪 ok 或 disabled。在测试环境中Redis探针被迫 disabled 用于确定性 CI 结果。

    nginx 容器健康检查通过完整堆栈使用 /health/ready， 因此，绿色的 nginx 容器意味着应用程序 + DB（+ 可选的 Redis）是可访问的。

    调度程序命令¶

    scheduler 服务取代了 cron 作业。它永远循环，运行 下面的命令，然后休眠 OUTBOX_PUBLISH_INTERVAL （默认 5 秒）：

    命令 模块 目的
    app:trade:outbox:publish 贸易 将待处理的 trade.order.created.v1 / trade.order.cancelled.v1 事件发布到 Messenger
    app:store:outbox:publish 商店 发布待处理的商店集成事件
    app:inventory:outbox:publish 库存 发布待处理的库存集成事件
    app:inventory:reservations:release-expired 库存 释放过期库存预订
    app:settlement:allocations:requeue-due 结算 将需要重试的分配过帐重新排队
    app:settlement:outbox:publish 结算 发布待处理的结算整合事件

    每个发件箱发布者都遵循相同的模式 (src/{Module}/Command/PublishOutboxCommand.php)： 可标记行通过租约 (claim()) 声明，并根据已知进行验证 主题，使用版本化信封分派到 messageBus 上，然后 markPublished()；失败会被延迟并显示错误消息并重试 稍后。该循环可以容忍崩溃的迭代（每次运行都干净地退出），使得 作为计划作业运行是安全的。

    有用的命令¶

    开发（生产变体添加 -f compose.yaml -f compose.prod.yaml --env-file .env.prod.local）：

    docker compose logs -f app                       # tail app logs
docker compose exec app php bin/console about    # run a Symfony command

    自定义 nginx 配置¶

    将 docker/nginx/default.conf 替换为您自己的配置。常见变化：

    • 添加 TLS/SSL 证书并监听 443
    • 将 server_name 更改为您的域名
    • 添加速率限制或IP白名单

    然后只重建 nginx：

    docker compose up -d --build nginx

    默认配置通过 index.php （前端控制器）路由 location /， 通过 FastCGI 将 ^/index\.php(/|$) 转发到 app:9000，internal 是 PHP 位置（从未直接提供），为任何其他 .php 文件返回 404，以及 client_max_body_size 上限为 20m。
