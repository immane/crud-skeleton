# API Design Contract

> Unified response format, URL conventions, HTTP method semantics, authentication, pagination, and query parameters.
> **Every API endpoint MUST conform to this contract.**

---

## 1. Unified Response Envelope

Every API response wraps data in a standardized envelope:

```json
{
  "data": {},
  "code": 200,
  "message": "SUCCESS",
  "paginator": {}
}
```

### 1.1 Fields

| Field | Type | When Present | Description |
|-------|------|-------------|-------------|
| `data` | any | Always | Response payload (object, array, null, or scalar) |
| `code` | int | Always | HTTP status code (mirrors response status) |
| `message` | string | Always | Human-readable status (success) or error description (warning) |
| `paginator` | object | When paginated | Pagination metadata (current page, total pages, total items, per page) |

### 1.2 Success Response

Generated by `RestController::success($data, $message, $status)`:

```json
{
  "data": { "id": 1, "title": "..." },
  "code": 200,
  "message": "SUCCESS"
}
```

| Scenario | Status | Message |
|----------|--------|---------|
| GET list/detail | 200 | "SUCCESS" |
| POST create | 201 | "SUCCESS" |
| PUT update | 200 | "SUCCESS" |
| DELETE remove | 204 | "SUCCESS" |

### 1.3 Error Response

Generated by `RestController::warning($error_msg, $error_code, $raw_data, $status)`:

```json
{
  "code": 400,
  "message": "Validation failed: email is required",
  "data": ""
}
```

| Scenario | Status |
|----------|--------|
| Validation error | 400 |
| Not found | 404 |
| Authentication failure | 401 |
| Authorization failure | 403 |
| Server error | 500 |

### 1.4 Paginator Object

```json
{
  "paginator": {
    "page": 1,
    "limit": 20,
    "pages": 5,
    "total": 100
  }
}
```

## 2. URL Conventions

### 2.1 Base Prefix

| Scope | Prefix |
|-------|--------|
| Authentication | `/api/auth` |
| Business API (public) | `/api/v1/app` |
| Business API (admin) | `/api/v1/manage` |
| Documentation | `/api/doc` |

### 2.2 Resource Naming

| Convention | Example | Rationale |
|------------|---------|-----------|
| Lowercase, hyphenated | `/api/v1/manage/order-items` | Readable URLs |
| Plural nouns | `/categories` not `/category` | Consistent REST |
| No trailing slash | `/categories/{id}` | Clean URLs |
| No verbs in base URLs | Create via `POST /categories` | HTTP method semantic |
| Resource identifier in path | `/{id}` where `id` is digits or a canonical UUID | Core resolves digits as the local ID and UUIDs as the mapped `uuid` field |
| Sub-resources | `/orders/{id}/items` | Relationship scoping |

`{id}` is the stable Core route parameter name, not a promise that every resource uses
only a numeric identifier. Clients provide exactly one value: a digit-only local ID or,
when the resource exposes one, a canonical UUID. Do not add parallel `id` and `uuid`
path/query parameters for the same target. New cross-module integrations and durable
external references should use UUIDs when available.

### 2.3 Special Routes (Non-CRUD)

| Operation | URL Pattern | Example |
|-----------|------------|---------|
| Batch upsert | `POST /{resource}/batch-update` | `POST /categories/batch-update` |
| Workflow todo | `GET /{resource}/todo` | `GET /orders/todo` |
| Workflow transitions | `GET /{resource}/{id}/transitions` | `GET /orders/5/transitions` or `GET /orders/{uuid}/transitions` |
| Workflow execute | `POST /{resource}/{id}/do/{transition}` | `POST /orders/5/do/confirm` or `POST /orders/{uuid}/do/confirm` |
| Workflow reset | `PUT /{resource}/{id}/status-reset` | `PUT /orders/5/status-reset` or `PUT /orders/{uuid}/status-reset` |

`WorkflowApiViewMixin` resolves workflow targets through the Core identifier lookup
(`mixIdToCommonFilter()`): digit-only values as local `id`, canonical UUID values
as `uuid`, merged with `commonFilter()` and authorization. It returns `404` when the
identifier is not found and `403` on authorization failure.

## 3. HTTP Method Semantics

| Method | CRUD | Idempotent | Body | Path ID |
|--------|------|-----------|------|---------|
| GET | Read (Collection) | Yes | No | No |
| GET | Read (Detail) | Yes | No | Yes |
| POST | Create | No | Yes | No |
| PUT | Update (Full replace) | Yes | Yes | Yes |
| DELETE | Delete | Yes | No | Yes |

### 3.1 POST Specializations

| Variant | Path | Body | Purpose |
|---------|------|------|---------|
| Create single | `POST /` | `{}` | Single entity creation |
| Create batch | `POST /` | `[{}, {}, ...]` | Multiple entities in one transaction |
| Batch upsert | `POST /batch-update` | `[{}, {}, ...]` | Idempotent bulk sync with `@basis` + `@mode=mixed` |
| Singleton upsert | `PUT /` | `{}` | Single-row resource (get-or-create) |

## 4. Authentication

### 4.1 Token Format

```
Authorization: Bearer {access_token}
```

- Access token: RS256 JWT, 7200s TTL (default)
- Refresh token: opaque HMAC-SHA256 hash, stored server-side, 1 year TTL

### 4.2 Public Endpoints (No Auth Required)

| Endpoint | Method |
|----------|--------|
| `/api/auth/login` | POST |
| `/api/auth/otp/request` | POST |
| `/api/auth/otp/verify` | POST |
| `/api/auth/token/refresh` | POST |
| `/api/auth/logout` | POST |
| `/api/doc`, `/api/doc.json` | GET |

### 4.3 Role Hierarchy

```
ROLE_USER
  |-- ROLE_ADMIN
```

- Public `/api/v1/app/*`: No role required (can be read-only)
- Admin `/api/v1/manage/*`: `ROLE_ADMIN` required

## 5. Query Parameters (Dynamic Query System)

### 5.1 List Endpoint Parameters (`GET /`)

| Parameter | Type | Description |
|-----------|------|-------------|
| `page` | int | Page number (1-based) |
| `limit` | int | Items per page |
| `@filter` | string | Expression-based WHERE condition |
| `@dql` | string | Raw DQL WHERE sub-clause |
| `@order` | string | Comma-separated `field|ASC` or `field|DESC` |
| `@select` | string | DQL SELECT clause override |
| `@groupBy` | string | DQL GROUP BY |
| `@hints` | string | Doctrine query hints |
| `@sort` | string | In-memory sort expression (fallback) |
| `@expands` | string | Comma-separated nested entity expansion |
| `@display` | string | Field projection mode (`complex`, `reduce`, or expression) |
| `@showDQL` | bool | Debug mode: returns compiled DQL in response |

### 5.2 Create/Update Parameters

| Parameter | Method | Type | Description |
|-----------|--------|------|-------------|
| `@partial` | POST, PUT | bool | Non-transactional mode (skip failed items) |
| `@transform` | POST, PUT | string | Expression-based field value transformation |
| `@mode` | POST (batch-update) | string | `mixed` (upsert), `strict` (update-only) |
| `@basis` | POST (batch-update) | string | Comma-separated match fields for upsert |

### 5.3 Expression Syntax (`@filter` / `@sort` / `@transform`)

| Operator | Meaning | Example |
|----------|---------|---------|
| `==` | Equal | `entity.status == "active"` |
| `!=` | Not equal | `entity.price != 0` |
| `>` | Greater than | `entity.age > 18` |
| `<` | Less than | `entity.price < 100` |
| `>=` | Greater or equal | `entity.count >= 5` |
| `<=` | Less or equal | `entity.rating <= 4.5` |
| `&&` | Logical AND | `a == 1 && b == 2` |
| `\|\|` | Logical OR | `a == 1 \|\| b == 2` |
| `!` | Logical NOT | `!entity.deleted` |
| `matches` | Literal substring or `/regex/flags` match | `entity.title matches "paper"`, `entity.title matches "/^paper.*/i"` |
| Chained attributes | Property traversal | `entity.getCategory().getName()` |

Plain `matches` values are escaped before being compiled to a contains-style `LIKE`.
Regex literals support `i`, `m`, `s`, and `x`; `g` and `u` are accepted but have no
database-side effect. Unknown regex flags are rejected.

### 5.4 Expression Functions (Available in Expressions)

| Namespace | Functions |
|-----------|-----------|
| `Math` | `abs`, `ceil`, `floor`, `round`, `max`, `min`, `add`, `sub`, `mul`, `div`, `mod`, `pow`, `sqrt` |
| `ArrayCommon` | `in_array`, `count`, `merge`, `push`, `key_exist`, `filter`, `map`, `reduce` |
| `Datetime` | `get($time, $timezone)` -- returns DateTime |

## 6. Content-Type & Request Body

| Direction | Content-Type |
|-----------|-------------|
| Request | `application/json` |
| Response | `application/json` |

- Request body MUST be valid JSON
- Invalid JSON returns `400 { message: "Invalid JSON" }`

## 7. OpenAPI Documentation

- Every endpoint MUST carry `#[OA\*]` attributes for NelmioApiDocBundle
- Swagger UI: `/api/doc`
- OpenAPI JSON: `/api/doc.json`
- Attributes MUST include: method tag, parameters (with types), response schemas, request body schemas

### 7.1 Required Attributes per Endpoint

| Action | Attributes |
|--------|-----------|
| List | `#[OA\Get]` with all query parameters documented |
| Detail | `#[OA\Get]` with `@expands` parameter |
| Create | `#[OA\Post]` with `@partial`, `@transform` parameters, request body schema |
| Update | `#[OA\Put]` with `@transform` parameter, request body schema |
| Delete | `#[OA\Delete]` with response descriptions |
| Batch update | `#[OA\Post]` with `@mode`, `@basis`, `@partial`, `@transform`, request body schema |
| Workflow | `#[OA\Get]` / `#[OA\Post]` / `#[OA\Put]` matching the action |

## 8. Response Encoding Rules

### 8.1 Entity Serialization

- Circular references resolved to `{ "id": N, "__toString": "...", "__metadata": {} }`
- `DateTime` fields serialized to ISO 8601 strings
- JSON fields auto-parsed from string to object/array
- Doctrine proxy/internal fields stripped

### 8.2 Field Selection (`@display`)

| Mode | Behavior |
|------|----------|
| `complex` | Deep expansion with metadata |
| `reduce` | Shallow, only ID+toString for relations |
| Expression | Custom field mapping via expression syntax |
| (none) | Flat normalization (default) |

### 8.3 Nested Expansion (`@expands`)

Example: `@expands=category,tags`

Collapsed entity relations are expanded to nested objects with `__metadata`.
